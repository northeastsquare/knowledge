DynamicVLA：面向动态物体操作的 VLA

面向移动/动态目标抓取的 VLA，解决动作时延导致的错位问题——用一个 0.4B 紧凑模型 + 连续推理 + 潜在感知的动作流，把动态抓取的成功率从基线约 13% 拉到 47%，并配套造了一个全自动的动态操作基准 DOM。

论文DynamicVLA: A Vision-Language-Action Model for Dynamic Object Manipulation
机构南洋理工大学 S-Lab
arXiv2601.22153v1
主题VLA · 动态物体

它解决的问题

VLA 模型在静态操作上泛化已经很强，但一到动态物体（移动、翻滚、被抛出的目标）就掉链子：这类任务需要快速感知、时间预测和连续闭环控制，而传统 VLA 的推理时延会直接导致失败。

作者把问题归结为一个被静态操作掩盖、在动态操作里致命的因素——观察与动作执行之间的时序错位（temporal misalignment），具体表现为两个缺口： ⟨/⟩ 代码

  • 感知-执行缺口（Perception–Execution gap）：模型在时刻 t 基于观测 Ot 推理，但推理要花 m 步时延，动作在 t+m 才可用，此时物体已经从 st 运动到了 st+m——预测的动作已对不上当前环境。
  • 块间等待（inter-chunk waiting）：现有 VLA 要等上一个动作序列完整执行完才触发下一次推理，推理与执行被串行化，控制流被卡住。

论文在讨论部分点破的核心判断：动态操作的主导失败模式不是"看不看得懂"（感知歧义），而是观察与动作执行之间的时序错位——这是静态操作里几乎被忽略的因素。

此外还有两个现实约束让这件事更难：

  • 现有数据缺位：主流机器人数据集几乎全是静态场景，没有大规模动态操作数据；而动态操作下遥操作（teleoperation）基本失效——人类反应速度追不上快速移动的物体。
  • 已有动态工作要么太窄要么太松：DBC-TFP、GEM 只在传送带式可预测运动里做；RDT-2、RTVLA、VLASH 虽能对快速目标实时交互，但容忍大接触余量（如球拍接球），不需要动态操作所要求的精确 6DoF 控制。

方法主线

DynamicVLA 的思路不是堆大模型，而是"把时延当成首要敌人来打"，主线四步：

  1. 造一个足够快的 0.4B VLA：用卷积视觉编码器 FastViT（高效空间压缩、结构保真、避免多帧输入下 token 二次增长）+ 截断到前 16 层的 SmolLM2-360M 语言骨干 + Flow Matching 动作专家，把推理压到 ~88Hz（1.8GB 显存）。
  2. Continuous Inference（CI）：推理与执行重叠的流水线——上一次推理一完成就立刻触发下一次，不等动作序列执行完，消除块间等待。
  3. Latent-aware Action Streaming（LAAS）：一个显式的执行策略，丢弃过时动作、优先最新预测，恢复"感知-执行"的时间对齐。
  4. 补上数据地基 DOM benchmark：用自动化管线（仿真 200K 集 + 真实世界 2K 集，无需遥操作）训练并评测，覆盖多本体（Franka、PiPER）。

三件创新对应当前动态 VLA 的三个瓶颈：紧凑骨干→推理速度；CI→消除块间等待；LAAS→消除感知-执行错位。数据管线→解决动态数据缺失。

输入、输出与数据流

模型在时刻 t 接收三路输入，输出一个动作块；执行阶段靠 CI + LAAS 保证时序一致：

环节内容
输入 · 观测时间窗口 Ot = {ot-2, ot}（默认稀疏两帧，多视角 RGB 按通道拼接，用于隐式感知速度）
输入 · 语言指令 Lt，按长度 token 化
输入 · 本体32 维本体状态 Pt（末端笛卡尔位姿，未用项零填充），线性投影成单个 960 维 token
编码FastViT 输出 36 个 960 维视觉 token；三路 token 拼接后交给 SmolLM2-360M 前 16 层，KV 表示缓存复用
动作专家Flow Matching Transformer（隐维 720 = 0.75× 语言嵌入），去噪时查询缓存的 KV，不重编码感知输入
输出动作块 At，horizon n=20 步，每步 32 维（末端位姿 + 夹爪状态）
执行CI 在 t, t+m, t+2m… 连续触发；LAAS 丢弃早于 t+m 的过时动作、重叠处新块覆盖旧块

训练或运行方式

训练分三阶段，全程约两周；数据则靠"状态机 + 仿真器"自动化采集。

三阶段训练（32×A100，batch 40/卡，AdamW，lr 1e-4，cosine + 1000 warmup）

  • 预训练（2 天）：只用视觉-语言对齐，在 COYO-700M 采样 150M 英文图文对上训练 FastViT + SmolLM2-360M。
  • 中训练（10 天）：在合成 DOM 数据集上训练完整 VLA，动作专家按 Flow Matching 目标（Eq.1）去噪。
  • 后训练（2 天）：用机器人本体相关的真实世界演示微调，适配新本体和传感配置。

数据管线（免遥操作）

  • 仿真：Isaac Sim 提供真值 6D 位姿/速度，驱动一个四阶段状态机控制器（接近物体→抓取提升→接近目标放置→复位），物体速度采样 0~0.75 m/s、摩擦 0.5~1.5，2.8K 场景 × 206 物体，产出 200K 集。
  • 真实世界：因为人类遥操作追不上快速物体、且无真值状态，作者搭了一个"真实世界仿真器"——双 RGB 视角（Azure Kinect DK）+ 腕部 RealSense，用 EfficientTAM 出掩码、几何三角化出 3D 质心、短时间窗口拟合出线/角速度，用同一状态机自主执行，约 10 秒/集，产出 2K 集，Franka 与 PiPER 通用。

推理

模型 1.8GB 显存、~88Hz（NVIDIA RTX A6000）；动作块 n=20，CI 假设 n > m（新块在旧块执行完之前就绪）。

关键结果

仿真基准（每个方法 1800 次试跑 = 10 场景 × 9 维度 × 20 次）上 DynamicVLA 全面碾压基线；真实机器人上同样领先。

一句话总结结果：动态操作的胜负手不是模型大小，而是时延管理。0.4B 的 DynamicVLA 用"快推理 + 重叠执行 + 丢弃过时动作"三招，把动态抓取成功率从最强基线的 13.61% 提到 47.06%，同时完成时间还更短（8.53s vs 基线约 10.5s+）。

我真正学到的内容

  • 动态操作的第一性问题是时延，不是感知。静态操作里"慢一点没关系"，一旦物体在动，推理的每一毫秒都在制造"感知-执行错位"。这改变了调优方向：优先压推理频率、对齐时间轴，而不是一味加模型容量。
  • 错位可以用极简单的执行策略消除。LAAS 就是"丢弃过时动作 + 新块覆盖旧块"，不需要重训、不需要改模型，却能补上感知-执行 gap——而且它是即插即用的（论文直接装到 SmolVLA、π0.5 上验证过）。
  • 在实时约束下，小模型能赢大模型。1.7B 骨干反而只有 24.33%，因为推理时延直接损害闭环响应。这对"越大越好"是重要反例：预算要给到"够快"而非"够大"。
  • 数据能自动化，遥操作不是唯一答案。面对"人类反应追不上物体"的困境，作者用状态机 + 真实世界"仿真器"（无真值感知，靠 RGB-D + 分割 + 三角化 + 速度拟合）自主采集，10 秒一集。这是可迁移的采集范式。
  • 卷积视觉编码器在动态多帧下更合适。FastViT 靠空间压缩避免 token 二次增长、保持结构保真，比 transformer 视觉快且效果更好。

可复用设计

  • CI + LAAS 执行机制（最值得抄）：与模型解耦，不改骨干、不重训即可装到现有 VLA 上；论文验证了对时延适中的模型（SmolVLA）有稳定增益，对时延过高的模型（π0.5）收益有限——可作为通用"时延对齐插件"。
  • 四阶段状态机控制器：接近物体（预测 ~0.23s 近未来运动、悬停上方 10cm）→抓取提升→接近目标放置→复位。可直接作为动态抓取的策略骨架或数据生成器。
  • 真实世界"仿真器"管线：双视角 RGB-D + EfficientTAM 掩码 + 几何三角化 3D 质心 + 短窗口速度拟合，用商品级传感器近似真值状态，免除遥操作和真值标注。
  • 动作专家缓存 KV 查询：去噪时查询语言骨干缓存的 KV 表示而非重编码感知输入，省算力、提吞吐。
  • 稀疏时间上下文设计：{ot-2, ot} 两帧间隔足够估计速度，再多帧收益递减——动态任务里"给足时间间隔"比"给多帧"更重要。

疑问与风险

  • 扰动鲁棒性仍是短板：DR 只有 26.5%，作者也承认环境扰动下 DynamicVLA 依然吃力，且真实世界未测扰动（难以可靠复现）。
  • 只覆盖短/中时程反应式交互：长时程多阶段任务（规划、记忆、任务分解）未涉及；物体持续运动的多阶段操作是空白。
  • 刚体假设：数据管线假设刚体状态估计，流体/非刚体/软体动力学不在范围内。
  • 成本与依赖：训练约两周、32×A100；真实世界采集依赖 6D 状态估计精度，"仿真器"接口的鲁棒性存疑。
  • 小模型的天花板：0.4B 在复杂语言理解上的能力边界未充分讨论；图 6 中 DynamicVLA 泛化绝对成功率仍不算高（约 48%），说明"快但不够聪明"的取舍仍在。
  • 待核实细节：论文正文引用的 SmolLM2 编号（[3]/[29]）不一致、部分图数值在文字中未逐一对应，引用时需回到原文核对。

后续动作

  • 读代码/项目页：https://haozhexie.com/project/dynamic-vla，重点看 CI 与 LAAS 在推理循环里的具体调度实现。
  • 复现最小实验：把 CI + LAAS 装到自己项目里的 VLA 上，在时延敏感场景测成功率变化（不改骨干、不重训即可验证）。
  • 补概念：Flow Matching / rectified flow 去噪目标；FastViT 的结构重参数化；EfficientTAM 分割跟踪；SmolVLA 的骨干截断技巧。
  • 理解量化约束：感知-执行 gap 的时延步数 m 如何测量；动作块尺寸需满足 n > m 的设计前提。
  • 做实验：在本项目的移动/动态抓取场景上验证"丢弃过时动作 + 最新预测覆盖"是否同样带来时序对齐收益；评估是否要复刻其真实世界"仿真器"采集管线。
