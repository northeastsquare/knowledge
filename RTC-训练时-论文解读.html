训练时 RTC：让模型在训练里就学会“接着已经在执行的动作往下写”

异步执行时，新动作块算出来的那一刻，旧动作块已经执行了 d 步，所以新块必须和这 d 步严丝合缝地接上。推理时 RTC 在每一步去噪时都用梯度把新块往这 d 步上“拽”，有效但更慢；训练时 RTC 换了个思路：训练时随机模拟延迟，把前 d 步换成真实动作并标记为“已经干净”，让模型直接学会条件生成。这样推理时不增加任何计算，网络结构也不用改。

一句话：把“补全前缀”这件事从推理时的数值优化搬到训练时的监督学习。实现只需要三处改动：每个动作 token 用各自的 flow 时间步、前缀填真实动作并设 τ=1、损失只算后缀。

问题：为什么异步执行会“抖”，同步执行会“停”

  1. 动作分块与延迟：动作块一次预测 H 步，执行其中 s 步后再重新推理。大模型推理一次要几十到上百毫秒（感知—执行时延）。在 50Hz（每步 20ms）的机器人上，100ms 相当于 d≈5 步。
  2. 同步执行会停：执行完 s 步就停下来等新块，动作一顿一顿的，整体也慢。RTC 论文中，π0.5 用同步执行就能看到明显停顿。
  3. 朴素异步会跳：推理从第 t 步开始，到第 t+d 步才出结果，这 d 步只能继续执行上一块。新块是根据新观测重新采样的，而 flow/扩散策略是多模态的（比如从左边绕还是从右边绕都合理），新块可能换了一种策略，切换时速度和方向会突变。平均两个块（temporal ensembling）也不行，把两种策略平均可能得到一个两边都不是的动作。
  4. 约束：前缀要有效，必须满足 d ≤ H − s，也就是新块的前 d 步在上一块里还没用完。RTC 进一步要求 d ≤ s ≤ H − d。

所以真正要解的是一个条件生成问题：已知新块的前 d 步一定等于上一块对应的动作，生成其余部分，使它既和前缀连贯，又能利用新观测。

推理时 RTC：把衔接当成“补全图像”，每一步去噪都做一次引导

前作 Real-Time Chunking（arXiv 2506.07339） 把块间衔接看成图像补全（inpainting）：前 d 步像图像中已知的像素，其余部分要补全。它用的是不需要训练的伪逆引导（ΠGDM）。设 flow 约定为 Aτ = τ·A + (1−τ)·ε，τ=1 时是干净动作。每个去噪步做四件事：

① 估计终点用当前速度一步跳到 τ=1：Â¹ = Aτ + (1−τ)·v
② 比较目标误差 (Y − Â¹)·W，Y 是上一块的剩余动作，W 是逐位置权重
③ 反向传播把误差经网络的雅可比 ∂Â¹/∂Aτ 传回去，得到修正量（向量-雅可比积，VJP）
④ 加到速度上v + min(β, (1−τ)/(τ·r²τ))·修正量；β 是作者为少步数采样的稳定性加的上限

软掩码（soft masking）：只约束前 d 步时，引导信号太弱，新块仍可能换策略。所以 W 对前 d 步取 1，对重叠区按指数从 1 衰减到 0，对最后 s 个全新位置取 0。演示里“推理时 RTC”模式显示的就是这条权重曲线，公式和代码中的 get_prefix_weights(..., "exp") 一致。

代价：每个去噪步都要多一次反向传播。RTC 论文里，π0.5 的模型延迟从 76ms 增加到 97ms。另外，引导依赖网络在当前点的线性化，前缀越长，补全越吃力。

训练时 RTC：三处改动

目标是直接学习条件分布 p(At+d:H | ot, At:t+d)，前缀和后缀都取自同一条真实动作块。

① 每个 token 有自己的 τ标准 flow 中整个块共用一个 τ。现在 τ 变成形状 (batch, H)。对于 adaLN-zero 结构（π0.6 的动作专家、DiT），只需让 scale/shift/gate 逐 token 不同，参数量不变。
② 前缀填真值，τ=1前 d 个位置直接放真实的干净动作，τ 设为 1；后缀照常加噪。τ=1 本来就表示“这是干净数据”，所以 τ 序列本身就告诉了模型延迟 d 是多少。
③ 损失只算后缀前缀位置的预测不计入损失，只学“已知前缀时怎么去噪后缀”。
④ 延迟随机采样真实延迟会波动，所以每个样本随机抽一个 d。真机实验用 0–10 均匀分布（50Hz 下最大 200ms）；仿真用 {0..4}，延迟越大权重越小（指数递减）。

推理：每个去噪步都先把前 d 位覆盖成上一块的动作，并把这些位置的 τ 设为 1，然后正常前向一次。没有反向传播，也没有引导系数。接口和推理时 RTC 完全相同（输入前缀和 d，输出整个块），机器人运行时代码不用改。

# 论文 Algorithm 1（节选，与标准 flow matching 的差别在注释处）
delay = randint(0, max_delay)                       # 新增：模拟延迟
prefix = arange(H)[None] < delay[:, None]            # 新增
time   = where(prefix, 1.0, time[:, None])           # 新增：前缀 τ=1
x_t    = time * action + (1 - time) * noise
loss   = (model(obs, x_t, time) - (action - noise))**2
loss   = sum(loss * ~prefix) / sum(~prefix)          # 新增：只算后缀

# 采样：每一步都把前缀覆盖为已执行的动作
for _ in range(num_steps):
    x_t = where(prefix, action_prefix, x_t)
    v_t = model(obs, x_t, where(prefix, 1.0, time))
    x_t, time = x_t + dt * v_t, time + dt

为什么这样就成立：三层原理

  1. τ 本来就是“这个位置有多可信”的信号。flow 模型的输入是“τ 比例的真值 + (1−τ) 比例的噪声”。τ=1 表示完全没有噪声。把前缀的 τ 设为 1，相当于用模型原有的语言告诉它“这几步已经确定”，不需要新增输入通道或条件 token。adaLN 让每个 token 根据自己的 τ 调制特征，token 之间通过注意力或 token-mixing 交换信息，后缀就能“看到”干净的前缀。
  2. 学出来的条件分布比现算的引导更准。推理时 RTC 是在一个没学过条件生成的模型上，用一阶线性化去近似条件采样，前缀越长误差越大。训练时 RTC 用真实数据直接监督“已知前缀时后缀该是什么”，属于精确的条件建模。所以在 d≥2 时它更好，而且 d 越大差距越大。
  3. 算力从推理端挪到训练端。推理端的成本是每次控制都要付的，训练端的成本只付一次。对实时控制来说，这笔交换很划算：少量微调换来推理延迟回到基线，而延迟变小又让 d 变小、反应更快，形成正反馈（真机上 108ms 对应 d≈5，推理时 RTC 是 135ms、d≈7）。

关键结果

设置结果
仿真：动态 Kinetix，H=8，4 层 MLP-Mixer，每个数据点 2048 次 rollout，s=max(d,1)d≥2 时训练时 RTC 优于推理时 RTC，延迟越大差距越大；d=0、1 时略差，因为前几个位置得到的监督变少了。为了让训练算力相同，训练时 RTC 从第 24 个 epoch 接着微调 8 个 epoch，对照组训练满 32 个 epoch
真机：π0.6 基座，组装纸箱和做浓缩咖啡（来自 π*0.6 的任务），各微调 8000 步，batch 512成功率和完成时长与推理时 RTC 持平；两种 RTC 都比同步执行快（同步执行在块之间有明显停顿）
延迟：远程 H100，5 个去噪步端到端延迟：训练时 RTC 108ms（d≈5），推理时 RTC 135ms（d≈7）

深层理解：这篇真正改变了什么

  • 执行层的问题，可以在训练层解决。RTC 把实时性当作采样算法问题，训练时 RTC 把它变成数据增强：训练分布里本来就包含“带延迟的条件生成”这种情形。
  • flow 时间步是通用的条件接口。τ 不只是噪声日程，还可以逐 token 表达“这一位有多确定”。同样的思路可以推广到其他已知部分动作的场景，例如固定的末端位姿或安全约束。论文没有做这些实验，这里是推论。
  • 它让大模型也能实时控制。推理开销为零，所以模型变大或推理放到远端服务器时，只需要把延迟分布调大。π0.7 就用了训练时 RTC：模拟 0–12 步延迟（50Hz 下 240ms），最小变体的推理延迟降到 38ms。

代价与边界

  • 只有硬前缀：只能以前 d 步为条件，不能像软掩码那样“温和地”参考后面的重叠部分。
  • 延迟分布要事先选好：训练时没见过的延迟（比如超过 max_delay）就无法处理。真实延迟分布变化后，需要重新微调。
  • 需要训练：推理时 RTC 可以直接套在现成的 checkpoint 上，训练时 RTC 必须微调。好在不需要从头预训练。
  • 小延迟下略差：前缀位置不计入损失，前几步动作得到的监督略少。
  • 依赖 flow/扩散动作头：逐 token 的 τ 是 flow/扩散模型特有的。FAST 这类自回归 token 策略天然就以前缀为条件，不需要这个技巧，但它们的推理延迟更大。

前后脉络与被谁接手

  • 前作：RTC（推理时补全）；它之前有 ACT 的 temporal ensembling，以及 SmolVLA 的异步推理（不处理块间不连续）。
  • 同期：A2C2 加一个轻量的修正头；VLASH 只以未来的一个动作为条件，训练时 RTC 则以完整前缀为条件。
  • 接手：π0.7 默认采用训练时 RTC；Realtime-VLA FLASH 用投机推理进一步降低扩散 VLA 的延迟，并指出与 RTC 结合时需要处理可变延迟；DynamicVLA 处理运动物体带来的感知—执行错位。
  • 在全景中的位置：见 π 公司线 的“动作怎么出得又好又快”：FAST → 知识隔离 → RTC → 训练时 RTC。

自测

为什么前缀的 τ 要设成 1，而不是 0？

按 Aτ=τA+(1−τ)ε 的约定，τ=1 表示完全没有噪声的真实动作，τ=0 表示纯噪声。前缀是已知的干净动作，所以取 1。

推理时 RTC 的额外开销具体来自哪里？

每个去噪步都要对“估计终点”做一次向量-雅可比积（反向传播），把加权误差传回输入，得到引导修正量。5 个去噪步就多 5 次反向传播。

训练时 RTC 为什么不需要额外的参数？

adaLN-zero 本来就根据时间嵌入算 scale/shift/gate，只需让时间嵌入逐 token 不同，线性层权重保持共享。

为什么延迟越大，训练时 RTC 的优势越明显？

前缀越长，推理时补全要用一阶线性化把更多位置“拽”到目标上，近似误差越大；训练时 RTC 直接学到了对应的条件分布，不依赖这种近似。

它能完全替代推理时 RTC 吗？

大多数场景可以，真机上效果持平且更省计算。但它只支持硬前缀、需要事先确定延迟分布、要额外微调；需要软约束或现成 checkpoint 时，推理时 RTC 仍然有用。
