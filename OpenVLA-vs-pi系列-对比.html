OpenVLA vs π 系列（openpi）：动作该怎么生成？

两者都是"VLM 骨干 + 输出机器人动作"的 VLA，最核心的分歧只有一个：动作是像文字一样逐个生成离散 token，还是交给一个独立的生成式动作专家，一次输出一段连续动作。

OpenVLA斯坦福 / 伯克利 / TRI 等，2024.06
π0Physical Intelligence，2024.10
开源仓库openvla · openpi
主题动作表示 · 骨干与架构

一句话区别

OpenVLA：把动作当文字

沿用 RT-2 路线。每个动作维度切成 256 个 bin，借用词表里的 token，由 Llama 2 自回归地一个一个输出，一次只输出一步动作。

π0：VLM 负责理解，动作专家负责生成

VLM 之外另接一个约 300M 的"动作专家"，用 flow matching 从噪声中生成连续动作，一次输出一段 action chunk（50 步）。

为什么动作头是分水岭

  • 精度：每维 256 个 bin 是粗量化，细腻的连续控制会损失精度；flow 直接在连续空间建模，还能表达多峰分布（同一场景下有多种合理做法）。
  • 速度：自回归每输出一个维度就要前向一次，7 维动作就要解码 7 个 token；动作块配合并行生成，一次推理就能覆盖未来多步。
  • 知识保留：离散 token 与文字共享输出空间，天然保留 VLM 的语言能力；独立动作专家的梯度会回传到骨干、破坏 VLM 知识，π0.5 后来用离散 FAST token与知识隔离来补这一点。

口诀：OpenVLA 是"语言模型顺便说动作"，π0 是"语言模型看懂之后，交给专门的手去动"。

后来两条路线互相借鉴

OpenVLA → OpenVLA-OFT（2025.02）

放弃逐 token 解码，改为并行解码 + 动作块 + 连续动作 L1 回归，速度和成功率都大幅提升，实际已向 π0 的"一次输出一段连续动作"靠拢。arXiv 2502.19645

π0 → π0-FAST / π0.5 / π*0.6 / π0.7

反过来引入离散 token：π0-FAST 用 DCT + BPE 压缩动作 token（精读）；π0.5 训练时用离散 token、推理时用 flow；π*0.6 加入 RL（RECAP）；π0.7 让模型可以通过提示调节行为。

所以今天的分界已经不是"谁离散、谁连续"，而是训练时用离散 token 保住语义，推理时用连续生成保证精度和速度的混合方案。

该选哪个上手

  • 想理解 VLA 的最小形态、在单卡上做 LoRA 微调或改代码：先读 OpenVLA。它是 PyTorch + HuggingFace 实现，结构最直白。
  • 要做灵巧、高频或双臂任务，或者想直接用强 base 模型微调：用 openpi 的 π0 / π0.5 checkpoint（JAX 实现，也有 PyTorch 支持）。
  • 要研究 VLA + RL：本库的 πRL、RL Token 都以 π 系列为底座，见 VLA-RL 全景。
