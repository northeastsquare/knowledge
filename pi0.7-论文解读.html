π0.7：用“说清怎么做”的提示，喂进更杂的数据

π0.7 是 Physical Intelligence 的 5B 参数 VLA。结构沿用 π0.6：VLM 主干 + 流匹配动作专家，再加上 MEM 的历史视觉编码。真正的新东西在提示里：除了“做什么”，还告诉模型“这条数据是怎么做的”——子任务、子目标图像、速度、质量、有没有失误、控制模式。这样连失败数据、RL 模型自己跑的数据都能拿来训。

论文π0.7: a Steerable Generalist Robotic Foundation Model with Emergent Capabilities
机构Physical Intelligence
arXiv2604.15483v2 · 本地 PDF
规模4B VLM（含 0.4B 视觉）+ 0.86B 动作专家 ≈ 5B
官方代码未开源（openpi 只到 π0.5）
对照代码openpi π0.5 · 开源复现 pi_model

带着问题读

  1. 失败数据为什么反而能让模型变好？靠的是哪个输入？
  2. 6 帧历史图像进来，主干看到的 token 为什么和 1 帧一样多？
  3. FAST token 和流匹配动作 token 都在预测动作，为什么不能互相看？
  4. 推理延迟 240 ms 时，新动作块怎样接上正在执行的旧动作？
  5. 测试时没有“真实未来帧”，子目标图像从哪里来？

先说结论

01 · 方法

不是新架构

主体结构来自 π0.6 和 MEM。贡献是一套“多样化提示”训练法，外加实证分析。

02 · 提示

说清“怎么做”

提示 = 任务 + 子任务 + 子目标图像 + 元数据（速度 / 质量 / 失误）+ 控制模式。训练时每一项都随机丢掉。

03 · 数据

杂数据变成养分

带元数据时，数据越多越好，哪怕平均质量变差。不带元数据，加入差数据后反而变差。

04 · 运行

测试时“点菜”

固定填 Quality 5、Mistake false、较快的 Speed；再用 CFG 把动作往“好”的方向推。

整体架构

一句话：图像、子目标、文本、状态一起进 Gemma 3 主干；主干只学 FAST 离散动作；动作专家隔着 stop-gradient 读主干每层的 K/V，把噪声去成 50 步动作。

多样化提示：每一项在说什么

以前的 π0、π0.5、π0.6 只给一句简短任务。π0.7 把提示扩成多种模态。论文给的完整例子：

<多视角观测><多视角子目标>
Task: peel vegetables. Subtask: pick up the peeler. Speed: 8000. Quality: 5.
Mistake: false. Control Mode: joint.<本体状态>

小例子：Speed 怎么取整。一条 episode 用了 2130 步（50 Hz 下约 42.6 s）。按 500 一档：2130 / 500 = 4.26，四舍五入成 4，写成 Speed: 2000。1750 到 2250 步都写成 2000。
为什么有用：同一个“叠衣服”任务里，有 2000 步的利落数据，也有 6000 步、失误多次的数据。不加标签时，模型只能学两者的平均。加了标签，模型分得清“6000 + Quality 2”是一种做法，“2000 + Quality 5”是另一种。测试时只点后一种。

这就像点外卖时写备注。厨房做过各种口味（数据有好有坏），备注“少辣、快送”（元数据）告诉它这次要哪种。没有备注，它只能按平均口味做。

状态不再写成文本数字。π0.6 把 q 离散成文本 token；π0.7 照 MEM 的做法，用一个线性层把每帧状态投成一个主干宽度的 token。历史帧被丢时，对应状态 token 也一起遮掉。

MEM 历史视觉编码

π0.7 每个相机最多看 6 帧（现在和过去 5 秒，每秒一帧）。直接全塞进主干太贵，所以在视觉编码器内部就把时间信息压进当前帧。

算一下 token 数。一张 448×448 的图，patch 14 → 32×32 = 1024 个 patch。6 帧就是 6144 个。经过 MEM 编码器后只留当前帧的 1024 个，再 2×2 池化成 256 个。3 个相机 = 768 个观测 token；再加 3 张子目标图 = 1536 个图像 token。如果不压缩，6 帧 × 3 相机 × 256 = 4608 个，是 768 的 6 倍。

图 3 · MEM 时空注意力。实现见复现 pi_model/vision.py 的 space_time（第 45–70 行）。1 帧时这些额外计算不起作用，输出与原 SigLIP 完全一样，所以能直接用预训练权重。

复现里的两点假设：时间注意力只看“同一位置”的 patch；过去帧在最后一个时间层后丢掉。论文只说“时间和空间压缩、输出固定数量的 token”，细节以 MEM 原文为准。

注意力掩码

主干和动作专家的 token 拼成一条长序列。谁能看谁，由下面这张表决定（行 = 正在看的 token，列 = 被看的 token）。

图 4 · 分段掩码。依据论文 Fig. 19 与复现 pi_model/model.py 第 31–38 行的 RULE 表。局部层再叠加 1024 的滑动窗口。

  • FAST 和动作 token 互相看不见。两者都在预测同一段动作。如果动作 token 能看 FAST，就等于偷看答案；而 FAST 只在训练时存在，推理时没有，看了也对不上。
  • 子目标能看观测，观测看不到子目标。没有子目标的样本（75%）里，观测 token 的表示不受影响。
  • CFG 推理时，论文把“有元数据”和“无元数据”两条分支打包进同一条序列，两支互相看不见（论文叫 attention tree）。一次前向就拿到两个速度。

训练目标：知识隔离 + 流匹配

π0.7 沿用 知识隔离（KI）：主干只被离散的 FAST token 交叉熵训练；动作专家用 流匹配 训练，它读主干的 K/V，但梯度不传回主干。

总损失：

\[ \mathcal{L} = \underbrace{-\sum_{j}\log p_\theta\!\left(f_j \mid f_{<j},\,\text{prefix}\right)}_{\text{FAST 交叉熵：训主干}} \;+\; \underbrace{\big\lVert v_\phi\!\left(x_\tau,\tau,\ \mathrm{sg}[KV]\right) - (a-\varepsilon)\big\rVert^2}_{\text{流匹配：只训专家}} \]
  • \(f_j\)：第 \(j\) 个 FAST token；\(\text{prefix}\) 是图像、文本、状态 token。
  • \(a\)：真实动作块（50 步）；\(\varepsilon\)：标准高斯噪声，形状和 \(a\) 一样。
  • \(\tau\in(0,1]\)：流匹配时间；复现里 \(\tau=1\) 是干净动作。
  • \(x_\tau=\tau a+(1-\tau)\varepsilon\)：加噪后的动作。
  • \(v_\phi\)：动作专家输出的速度；目标是 \(a-\varepsilon\)。
  • \(\mathrm{sg}[KV]\)：主干每层的 K/V 加 stop-gradient（复现第 147 行 k.detach(), v.detach()）。
小例子（一个动作维）。真实动作 \(a=0.8\)，噪声 \(\varepsilon=-0.4\)，\(\tau=0.25\)：
\(x_\tau = 0.25\times0.8 + 0.75\times(-0.4) = 0.2-0.3 = -0.1\)。目标速度 \(a-\varepsilon = 1.2\)。
推理从纯噪声 \(-0.4\) 出发，5 步、每步 \(\Delta\tau=0.2\)。若每步都预测 1.2，走 5 步：\(-0.4 + 5\times0.2\times1.2 = 0.8\)，正好回到真实动作。

τ 的方向要注意。官方 openpi 反过来：t = 1 是纯噪声，x_t = t·noise + (1−t)·actions，目标 noise − actions，采样时 dt = −1/num_steps（openpi/models/pi0.py 第 199、200、228 行）。两种写法等价，只是正负号相反。两边的时间采样都是 Beta(1.5, 1)，偏向噪声多的一端（openpi 第 197 行；复现第 153 行）。

τ 怎么进专家。和 π0.5 的 adaRMSNorm 一样：τ 先做正余弦编码，再经 MLP，去调 RMSNorm 的缩放与偏移。openpi 在 pi0.py 第 161–169 行；复现在 layers.py 第 27 行 AdaRMSNorm。

训练时 RTC

机器人不会停下来等模型。推理要 38–127 ms，这段时间里机器人还在执行上一块动作。π0.7 用 训练时 RTC：训练时随机假装延迟 \(d\) 步，把前 \(d\) 步换成干净真值，不算损失。

数字：论文模拟 \(d\in\{0,\dots,12\}\)。50 Hz 下一步 20 ms，12 步 = 240 ms，正好盖住最坏的推理延迟。

图 5 · 训练时 RTC，一格 = 1 步，共 50 步。复现：训练 model.py 第 187 行起，推理 sample_actions 第 205 行起。

训练时 RTC 不需要推理时额外反传。LeRobot 的 policies/rtc 两种都有：mode="guided" 是推理时的雅可比引导，mode="trained" 是直接覆盖前缀，需要用训练时 RTC 训出的权重（configuration_rtc.py 第 68–70 行）。

子目标图像与世界模型

子任务“打开冰箱门”没说抓把手哪里。子目标图像直接画出几秒后每个相机该看到的样子。有了它，预测动作几乎变成“逆动力学”：已知现在和将来的画面，推中间的动作。所以训练变得很快，论文只给 25% 的样本加子目标，免得模型过度依赖它。

项目数值（论文）

训练损失 \(\max_\psi \mathbb{E}\,\mathcal{L}_{\mathrm{CFM}}\big(g^\star_t,\ g_\psi(o_t,\hat\ell_t,m)\big)\)。\(g^\star_t\) 是片段结束时的真实画面，\(o_t\) 是当前观测，\(\hat\ell_t\) 是子任务，\(m\) 是元数据，\(\mathcal{L}_{\mathrm{CFM}}\) 是流匹配损失。

世界模型还混入人类第一视角视频、网络图像编辑数据。这些知识先进世界模型，再通过“画出来的子目标”传给 π0.7。开源复现没有实现世界模型，训练只用真实未来帧。

元数据 CFG

因为训练时元数据会被丢，模型同时会“有元数据”和“没元数据”两种预测。推理时把两者的差放大，就是 无分类器引导（CFG）：

\[ v = v_c + \beta\,(v_c - v_u) \]
  • \(v_c\)：提示里带“Quality 5、Mistake false、Speed 快”时的速度。
  • \(v_u\)：去掉这些元数据时的速度。
  • \(\beta\)：引导强度，论文用 1.3、1.7、2.2。
小例子：\(v_c=1.0\)，\(v_u=0.6\)，\(\beta=1.7\)。\(v = 1.0 + 1.7\times0.4 = 1.68\)。“好做法”比“平均做法”多出的那 0.4，被放大了 1.7 倍再加上去。复现在 model.py 第 236 行。

实验要点

问题结论（论文）
开箱即用能否赶上专用模型？做咖啡、折纸箱、叠衣服上，与 π*0.6 的 RL 专用模型相当；叠衣服、折纸箱的吞吐还更高。其他灵巧任务接近基于 π0.6 的 SFT 专用模型。
跨机型UR5e 双臂从没采过叠衬衫数据。π0.7 任务进度 85.6%、成功率 80%；10 位资深遥操作员零练习时为 90.9% 和 80.6%。
杂数据能不能用？叠衣数据按质量分 4 桶（前 30%、50%、80%、全部），共训 8 个模型。带元数据：数据越多越好；不带：数据变多反而变差。
多样性有没有用？去掉“任务最多样的 20%”比随机去掉 20% 掉得多。
joint 还是 ee？跨机型任务上两者差别不大，主实验用 joint。

训练数据还包括：失败与多次失误的示范、历代模型评测时自己跑的数据（含 π*0.6 RL 训练时的数据）、人工干预、开源机器人数据、人类第一视角视频和网页多模态数据。泛化评测任务上采到的自主数据被排除在训练之外。

疑问与风险

  • 标注成本高。Quality 和 Mistake 要人工按片段打。换到自己的数据上，这一步很难省。
  • “Speed”其实是时长。它是整条 episode 的步数，不是瞬时速度。不同任务的数值不可比，所以推理时要按任务取百分位。
  • 世界模型很贵。14B、4 张 H100 才能 1.25 s 出一组图。没有它时，π0.7 只能靠语言子任务。
  • 动作专家宽度未公开。论文只给 860M 总量。复现的 1216 / 4608 是凑出来的。
  • 没有开源权重。页面里的所有“代码行”要么是官方 π0.5，要么是个人复现，都不是 π0.7 官方实现。

读后思考 · 练习题

1. 一个任务训练集里 episode 长度分别是 1800、2100、2600、3400、5200 步。推理时 Speed 大约填多少？

取第 15 百分位，落在最短的几条附近，约 1800–2100 步；按 500 取整写成 Speed: 2000。意思是“按快的那批数据的节奏做”。

2. 为什么只给 25% 的样本加子目标图像？

有子目标时，预测动作变成“已知现在和将来画面，推中间动作”的逆动力学问题，太容易。全给的话模型会依赖它，没有子目标时就做不好。论文说加了子目标训练快得多。

3. 如果把 stop-gradient 去掉，会发生什么？

流匹配的梯度会改主干。KI 论文的观察是：这会冲掉 VLM 预训练学到的知识，训练也变慢。π0.7 让主干只吃稳定的 FAST 交叉熵。复现里 knowledge_insulation=False 就是这个对照开关。

4. 推理延迟 100 ms、控制 50 Hz，RTC 的前缀 d 该是几？

100 ms / 20 ms = 5 步，所以 d = 5。这 5 步填正在执行的旧动作，模型只去噪后 45 步。训练时 d 在 0–12 里随机，覆盖了这个值。

5. CFG 里 β = 0 是什么意思？β 越大越好吗？

β = 0 时 \(v=v_c\)，就是普通的带条件预测。β 越大，越往“好数据”方向推，但推过头会偏离训练分布、动作发抖。论文只用 1.3–2.2 这样的中等值。

6. 6 帧历史为什么不会让主干变慢？

时间信息在视觉编码器里就并进了当前帧；第 24 层之后过去帧被丢掉。主干看到的仍是每相机 256 个 token。代价只在视觉编码器那几层。
