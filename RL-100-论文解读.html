RL-100：真机强化学习，把成功率压到 100%

在模仿学习训出的扩散策略之上做三段式 RL 后训练。核心不是新算法，而是一套可复用、能保证"每步都在变好"的工程流水线：用 OPE 当闸门把关迭代离线 RL，再拿小预算在线 RL 清长尾。

1要解决什么问题

模仿学习有个天花板：它只能学到演示里已有的东西。

纯行为克隆（BC）的性能上限受限于演示数据的质量与覆盖度。演示本身有噪声、不一致，长程任务里小误差会累积成失败；而且 BC 无法优化"完成得多快"——演示里的人怎么做，模型就怎么学。

但直接在真机上跑朴素 RL 又是另一组麻烦：样本低效、训练不稳定、探索不安全。真机的每一次失败都要花时间、磨损硬件。

RL-100 的定位很明确：不是提出新的 RL 算法，而是把 IL 先验、离线 RL 的稳定性、在线 RL 的收尾能力拼成一条工程上可复用、改进单调的流水线。

2三段式流水线

IL 打底 → 迭代离线 RL 挑大梁 → 在线 RL 收尾。

① 模仿学习（IL）在遥操作演示上训扩散视觉运动策略。建立低方差底盘，论文称其 "a competent, low-variance base"。每任务约百来条演示，小时级。
② 迭代离线 RL（主算力）用策略自己跑出的 rollout 不断扩充数据，用 OPE 闸门决定是否接受更新。论文明确说这一阶段 "delivers the bulk of the improvement"，性能提升的大头在这里。
③ 在线 RL（小预算）on-policy 微调，专门清掉残余的长尾失败模式，把 ~95% 推到 99%+，即 "the last-mile reliability"。
关键在阶段②的循环：策略自己在真机上跑 → 数据并入 replay buffer → 离线更新 → OPE 评估通过才推进，否则保持原策略不变。这个"接受门槛"是整条流水线稳定性的来源。

OPE 闸门具体怎么把关

论文用 AM-Q——一个带学习到的转移模型的估计器——来比较"候选策略"和"当前行为策略"，不需要额外与真机交互。规则是：

候选策略的 AM-Q 估计比当前策略高出至少 δ 时，才接受这次更新、把行为策略推进为 πi+1 ≔ π；否则行为策略保持不变。

δ 是自适应的：δ = 0.05·|Ĵ_AM-Q(π_i)|。论文把这条规则称为 "OPE-gated"，效果是保守且单调的行为策略改进——这正是它敢在真机上反复迭代而不崩的原因。

离线阶段不采集任何新环境数据；候选策略来自在数据集 D 上跑若干轮梯度更新。只有"通过闸门"的策略才会被真机拿去跑 rollout、产生新数据。

3两个关键技术

设计一把 PPO 套在去噪链上：一个目标打通离线与在线

扩散/流策略一次要跑 K 步去噪。RL-100 把整个去噪过程当成一个 K 步的子 MDP，嵌在每个环境时间步内部，然后在每一步去噪上都套 clipped PPO 代理目标：

Ji(π) = Σk=1..K min( rk(π)·At, clip(rk, 1−ε, 1+ε)·At )

  • 关键设计：At 是环境层面的优势，在 K 个去噪步之间共享。这样既给去噪过程提供了密集信号，又与环境的奖励结构保持一致。
  • 每步去噪的重要性比值 rk 用高斯子策略似然算（Eq. 7），仅在方差严格为正处有效。
  • 离线与在线共用一个代理目标，只有优势估计方式不同：离线用 IQL 式的 A = Q(s,a) − V(s)，在线用 GAE。这是"离线→在线切换不崩"的机制保证。
  • 只更新任务头：离线 RL 阶段视觉编码器 φ 是冻结的，防止表示漂移。
  • 方差裁剪（Eq. 23）：把标准差裁到 [0.01, 0.8]，限制行为策略的随机性、让 PPO 的重要性比值保持良性。论文说会"经验性地证明这个简单修改至关重要"。

注意区分：IL 阶段用的仍是监督式的噪声预测损失（加可选的重建 / VIB-KL 正则），不是这个 RL 目标。共享的是离线 RL 与在线 RL 这一个目标。RL 微调时重建/VIB 的权重 β 会下调 10 倍，保持表示稳定。

设计二一致性蒸馏：把多步去噪压成单步

训练时用多步采样（K 步），部署时蒸馏成一个一致性模型，一步出结果：x⁰ ≈ Cθ(xτ_K, τ_K)，xτ_K ~ N(0,I)。

  • 和 RL 联合训练：L_total = L_RL + λ_CD·L_CD，用带 stop-gradient 的一致性蒸馏目标（Eq. 9），把扩散策略当 teacher。stop-gradient 的作用是让 teacher 在被 RL 持续改进的同时，仍能充当蒸馏目标。
  • 前提：teacher 必须遵循与 student 相同的子采样时间表 {τk}。
  • 收益：多步采样上获得 K× 加速，论文表述为"一个数量级的延迟下降，同时保住任务性能"，给出的具体例子是 100ms → 10ms。

这篇 arXiv 版本没有量化蒸馏的额外成本，只称其为 "lightweight distillation loss"；也没有报告达成的控制频率。Hz 只在动机部分出现过一次（对比 20Hz 与 10Hz，说 20Hz 循环能把轨迹时间减半），不是实验结果。

设计三奖励设计

除 Dynamic Push-T 外，全部是稀疏奖励：任务成功时 +1，其余为 0，由人工监控者敲键盘给出。

Dynamic Push-T 用稠密整形奖励，三项之和：

  • r_pose = exp(−3e) − 1，e 是 T 型块与目标位姿之间的 SE(3) 偏差；
  • r_static = −1 若该步内 T 型块位移低于阈值，否则 0（惩罚"不动"）；
  • r_smooth = −5‖a_t − a_{t−1}‖²（惩罚动作抖动）。

4数据流与运行方式

观测以 3D 点云为主，控制模式单步与动作块都支持。

训练循环（Algorithm 1）

  1. 训练 critic（IQL）与一个转移模型；
  2. 离线 RL 更新，候选策略通过 OPE 闸门才被接受；
  3. 用新策略在真机 rollout，采集新数据；
  4. 数据并入，并在扩充后的数据上重新训练 IL；
  5. 重复 2–4，在线微调只在循环之后跑。

为什么要在扩充数据上重训 IL，论文给了四条理由：分布偏移、稳定性、多模态、蒸馏。

6消化成可复用的结论

  • 真机 RL 的瓶颈常常不是算法，而是"敢不敢迭代"。RL-100 最大的工程贡献是把"每次更新都要保证不变差"做成了一条可执行的闸门规则（OPE-gated、δ 自适应）。有了它，离线迭代才能反复跑而不崩。
  • 离线挑大梁、在线收尾，是样本预算受限时的正确分工。训练时在真机上自由探索的代价太高；把绝大部分改进放在"不采新数据的离线迭代"里，只在最后用少量在线交互啃长尾。
  • 越难的任务收益越大，正是"先验 + 细化"的价值所在。IL 已经能做好的任务（拧螺母 82%、倒液 78%）提升有限；IL 做不好的（保龄球 14%、Push-T 40%）提升幅度最大。
  • 把去噪链当子 MDP、共享同一个环境级优势，是一个通用的"让扩散/流策略能被 PPO 训练"的技巧。和把优势条件化（RECAP）或只训噪声策略（DSRL）是同一问题的不同解法。
  • 部署延迟要靠蒸馏解决，而不是靠减少去噪步数。训练时保持多步采样质量，部署时蒸馏成单步（100ms → 10ms），trade-off 被挪到了训练端。

7疑问与局限

  • OPE 闸门依赖一个学习到的转移模型（AM-Q）。这个模型本身的误差会怎么影响"接受/拒绝"的判断，论文没有深挖——而它恰恰是整条流水线稳定性的支点。
  • 奖励仍需人工。除 Push-T 外都是稀疏奖励，靠人敲键盘标 +1。七任务、每个上千次 rollout，人工标注的负担不小，也限制了扩展到更长的任务。
  • 蒸馏成本未量化。arXiv 版只说 "lightweight"，没有给出额外训练开销，也没有报告实际达成的控制频率。
  • 重新训练 IL 的四条理由（分布偏移、稳定性、多模态、蒸馏）更像经验论述，缺少"去掉重训 IL 会怎样"的独立消融。
  • 点云 vs RGB 只在仿真对比过，真机上的表示选择仍按经验定。
  • 与 π 系列的关系需要留意版本差异：本文 arXiv 版是七任务、900/900；后续期刊版本任务数与试验数更多。引用具体数字时要注意对应的是哪一版。
一句话总结

RL-100 的贡献不是"某个更好的 RL 算法"，而是证明了一条真机流水线可以做到改进单调、可反复迭代：先让 IL 给一个不差的地板，再用"OPE 把关的迭代离线 RL"承担绝大部分提升，最后用小预算在线 RL 把最后的 5% 补上，并靠一致性蒸馏换回部署时的一个数量级延迟。
