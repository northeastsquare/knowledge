π0.7: a Steerable Generalist Robotic Foundation Model with Emergent Capabilities pi.website/pi07
一句话总结

π0.7 是一个 5B 参数的可操控(steerable)通用机器人基础模型,核心创新是在训练时使用多样化的 context conditioning——不只告诉模型"做什么(语言指令)",还通过 episode metadata(质量/速度/是否出错) 和 subgoal images 告诉它"怎么做、做得好不好"。这让模型能从大规模、混合质量、甚至失败的次优数据中学习而不被"平均化",从而涌现出组合泛化、跨本体迁移、复杂语言跟随等能力。

01

方法论,而非新架构

作者明确说不提新架构,而是提出一套"让 VLA 用上更多样数据源"的方法 + 实证分析。

02

Diverse prompting

把 metadata + subgoal images + 更丰富的 subtask 语言塞进 prompt,训练时全部随机 dropout,测试时可任意组合。

03

混合质量数据可扩展

带 metadata 时数据越多越好(哪怕平均质量下降);不带 metadata 反而越训越差。

01

核心思想与动机

Motivation
Q
Q1π0.7 要解决的核心问题是什么?
点击查看答案 ▸
A
此前的 VLA 缺乏组合泛化(compositional generalization)能力——不仅无法解决新任务,甚至常常无法在不做任务特定微调的情况下流畅执行所有训练过的指令。π0.7 旨在让 VLA 具备类似 LLM 的能力:把训练数据中的技能以新方式重组来解决新问题。
Q
Q2π0.7 的 main idea 是什么?
点击查看答案 ▸
A
训练时使用 diverse context conditioning。不只用描述"做什么"的语言指令,还加入描述"怎么做/用什么策略"的多模态信息(episode metadata 和 subgoal images)。这能消解大规模多样数据中的歧义,让模型从次优数据中学习而不损害性能。
Q
Q3为什么不能直接(naively)在多样化数据上训练?
点击查看答案 ▸
A
多样化数据在策略和完成质量上各不相同,naive 训练会把数据集里不同的 mode 平均(average together),产生次优结果。例如同一任务有快有慢、有成功有失败,平均后两头不靠。
Q
Q4方法的灵感来源是什么?为什么 robotics 不能照搬?
点击查看答案 ▸
A
灵感来自图像/视频生成中的 prompt expansion(用更详细 prompt 提升生成质量)。但 robotics 里光给数据加更详细的文字 caption 不够——决定成败的细节可能很微妙(如整体 episode 质量),或难以用语言表达(如一件叠好 T 恤的具体外观)。所以除文字外还要加 metadata 和 subgoal images。
Q
Q5π0.7 相比前代在 context 上的关键扩展是什么?
点击查看答案 ▸
A
π0/π0.5/π0.6 只用任务的简短文字描述作 context。π0.7 扩展为:更具表达力的 language commands、episode metadata、subgoal images,从而能在多样且可能次优的数据上训练。
02

Flow-based VLA 基础

Foundations
Q
Q6VLA 的基本训练范式?
点击查看答案 ▸
A
VLA 从预训练 VLM backbone 出发适配机器人控制。数据集 D 包含机器人轨迹(观测 o_t 和动作 a_t 序列)。观测 o_t = [I¹_t,…,Iⁿ_t, q_t](n 个相机图像 + 关节构型 q_t),动作为关节或末端执行器命令。
Q
Q7什么是 action chunk?为什么用 action expert?
点击查看答案 ▸
A
VLA 通常预测 action chunk,即未来一小段动作 a_{t:t+H}(执行时常用更短 horizon Ĥ < H)。action chunk 由 action expert 生成——一个更小的 transformer,attend 到 VLM backbone,实现快速推理。它通常用 flow matching(或 diffusion) 目标以捕捉动作的多模态性。
Q
Q8什么是 Knowledge Insulation (KI) 训练配方?
点击查看答案 ▸
A
VLM backbone 用 FAST tokens 监督;action expert 虽然 attend 到 VLM backbone 的所有 activations,但 action expert 的梯度不回流到 VLM backbone。这样 VLM 通过相对稳定的离散 cross-entropy loss 训练,而不被 flow matching 的 noisy 梯度干扰。
Q
Q9π0.7 的训练目标?flow matching 扮演什么角色?
点击查看答案 ▸
A
目标是给定观测历史和 context C_t 的动作近似 log-likelihood:max_θ E_D [ log π_θ( a_{t:t+H} | o_{t-T:t}, C_t ) ]注意 flow matching action expert 优化的是近似下界(approximate lower bound),不是闭式 log-likelihood。
Q
Q10context C_t 在传统 VLA 和 π0.7 中分别是什么?
点击查看答案 ▸
A
传统上 C_t = (ℓ_t),仅一条人工标注的语言指令(如 "clean up the kitchen")。π0.7 把 C_t 扩展为多模态、包含策略信息的丰富上下文。
03

Prompt 多样化（核心贡献）

★ Key Contribution
Q
Q11π0.7 的 prompt(context C_t)包含哪几部分?
点击查看答案 ▸
A
(1) Subtask instructions ℓ̂_t;(2) Subgoal images g_t;(3) Episode metadata m(speed/quality/mistake);(4) Control mode c。训练时对子任务指令、子目标图像和 metadata 做随机 dropout,让模型适应这些条件缺省的情况；control mode 保留。
Q
Q12Subtask instruction 是什么?跟整体任务描述什么关系?
点击查看答案 ▸
A
沿用 π0.5,在整体任务描述 ℓ_t(如 "clean the kitchen")之外,加入捕捉下一个语义子任务的中间层文字 ℓ̂_t(如 "open the fridge door")。推理时 ℓ̂_t 可由学到的 high-level policy 或人类提供(也可省略),且会随时间变化。
Q
Q13Subtask instruction 还带来什么额外能力?
点击查看答案 ▸
A
让模型可被逐步口头指导(verbal coaching)。因为模型训练成能跟随多样语言指令,它能在新任务中跟随人类的 live 指令(如把红薯放入空气炸锅)。之后可用这些 coaching 数据微调出一个 high-level policy,让机器人全自主执行。
Q
Q14Subgoal images 补足了 subtask instruction 的什么不足?
点击查看答案 ▸
A
subtask instruction 传达高层意图,但缺执行细节——如 "open the fridge door" 没说手臂该怎么抓把手。Subgoal images 通过描绘场景的期望近未来状态,更丰富地指定"任务成功推进后世界该是什么样"。
Q
Q15为什么用 multi-view subgoals?各视角分工是什么?
点击查看答案 ▸
A
g_t = [G¹_t,…,Gⁿ_t],G^i_t 是相机 i 的期望近未来图像。多视角同时指定环境/物体中心的结果(base view 最易)和手臂/夹爪的结果(wrist view 最易),改善控制的空间 grounding。
Q
Q16Episode metadata 包含哪些字段?怎么定义?
点击查看答案 ▸
A
  • Overall speed:episode 时间步长度,按 500 步区间离散化(如 1750–2250 → "2000 steps")。速度快常对应质量高(错误少)。
  • Overall quality:1–5 分,5 最高。
  • Mistake:某 action segment 内机器人是否出错(如没抓住物体、做错子任务)的布尔标签,由人工粗标。
Q
Q17为什么 episode metadata 是 π0.7 能用次优数据的关键?
点击查看答案 ▸
A
π0.7 大量使用低质量演示(含失败)和旧模型的自主数据。要让模型测试时仍尽可能好地执行,就需要用 metadata 标注这些轨迹"任务执行得如何",让模型正确 contextualize 它们。数据多样性(如不同速度的 episode)提供必要信号让模型学会把 metadata 与目标动作关联。测试时即可通过 metadata prompting 指定"高速、高质量、无错误"。
Q
Q18Control mode 是什么?
点击查看答案 ▸
A
文字标识 c ∈ {joint, ee},指定底层动作执行用关节空间还是末端执行器。训练时两种都包含,测试时按任务选择。
Q
Q19一个完整 prompt 长什么样?
点击查看答案 ▸
A
<Multi-view observation><Multi-view subgoals> Task: peel vegetables. Subtask: pick up the peeler. Speed: 8000. Quality: 5. Mistake: false. Control Mode: joint. <Proprioception>
Q
Q20训练时各组件的 dropout 策略?为何这样设计?
点击查看答案 ▸
A
  • Subgoal images:仅加到每个 batch 的 25% 样本。因为给了 subgoal 后动作预测变成 "inverse dynamics" 问题(推断当前帧到未来帧之间的动作),训练快很多,故意只给少部分以防过度依赖。
  • 有 subgoal 的样本中,subtask instruction 再以 30% 概率 dropout(视觉 subgoal 常能更丰富地替代文字)。
  • Episode metadata:整体 15% 概率全 drop;另外每个分量(speed/quality/mistake)各以 5% 概率单独 drop。
  • Control mode:不做 dropout。
04

模型架构细节

Architecture
Q
Q21π0.7 的总体规模和组成?
点击查看答案 ▸
A
约 5B 参数。包括:4B VLM backbone(从 Gemma3 4B 初始化,含 400M vision encoder)+ MEM 式 video history encoder + 860M flow matching action expert。
Q
Q22π0.7 相比 π0.5/π0.6 的主要架构改动?
点击查看答案 ▸
A
(1) 采用 MEM 的 history vision encoder;(2) 在 context 中加入 visual subgoal images。
Q
Q23history encoder 怎么处理历史帧?
点击查看答案 ▸
A
vision encoder 也从 Gemma3 初始化,遵循 MEM video history encoder 设计,对历史观测做时间和空间压缩,对任意数量历史帧输出固定数量的 token。历史帧经 encoder 压缩到与单帧相同的 token 数;subgoal images 用同一 encoder 处理。
Q
Q24模型接受多少相机/历史帧?分辨率多少?
点击查看答案 ▸
A
最多 4 个相机(front、两个 wrist、可选 rear),每个最多 6 个历史帧;最多 3 个 subgoal images(省略 rear view)。相机观测和 subgoal images 都先 resize 到 448×448。历史帧采样 stride 为 1 秒;历史帧整体以 0.3 概率 dropout;rear view 也以 0.3 概率 dropout。
Q
Q25π0.7 用什么 attention masking?
点击查看答案 ▸
A
block-causal masking。observation tokens 和 subgoal image tokens 在各自内部用双向 attention;goal-image tokens 还能额外 attend observations;后续 text tokens 用 causal attention。
Q
Q26π0.7 怎么处理 proprioceptive state q_t?跟 π0.6 有何不同?
点击查看答案 ▸
A
π0.6 用离散化的 text tokens 表示 q_t;π0.7 遵循 MEM,用 linear projection 把 state 维度映射到 backbone 维度来 embed。每个历史 state 当作单独 token;若对应历史帧被 drop,该 state token 也被 mask。
Q
Q27Action expert 的具体设计?
点击查看答案 ▸
A
860M 参数 transformer,用 flow matching 预测连续动作。用 adaptive RMSNorm 注入 flow matching 的 timestep 信息。固定 50 个 action token = 50 步 action chunk。这 50 个 token 之间双向 attend,并可 attend VLM backbone 的 activations。
Q
Q28什么是 RTC?π0.7 怎么用?
点击查看答案 ▸
A
Real-Time action Chunking,用于在有推理延迟时生成平滑动作轨迹。π0.7 用 training-time 版本:训练时模拟 0–12 时间步的延迟,对应 50Hz 机器人最大 240ms 推理延迟。training-time RTC 不增加推理时开销。
05

World Model / 子目标图像生成

World Model
Q
Q29运行时 subgoal images 由什么产生?
点击查看答案 ▸
A
一个 lightweight world model g_ψ,它接受与主模型相同的 subtask instruction ℓ̂_t,但受益于在视频和图像编辑任务上的 web-scale 预训练,能泛化到多样任务和场景。
Q
Q30World model 的训练目标?
点击查看答案 ▸
A
max_ψ E_{D_g} [ L_CFM( g*_t , g_ψ(o_t, ℓ̂_t, m) ) ]L_CFM 是标准 flow matching loss,g*_t 是未来 subgoal image,m 是 episode metadata,D_g 是 subtask label 质量特别高的 segment 子集。segment 末尾的图像帧作为 ground-truth subgoal,即 g*_t = o_{t_end}。
Q
Q31World model 从什么初始化?为何这样选?
点击查看答案 ▸
A
遵循 SuSIE,从现成图像生成/编辑模型初始化——具体是 BAGEL(14B mixture-of-transformers),能做图像理解、编辑、生成。用 web 数据 + 非机器人数据(如 egocentric human videos)+ 其他视频数据增强训练,从而获得语义和物理概念,再通过 subgoal images 迁移进 π0.7。
Q
Q32生成的 subgoal images 相比语言指令有什么优势(实验角度)?
点击查看答案 ▸
A
grounded 在机器人当前观测上的生成 subgoal,常能比语言指令更清晰地消解目标歧义,改善 language following 和泛化。在 complex referential instructions 和 "Reverse Fridge to Microwave" 任务上,π0.7 (GC)(带生成 subgoal)显著优于不带的版本,后者甚至是成功的关键。
Q
Q33训练 π0.7 处理 subgoal images 时,real image 的采样方案?
点击查看答案 ▸
A
以 0.25 概率采 end-of-segment 图像(与 world model 预测目标一致);以 0.75 概率从当前时刻往后 0–4 秒内均匀采未来图像。
Q
Q34为什么训练时还要混入 world-model 生成的图像?
点击查看答案 ▸
A
缓解 real image 与 generated image 之间的 train-test mismatch。除 real future images 外,从 world model 采大量 subgoal images,构造额外训练样本(用生成图代替 real future image 放入 π0.7 的 context)。
Q
Q35World model 训练的输入输出和 backbone 细节(Appendix C)?
点击查看答案 ▸
A
从 BAGEL 初始化,基本沿用其训练配方。用带高质量 segmented language labels 的机器人数据 + egocentric human video(label 质量尤其是时间分割质量对 subgoal 质量影响大),并混入开源图像编辑/视频数据集以保留语义知识。每个样本含:subtask instruction ℓ̂、3 个相机输入 o_t、3 个目标图像 o_{t_end}。相机输入同时用 ViT(语义理解)+ VAE(细粒度细节) 处理:ViT tokens 经 7B LLM backbone,VAE tokens 经 7B 生成 backbone。ViT 输入 resize 到 448×336,VAE 输入 resize 到 512×384(因 patch size 不同,分别为 14 和 16)。测试时 Δ=4 秒重新生成 subgoal(与 SuSIE 对齐)。
06

训练数据与配方

Training Data
Q
Q36π0.7 的训练数据包含哪些来源?
点击查看答案 ▸
A
(1) 多平台演示数据(静态/移动、单臂/双臂,多样环境);(2) 大量 policy evaluation 的自主数据;(3) policy rollout 中的人类干预;(4) 开源机器人数据集;(5) egocentric human video;(6) web 来源的辅助非机器人数据(物体定位、属性预测、VQA、纯文本);(7) video-language 任务(视频 captioning)。
Q
Q37π0.7 在数据使用上"显著偏离经典 VLA 流程"的地方?
点击查看答案 ▸
A
大量使用 suboptimal robot data,包括低质量演示(失败 episode 或含大量错误的成功 episode)和旧模型在评估实验中收集的数据。例如用 π*₀.₆ 在 RL 训练中收集的数据作为额外样本,相当于把它们的行为 distill 进 π0.7。
Q
Q38这种"distillation"带来什么效果?
点击查看答案 ▸
A
把 metadata 加入 context 让模型能有效利用所有评估数据,达到与针对单任务做 RL 的专家模型相似的性能——即 generalist π0.7 继承 RL 专家的能力。suboptimal 数据还增加状态/场景多样性,带来更强 robustness,使 π0.7 在高难度灵巧任务上有时甚至超过 RL 训练或单任务后训练的策略。
Q
Q39训练数据上有什么重要的排除(exclusion)?
点击查看答案 ▸
A
排除任何 generalization-focused 评估任务(包括 Sec. IX 中的)里收集的自主数据,以保证泛化评估的公正性。
07

推理时 Prompting

Inference
Q
Q40运行时 episode metadata 怎么设置?
点击查看答案 ▸
A
  • Overall speed:按任务设为该任务 episode 长度的第 15 百分位(即偏快)。
  • Overall quality:永远设为 5(最高)。
  • Mistake:永远设为 false(无错误)。
Q
Q41subtask instruction ℓ̂_t 运行时从哪来?
点击查看答案 ▸
A
由学到的 high-level language policy 提供,或由人类监督者 coaching 提供。
Q
Q42subgoal images 运行时何时刷新?
点击查看答案 ▸
A
当语义意图改变(新 ℓ̂_t)或距上次生成已过 Δ=4 秒时,取先到者。
Q
Q43π0.7 的异步推理怎么运作?
点击查看答案 ▸
A
visual subgoal 生成和 subtask instruction 生成在独立线程进行;VLA 推理始终用当前可用的最新版本。world model 生成下一个 subgoal 时 π0.7 继续执行(naive async 策略)。
Q
Q44推理用多少 denoising 步?执行多少步 action?
点击查看答案 ▸
A
所有实验用 5 个 denoising 步生成 50 步 action chunk,执行其中 Ĥ ∈ {15, 25} 步。
Q
Q45π0.7 怎么用 CFG?为什么能用?
点击查看答案 ▸
A
因为每个 prompt 组件都用 dropout 训练,π0.7 可对任意 prompt 部分做 classifier-free guidance。每步 denoising 遵循:∇_a log π_θ(a|o,C) + β·( ∇_a log π_θ(a|o,C) − ∇_a log π_θ(a|o,C_uncond) )论文对 episode metadata 应用 CFG 以在灵巧任务上激发强性能,用中等 β ∈ {1.3, 1.7, 2.2}。
Q
Q46简述 Algorithm 1(测试时工作流)。
点击查看答案 ▸
A
输入初始观测 o₀、任务指令 ℓ、metadata m、control mode c。先初始化 subtask ℓ̂(来自 high-level policy 或 coaching),采初始 subgoal g* ~ p_ψ(·|o₀, ℓ̂, m),组成 C = {ℓ, ℓ̂, g*, m, c},采初始 action chunk(可选 CFG)。循环中:若 ℓ̂ 改变或 Δ 秒计时到 → 异步重采 subgoal 并更新 C;若距上次推理已过 Ĥ 步 → 异步(带 RTC)重采 action chunk;执行 a_t。
08

机器人系统

Hardware
Q
Q47π0.7 部署在哪些机器人平台?
点击查看答案 ▸
A
(1) 双臂移动 manipulator(2×6 DoF 臂 + 1 DoF 夹爪 + 1–2 DoF 升降 + 3 DoF holonomic base);(2) 静态双臂机器人("BiPi"),轻量 6 DoF 臂;(3) 双臂 UR5e + Robotiq 夹爪(用于跨本体实验);(4) 单臂 6 DoF(与 BiPi 同款臂)。全部 parallel-jaw 夹爪。
Q
Q48UR5e 为何是跨本体迁移的难点?
点击查看答案 ▸
A
大部分数据用类 BiPi 平台采集,而 UR5e 臂显著更长、形态不同、更重。实践中因臂的形状、相对桌面的位置(在两侧而非一边)、夹爪和手指形状,必须用不同的操作策略,使迁移到该平台成为重大挑战。
Q
Q49各平台运行频率和控制方式?

UR5e 跑 20Hz,其余跑 50Hz。每个机器人有前向相机 + 每臂 wrist 相机,移动机器人还有后向相机。π0.7 动作输出经简单 PD 控制器施加;末端执行器命令用数值逆运动学转成目标关节位置。

实验结果

Out-of-box · Memory · Language
Q
Q50开箱即用(out-of-the-box)灵巧性实验的核心结论?
点击查看答案 ▸
A
同一个通用 π0.7 模型无需任务特定后训练,就能在多种高难度任务上匹配任务特定微调的专家策略(π*₀.₆ RL 专家或 π0.6 SFT 专家),并在困难的洗衣叠衣和折盒任务上 throughput 甚至超过 RL 专家。
Q
Q51π0.7 (no eval data) 和 π0.7 (no metadata) 两个 ablation 说明了什么?
点击查看答案 ▸
A
  • π0.7 (no eval data):不用自主评估 episode → 无法 distill RL 等强策略的 rollout。
  • π0.7 (no metadata):不用 episode metadata。
π0.7 在所有任务上显著优于两者,throughput 上差距最明显。说明:在质量参差的评估数据上训练 + 用丰富 metadata 消解高低质量行为,对 π0.7 的强性能至关重要。
Q
Q52记忆相关任务的结果?
点击查看答案 ▸
A
π0.7 无需微调即可在需要显式追踪先前上下文的任务(Swap 3 Mugs、Find Object、Scoop Coffee、Window Cleaning)上,达到或超过 MEM 论文中针对部分任务做记忆微调的专家策略。
Q
Q53指令跟随实验的设置和结论?
点击查看答案 ▸
A
在 4 个未见厨房 + 2 个未见卧室上,每个测试跟随 3–6 步指令序列完成特定目标。π0.7 显著优于 π0.5 和 π0.6,整体指令跟随成功率高。
Q
Q54complex referential instructions 实验说明什么?
点击查看答案 ▸
A
故意设计不寻常、用非常规方式指物、或需理解空间关系的指令(如 "pick up an object I would use to eat soup")。标准指令各模型都行,但复杂指令上 π0.7 显著更好,且加 subgoal images(π0.7 GC)进一步提升——把 world model 的语义理解 import 进来。
Q
Q55"打破数据集偏置"实验是什么?结论?
点击查看答案 ▸
A
构造 Reverse Bussing(把垃圾放 bussing bin、餐具放垃圾桶,与训练相反)和 Reverse Fridge to Microwave(把食物从微波炉放回冰箱,训练里没采反向数据)。π0.7 显著优于前代,说明它语言跟随足够强、足够关注指令以打破数据偏置。其中后者上 π0.7 (GC) 是成功关键。

跨本体迁移

Cross-Embodiment
Q
Q56跨本体迁移实验想回答什么?主要发现?
点击查看答案 ▸
A
问:cross-embodiment transfer 是否是 π0.7 的 emergent property——能否直接把能力迁移到从未采集过任务数据的本体?发现:多个任务上 π0.7 完全开箱即用地在目标本体成功。形态差异较小时 π0.5/π0.6 也有一定 emergent transfer;但形态差距增大、需要显著改变策略时,π0.7 显著优于前代。
Q
Q57物体重排类跨本体任务的难度梯度?
点击查看答案 ▸
A
  • Table Setting:多种机器人采集 → 迁到静态双臂(最有利,所有模型都好)。
  • Bag In Backpack / Organize Tupperware:UR5e → 更小静态双臂(gap 更大,π0.5 显著退化,π0.6/π0.7 仍强)。
  • Shirt Bagging:小静态双臂 → 单臂 UR5e(gap 最大,需完全不同策略,π0.7 显著领先)。
Q
Q58"emergent strategy" 的两个具体例子?
点击查看答案 ▸
A
  • (a) 装袋:源机器人(矮的静态双臂)用一只手撑开袋子、另一只手插入;更高的 UR5e 因 reach 更大,π0.7 发现单臂 pick-and-place 策略。
  • (b) 叠衣:源机器人用倾斜末端执行器先把布按在桌上;UR5e 上 π0.7 改用更适合该臂运动学的竖直抓取。
两例都超越"复制源行为",发现更适合目标本体的策略。
Q
Q59叠衣的人类对照实验结论?意义?
点击查看答案 ▸
A
招募 10 名 top 2%(平均约 375 小时经验)的操作员,他们在 UR5e 上从未做过叠衣(对人和策略都是 zero-shot)。
  • 人类:task progress 90.9%、成功率 80.6%
  • π0.7:task progress 85.6%、成功率 80%,性能可比。
意义:灵巧技能可从轻便、低成本、易遥操作的平台,迁移到 high-payload 工业臂(后者采集人类演示昂贵且困难)。
Q
Q60跨本体实验为何用关节空间控制?
点击查看答案 ▸
A
因为发现末端执行器(EE)控制在前代模型上没有明显性能提升(Appendix E:跨任务比较 joint vs EE,无实质差异),为清晰起见主实验聚焦 joint-space 控制。

组合泛化与 Coaching

Compositional · Coaching
Q
Q61组合泛化为何被称为机器人基础模型的 "grand challenge"?
点击查看答案 ▸
A
此前模型已能在语义概念上泛化(如用未见文字标签去够物体),但执行全新任务一直难以实现。π0.7 展现出对训练中所见技能的组合泛化。
Q
Q62短 horizon 新任务的开箱即用能力?
点击查看答案 ▸
A
π0.7 可直接执行没采过专门数据的短 horizon 任务,如按法压壶柱塞、舀米入电饭煲、擦拭办公物品、旋转铰接物体(齿轮组、台扇)。π0.7 在直接语言条件(π0.7)和生成图像目标(π0.7 GC)下表现大致同样强。
Q
Q63长 horizon 新任务为什么不能直接 prompt?怎么解决?
点击查看答案 ▸
A
像"煮红薯"这类需多阶段、最长约 5 分钟交互的任务太复杂,直接要求做不出来。解决:用 π0.7 的语言跟随能力 "coach" 它——像教人一样逐步用语言指导(如 "pick up the sweet potato"、"open the air fryer")。设置 Loading/Unloading Air Fryer、Toasting a Bagel 三个多阶段厨房任务(机器人数据里没有这些任务的 episode)。π0.7 比前代更能被有效 coach,加生成 subgoal 时更好。
Q
Q64coaching 如何变成全自主能力?
点击查看答案 ▸
A
用 coaching 数据里的逐步指令训练一个 high-level language policy,让它在执行时自动用合适语言 prompt π0.7。这样无需额外遥操作数据即可获得全新长 horizon 任务的全自主能力。实验显示 π0.7 (autonomous) 大致匹配 π0.7 (coaching)(5 个任务)。

混合质量数据的可扩展性

Scaling · Mixed-Quality
Q
Q65"能否从混合质量数据学习"实验怎么做的?
点击查看答案 ▸
A
用 Laundry (T-Shirts and Shorts) 任务,按 fold 质量和速度标注,分 4 桶:top 30%、top 50%、top 80%、全部数据。每桶从头训 π0.7,分带/不带 metadata(共 8 个模型)。
Q
Q66该实验的关键结论?(对 fine-tune 尤其重要)
点击查看答案 ▸
A
π0.7 (without metadata) 在更大但更混杂的数据上反而变差;π0.7 (with metadata) 随数据增多持续改善,即使数据集增大伴随平均质量下降。说明 diverse prompting 让模型设计更可扩展——能从更大数据集获益,即使这些数据按常规方式训练会损害模型。metadata 在大规模数据中有效消解不同质量/策略,并在测试时可 prompt 期望行为模式。
Q
Q67任务多样性(task diversity)实验怎么做?结论?
点击查看答案 ▸
A
比较两个数据量相同的模型:
  • π0.7 (w/o most diverse 20%):去掉任务多样性最高的 20% 数据。
  • π0.7 (w/o random 20%):随机去掉 20%(数据量对照)。
结果:所有任务上 π0.7 和 π0.7 (w/o random 20%) 显著优于 π0.7 (w/o most diverse 20%),说明 π0.7 能有效吸收高任务多样性数据并转化为短 horizon 未见任务上的性能提升。

局限性与工程细节

Limitations · Systems
Q
Q68π0.7 的主要局限?
点击查看答案 ▸
A
  • zero-shot 泛化成功率仍低于 in-distribution(seen 任务常 >90%,unseen 任务或 unseen 任务-机器人组合在 60–80%)。
  • 在如此大且多样的数据上很难明确界定哪些任务真 "seen" 哪些 "unseen"——相关技能可能以不同 label 或作为执行其他任务的一部分隐含存在;类似理解 LLM 泛化的难题,模型可能主要靠 "remixing" 已有技能。论文认为这恰是组合泛化的本质。
Q
Q69未来工作方向?
点击查看答案 ▸
A
利用 π0.7 的高 steerability,从测试任务的数据中高效学习——例如更详细的语言 coaching,甚至自主强化学习。
Q
Q70π0.7 主模型和 world model 的推理速度/优化(Appendix D)?
点击查看答案 ▸
A
  • π0.7 + high-level policy:都基于 Gemma3 4B,单张 H100 推理。RTC 后多种优化把最小变体降到 38ms(3 相机、5 denoising、training-time RTC,无额外推理开销)。启用 MEM vision encoder + 加 subgoal images 后最坏 127ms。
  • World model:14B、序列近 10,000 token;用 4×H100 的 4-way tensor parallelism、8-bit 量化、改版 SageAttention,做到 25 denoising 步(含 text+image CFG)1.25 秒。推理时用 async 策略,π0.7 在 world model 生成下个 subgoal 时继续执行。

给 fine-tune π0.5 的实用借鉴

★ For Your Project
Q
Q71哪些点能直接搬到你自己的双臂 fine-tune 项目里?
点击查看答案 ▸
A
  • ① 别丢失败/低质量数据:用 quality(1–5) / speed / mistake 标注后混入训练,测试时 prompt quality 5 / mistake false 即可拿到好行为。对"用次优 bin-picking 软块数据喂 π0.5"高度契合——不必只留完美演示。
  • ② speed 目标 = episode 长度第 15 百分位:简单可复现,直接套用即可让策略偏快。
  • ③ metadata dropout 配方:训练时各分量单独 dropout(5%)+ 整体 dropout(15%),保证测试时即使缺省也能跑。
  • ④ world model / subgoal images 可后置:它对复杂 referential 指令和跨本体最有用;短 horizon 任务上"纯语言"已接近同等表现。资源有限时先把 metadata + 更细的 subtask 语言跑通。
  • ⑤ 多视角 subgoal 分工:base view 管环境/物体中心结果,wrist view 管手臂/夹爪结果——对你多相机 visual servoing 的视角分配思路有参考价值。
  • ⑥ 架构层面:π0.7 把 proprioception 从"离散 text token"(π0.6)改成"linear projection embed"(MEM 风格),且 history state 做 token 级 mask;复现 history 机制时可注意。
