DAgger：让机器人去它自己会走到的地方学

行为克隆（BC）只学专家走过的路。机器人一走偏，就到了训练里没见过的地方，然后越错越远。DAgger 的办法：让当前策略自己去跑，在它跑到的状态上要专家给出正确动作，把这些数据并进训练集，再重训。重复几轮，训练数据就越来越像策略真正会遇到的情况。

01问题：行为克隆为什么越错越远

BC 把模仿学习当成普通的监督学习：拿专家轨迹里的 (状态, 动作) 对训练一个分类/回归器。问题在于训练和测试的状态分布不一样。

训练时，输入全是专家走到的状态。测试时，输入是策略自己走到的状态。策略在第 t 步犯一点小错，第 t+1 步的状态就偏离了专家分布。在这个陌生状态上它更容易错，错误一路累积。论文把这个结论写成：BC 每步错误率是 ε 时，T 步任务的总代价最多比专家多 T²ε。

Q1 答训练只见过专家走到的状态，上真机时输入是策略自己走到的状态。一步小错把它带到没见过的地方，在那里更容易错，错误一路叠加，代价按 T² 增长。
行为克隆 BCDAgger
训练状态来自专家自己的轨迹当前策略（或专家与策略的混合）跑出来的轨迹
动作标签来自专家专家（在策略访问到的状态上补标）
数据集一次采完每轮新增 Dᵢ，并入总集 D
误差上界T²εuTεN + O(1)（线性）

02论文里的算法

论文第 3 节给出的 DAgger（Dataset Aggregation）伪代码，逐行如下：

Initialize D ← ∅
Initialize π̂₁ 为策略类 Π 里任意一个策略
for i = 1 to N do
    πᵢ = βᵢ·π* + (1 − βᵢ)·π̂ᵢ          # ① 混合策略：以 βᵢ 的概率让专家执行
    用 πᵢ 采样若干条 T 步轨迹            # ② 数据采集：跑出“会被访问到”的状态
    Dᵢ = {(s, π*(s))}                    # ③ 在这些状态上要专家给动作标签
    D ← D ∪ Dᵢ                           # ④ 聚合：新旧数据全部保留
    在 D 上训练分类器 π̂ᵢ₊₁                # ⑤ 模型迭代：在全部数据上重训
end for
return 在验证集上最好的 π̂ᵢ             # ⑥ 不一定是最后一轮
行做什么要点
① β 混合每一步以概率 βᵢ 执行专家动作，否则执行学习器动作β₁ = 1 时第一轮就是纯 BC。常用 βᵢ = pi−1 逐轮衰减；论文也提到只在第一轮用专家（βᵢ = 𝟙[i=1]）实际效果就不错
② 采样让 πᵢ 真实地跑这一步决定了“在哪里收数据”：在策略自己会到的状态
③ 专家标注不管谁在执行，所有访问到的状态都问专家“这里该怎么做”专家只给标签，不一定在开车。这一点对真人很难，见第 03 节
④ 聚合D 只增不删这就是名字里的 Aggregation。它对应在线学习里的 Follow-the-Leader，是一种无悔（no-regret）算法
⑤ 训练在累积的 D 上训练论文的理论保证来自“在所有历史数据上训练”，而不是只用最新一批
⑥ 返回挑验证表现最好的一版理论只保证序列里存在一个好策略

为什么能从 T² 降到 T

关键是 ③：训练数据来自策略自己诱导的状态分布。这样训练误差 εN 衡量的就是“策略在自己会遇到的状态上犯错的概率”，测试时不再有分布错位。论文证明迭代 N = Õ(uT) 轮后，存在一个 π̂ᵢ 满足 J(π̂) ≤ J(π*) + uTεN + O(1)，其中 u 是“犯一次错最多多付出多少代价”。论文用 Super Tux Kart（看图转方向）、Super Mario Bros 和手写识别（结构化预测）做了实验。

Q2 答在当前策略（混合策略 πᵢ）自己跑到的状态上收数据，动作标签由专家给（第 ③ 行 Dᵢ = {(s, π*(s))}）。数据位置跟着策略走，标签跟着专家走。
Q3 答β 是“每一步让专家执行”的概率：β₁ = 1 时第一轮就是 BC，之后逐轮变小，让策略越来越多地自己开。LeRobot 没有这个参数，换成了人按键接管，接管多频繁就相当于 β 多大（见 3.5 表格）。

03数据采集方式

3.1 论文：专家给每个访问到的状态打标签

执行者是混合策略 πᵢ，标注者是专家 π*。在游戏和仿真里，专家可以是一个规划器或人类玩家，它能对任意状态即时给出动作。所以策略开车、专家在旁边“同步报答案”是可行的。

真机上这件事很难。人看着机器人自己动，很难同时用遥操作臂报出每一帧的正确动作，因为人的手和机器人的状态没有连在一起。所以机器人领域通常改成“人觉得要出事了就接管”的做法：HG-DAgger（Kelly 等，2019）。LeRobot 再加上 RaC（Hu 等，2025）的规矩：接管后先恢复（把机器人带回好状态），再纠正（示范正确做法）。

Q4 答论文要专家在策略开车时给每一帧报动作，真人用遥操作臂做不到，因为手和机器人状态不同步。LeRobot 改成 HG-DAgger / RaC：平时策略开，快出错时人按键接管，先把机器人带回好状态再示范，只有接管段带标签。

04模型迭代方式

LeRobot 没有把“采集 → 训练 → 再采集”写成一个自动循环。每一轮是几条命令，人来串起来。官方文档的流程（Step 1:83Step 2:96Step 3:186）对应到论文的 for 循环：

  --output_dir=outputs/pretrain

Q5 答每轮：部署当前策略 → 采纠正数据 Dᵢ → 和之前所有数据合并成 D → 在 D 上训练（LeRobot 从上一轮权重接着微调）。合并是因为论文的理论保证来自在全部累积数据上训练；只用新数据会忘掉 D₀ 里的正常操作。

几个容易踩的坑

1. 别只用新数据训。论文的保证来自在全部累积数据上训练。只用 Dᵢ 微调，模型会忘掉 D₀ 里的正常操作。文档 Step 3 的示例命令只写了 hil-dataset，但正文要求先合并，以合并后的数据集为准。

2. intervention 列训练时没被用到。lerobot-train 和策略代码都不读这个列，所有帧一视同仁地做 BC。用 record_autonomous=True 时，接管前那几秒“策略正在犯错”的帧也会被当成正确示范。要么用默认的只记纠正模式，要么自己按 intervention 过滤或加权。

3. 从上一轮接着训 vs 从头训。论文每轮在 D 上重新训练。微调更省算力，但几轮后可能偏向最近的数据。轮数多了可以隔几轮从 D 上整体重训一次。

4. 纠正段要干净。纠正动作就是标签。犹豫、抖动都会被学进去。

04+几个容易混淆的地方

读公式、上真机时，最容易在下面这几处想岔。

① 公式里的符号

符号读法意思在机器人里是
π派策略：看到状态，给出动作控制机械臂的“大脑”
π*派星专家策略，星号表示“标准答案”人遥操作
π̂ᵢ派帽 i学到的策略，帽子表示“从数据里估出来的”第 i 轮训出的模型
πᵢ派 i两者按 β 混合后的策略第 i 轮采数据时真正在开的
a | sa 给定 s在状态 s 下选动作 a 的概率s 是相机图和关节角，a 是下一步动作

专家每轮都一样，所以 π* 没有下标。模型每轮重训，所以 π̂ 带下标 i。

“混合策略”是有好几个策略吗？

不是。只有两个：一个专家 π*，一个模型 π̂ᵢ。专家也只有一个，不是好几套规则。“混合”就是每一步抛硬币选一个来开：概率 βᵢ 让专家开，概率 1−βᵢ 让模型开。混合策略 πᵢ 不是第三个策略，只是“这一步让谁开”的规矩。

论文实验专家是谁
Super Tux Kart 赛车人用手柄
Super Mario能看到游戏内部的规划程序
手写识别正确答案

② 公式里的加法，加的是概率，不是动作

πᵢ(a|s) = βᵢ·π*(a|s) + (1 − βᵢ)·π̂ᵢ(a|s)
读法写出来对不对
加概率（混合分布）上面这行✅ 论文的意思
加动作（取平均）a = β·a* + (1 − β)·â❌

例子：β = 0.5，专家要往左，模型要往右。加概率：50% 往左，50% 往右，每一步只走一边。加动作：左右平均成“直走”，两边都没选，可能直接撞上。

所以 β = 0.5 的意思是：每走一步抛一次硬币，正面执行专家的动作，反面执行模型的动作。这里不是两个专家，是一个专家加一个正在学的模型。不管这一步谁在开，标签永远记专家的动作。

③ β 怎么取：每轮都变

取法公式各轮的 β
逐轮变小βᵢ = pi−1p = 0.5 时：1, 0.5, 0.25, …
只用一轮专家βᵢ = 𝟙[i=1]1, 0, 0, …（不用调 p，论文说实际效果常常很好）

论文没有固定的默认值。理论只要求 β 的平均值随轮数趋近 0。

Q6 答不会不变。β = 0 只表示采数据时由模型自己开。专家照样给每个走到的状态打标签，数据合并后每轮重训，所以 π̂ᵢ 每轮都在变。β 只管“谁来开”，不管“学不学”。β = 0 收到的全是模型自己会走到的状态，反而最有用。

④ 真机上：只有人接管的那段有标签

场景专家是谁能不能给每一步打标签
论文的游戏实验程序或玩手柄的人能：模型在开，专家同时给动作，只记录不执行
真机遥操作的人不能：人不动手，机械臂不会照他走，他没法边看边给
片段谁在开有没有标签
模型自己开模型没有
人接管人有，人的动作就是标签

接管段里每一帧都是训练样本，不只接管那一帧。训练时每帧往后取一段人的动作，凑成动作块（π0 / π0.5 默认 50 步）。接管段越长，样本越多。

⑤ 真机 DAgger 是不是效率太低

普通遥操作示教接管段
起点人摆好的干净状态模型自己走歪的状态
教的是正常怎么做歪了怎么救回来
模型缺不缺已经有很多正好缺这个

接管段确实是人造的，但标签本来就该人给。值钱的是起点：这种“歪掉的状态”，人自己示教时几乎走不到。模型自己开时，人只是看着不用动手，比全程遥操作省力得多。

模型自己开的那段怎么用
整条做成了当好数据留下
接管前的几帧按 intervention 筛掉（见上面坑 2）
成功和失败都有可以做强化学习，例如 π*0.6 的 RECAP 就用了模型自己跑的数据

真正低效的情况：模型太差，几步就要接管。这时先多采普通示教，等成功率到一半左右再开始 DAgger。

⑥ 进阶做法：人给终点，规则补标签

思路：出错时人把末端遥操作到正确的终点。接管前走过的状态都记下来了，终点也知道了，就能用规则（规划器）算出每个状态该怎么走。这就和仿真里“专家给每一步打标签”很像了。

纯人接管（HG-DAgger）人给终点 + 规则补标签
人做什么遥操作整段只把末端拉到终点
哪些帧有标签只有接管段走过的每一帧都能补
模型自己开的那段用不上重新打标签，能用上
标签质量人手会抖、不一致平滑、一致

要小心

1. 接触动作规则写不好。空中移动好写，夹取、放下、插入要看力和时机。

2. 两种风格会打架。规则走直线、匀速，人示教有弯有快慢。同一状态两种答案，模型会学成中间值。让一种风格占主导，或初始示教也用规则生成。

3. 终点会变。物体每次位置不同，每条都要重新给终点，或用检测给。

4. 想想还要不要学。如果规则拿到终点就能做好，用“检测 + 规划器”可能比端到端学习更简单。

阶段谁给标签
空中靠近、移开规则
给出终点人遥操作一下，或检测
夹取、放下这类接触人遥操作

一句话：移动交给规则，接触留给人。

⑦ 每轮从预训练权重重训，还是接着上一轮微调

论文每轮从头训，LeRobot 文档是接着上一轮微调。两种都要用合并后的全部数据。“从头”指从预训练权重（如 pi05_base）开始，不是随机初始化。

从预训练权重重训接着上一轮微调
速度慢，数据越多越慢快，几千步就够
旧数据每轮只看几遍越看越多遍，容易背答案
结果稳不稳稳，每轮可比偏差会一轮轮累积
学习率正常热身、衰减要调小，再热身一次
和论文理论一致不完全一致

建议混着用：中间轮接着微调；每隔几轮或最后一轮，从预训练权重重训一次当正式版本。最后用真机成功率挑。接管段只占数据一小部分，训练时可以多抽几次，让模型多看“歪了怎么救”。

⑧ DAgger、HG-DAgger、RaC 有什么区别

后两篇都是在 DAgger 上改的，方向一样：让真人当专家时也能用。

DAgger（2011）HG-DAgger（2019）RaC（2025）
作者Ross 等Kelly 等Hu 等
场景游戏、仿真真车自动驾驶真机长任务（如叠衣服）
谁决定专家上场β 抛硬币人觉得要出事就接管同 HG-DAgger
哪些帧有标签走过的每一帧只有接管段只有接管段
接管后怎么做—直接纠正先恢复到好状态，再纠正
解决的问题BC 越错越远真人没法边看边打标签长任务里纠正数据不够干净、不够多
DAgger：专家给每一步打标签（真人做不到）
  → HG-DAgger：人按需接管，只标接管段（真人能做了）
    → RaC：接管后先救回来，再示范怎么做（数据更好用）

RaC 要先恢复，是因为只纠正不恢复，模型学不会“从错误里退出来”。LeRobot 把两者合在一起：HG-DAgger 的按键接管，加 RaC 的“先恢复再纠正”（见 3.1）。同一家族还有 SafeDAgger、EnsembleDAgger 等，它们让模型自己判断何时该叫人。

07读完做几道题

先自己想，再点开看答案。

  1. 取 β₁ = 1，之后 βᵢ = 0。第一轮 DAgger 等价于什么？

    看答案
    等价于纯行为克隆：第一轮完全由专家执行，收到的就是专家示教。从第二轮起才是策略自己跑。见 第 02 节 表格第 ① 行。

  2. 论文为什么返回“验证集上最好的 π̂ᵢ”，而不是最后一轮的策略？

    看答案
    理论只保证 N 轮里存在一个足够好的策略，没保证最后一个最好。真机上对应的是：每轮都测成功率，留最高的那版。

  3. 默认的只记纠正模式下，一个 episode 从哪里开始，到哪里结束？

    看答案
    按 tab 从 PAUSED 进入 CORRECTING 开始记，再按 tab 回到 PAUSED 时调用 save_episode() 结束。策略自己开的时候不记帧。dagger.py:585

  4. 纠正段里写进数据集的动作标签，是人的遥操作动作，还是发给机器人的动作？

    看答案
    人的遥操作动作 processed_teleop（经过 teleop_action_processor）。发给机器人的是再经过 robot_action_processor 的 robot_action_to_send，它不进数据集。dagger.py:430

  5. 开了 record_autonomous=true，再直接拿全部帧训练，会有什么问题？

    看答案
    人接管前那几秒，策略正在犯错，这些帧标着 intervention=False 也被记下来了。训练代码不读 intervention 列，会把错误动作当成正确示范学。要过滤或加权，或者用只记纠正模式。见 第 04 节 坑 2。

  6. 主臂能被电机驱动（如 SO-101）和不能被驱动时，交接有什么不同？

    看答案
    能驱动：AUTONOMOUS → PAUSED 时，把主臂慢慢移到从臂位置，人接手不跳。不能驱动：PAUSED → CORRECTING 时，反过来把从臂慢慢移到主臂姿态。dagger.py:716dagger.py:729

  7. 按键线程为什么不直接改状态，而要先 request_transition，再由主循环 consume_transition？

    看答案
    两个原因：一是只登记合法切换，非法按键直接忽略；二是状态只在主循环每帧开头改，不会在一帧处理到一半时被别的线程改掉。dagger.py:134

  8. β = 0.5 时，专家要往左、模型要往右。这一步机械臂会往哪走？标签记谁的？

    看答案
    抛硬币：一半概率往左（专家），一半概率往右（模型），不会平均成“直走”。公式加的是选动作的概率，不是动作本身。不管谁在开，标签都记专家的“往左”。见 04+ 第 ② 条。
