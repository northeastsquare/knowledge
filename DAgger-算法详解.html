DAgger：让学生自己开车，请专家给它走到的每个状态打标签

普通行为克隆只在专家走过的状态上学习。学生一旦犯错，就会进入训练集中没有的状态，错误随之累积。DAgger 的做法是：让当前策略去环境里跑，让专家标注这些状态下的正确动作，把新数据并入旧数据，再在全部数据上重新训练。重复 N 轮后，训练数据的分布就接近学生自己执行时会遇到的分布。

01 · PROBLEM要解决的问题：训练分布和执行分布不一致

记任务时域为 T，专家策略为 π*，学生策略为 π，dπ 表示执行 π 时 T 步内状态的平均分布。模仿学习真正想要的是让学生在它自己会遇到的状态上和专家一致：

π̂ = argminπ∈Π Es∼dπ[ ℓ(s, π) ]（论文式 1）

难点在于 dπ 依赖 π 本身。普通监督学习（论文称 supervised approach，即行为克隆）退而求其次，只在专家分布上拟合：

π̂sup = argminπ∈Π Es∼dπ*[ ℓ(s, π) ]（论文式 2）

定理 2.1 给出它的代价：如果在专家分布上的错误率是 ε，执行时的总代价最多比专家多 T²ε，而且这个界是紧的。原因是学生一步走错，就会进入专家从没去过的状态，那里没有训练数据，后面更容易继续错。ACT 用动作分块减少决策次数来缓解这个问题，DAgger 的办法是直接去收集这些状态的数据。

方法（论文第 2 节）训练出的策略误差界问题
Supervised / BC平稳、确定T²ε不会从错误中恢复
Forward Training非平稳：每个时刻 t 一个 πtuTε要训 T 个策略，T 大或不确定时不可行
SMILe（类似 SEARN）平稳、随机：多个策略的混合近线性混合里有差策略，执行不稳定；需要 O(T² log T) 轮
DAgger平稳、确定uTεN + O(1)每一步都要专家给标签

02 · ALGORITHM 3.1算法 3.1 逐行读

1Initialize D ← ∅空数据集
2Initialize π̂1 to any policy in Π因为通常取 β1=1，第一轮用不到 π̂1，随便初始化即可
3for i = 1 to N do一共 N 轮
4Let πi = βiπ* + (1−βi)π̂i谁来开车：专家和学生的混合策略
5Sample T-step trajectories using πi去哪些状态：由混合策略决定
6Get dataset Di = {(s, π*(s))} of visited states by πi and actions given by expert标签是谁的：永远是专家的，和实际执行了谁的动作无关
7Aggregate datasets: D ← D ∪ Di数据怎么管：只追加，不丢旧数据
8Train classifier π̂i+1 on D模型怎么更新：在全部数据上做普通监督学习
9end for
10Return best π̂i on validation在验证集上选最好的一个，不一定是最后一轮的策略

第 4～6 行属于数据采集，第 7～8 行属于模型迭代。下一节的架构图把这两段和代码里的类、函数一一对上。

imitation 里一步是怎么走的

SimpleDAggerTrainer.train 调用通用的 generate_trajectories，传入的“策略”是专家，“环境”是包了一层的 InteractiveTrajectoryCollector。于是每一步都会先问专家，再由包装器决定实际执行谁的动作：

    policy=self.expert_policy, venv=collector, ... , deterministic_policy=True)

# dagger.py L254–262：InteractiveTrajectoryCollector.step_async(actions)
# actions 是专家刚给出的动作 a*
actual_acts = np.array(actions)
mask = self.rng.uniform(0, 1, size=(self.num_envs,)) > self.beta   # 每个环境各掷一次
if np.sum(mask) != 0:

# dagger.py L274–285：step_wait 把 (obs, 专家动作) 写进轨迹，episode 结束就落盘

关键点：环境里走的是 actual_acts，数据集里存的是 actions（专家动作）。只要 βi < 1，数据里就会出现学生犯错后才会到达的状态，而这些状态上的标签是专家给出的纠正动作。行为克隆缺的正是这部分数据。

05 · MODEL ITERATION模型迭代方式：在全部数据上重训，然后换掉学生

每轮采完数据，DAgger 做三件事：把 Di 并进 D；在整个 D 上做一次普通监督学习得到 π̂i+1；下一轮用 π̂i+1 当学生。训练本身和行为克隆完全一样，变的只是训练数据。

为什么是“聚合”，不是“替换”

论文把 DAgger 解释成在线学习里的 Follow-The-Leader：第 i 轮给出一个损失 ℓi(π) = Es∼dπi[ℓ(s,π)]，下一轮选“对至今所有损失之和最好”的策略，也就是在全部历史数据上训练。如果每轮只用最新数据，新策略只会修正上一个策略的错误，可能把以前学会的又忘掉，在几个策略之间来回摆动。Mario 实验里 SEARN 取 α=1（每轮完全换成新策略）就表现出这种不稳定。

imitation 里一轮训练怎么走

BC 的损失在 bc.py L94–156：loss = neglogp + ent_loss + l2_loss，即专家动作的负对数似然，减去 ent_weight（默认 1e-3）乘熵，加上 l2_weight（默认 0）乘参数 L2。优化器默认 Adam，batch 32，策略默认是两层 32 单元的 FeedForward32Policy。

warm start 和从头训：论文写的是 “Train classifier π̂i+1 on D”，实验用的是岭回归和线性 SVM 这类凸模型，每轮重新求解和接着训的结果基本一致。imitation 在同一个网络、同一个优化器上继续训 4 个 epoch，实现 B 也是对同一个 Keras 模型反复 fit。用神经网络时两种做法结果可能不同；数据增长后每轮训练时间与 |D| 成正比。

06 · THEORY为什么有效：把模仿学习归约成无悔在线学习

  1. 无悔（no-regret）：在线学习算法每轮选一个策略、承受一个损失。如果它的平均损失和“事后看最好的固定策略”之差 γN 随 N 趋于 0，就叫无悔。损失强凸时 Follow-The-Leader 满足 γN = Õ(1/N)。
  2. 混入专家的代价（引理 4.1）：‖dπi − dπ̂i‖1 ≤ 2Tβi。βi 越小，采集时的状态分布越接近学生单独执行时的分布。
  3. 定理 3.1：取 N = Õ(T) 轮，序列 π̂1:N 里存在一个策略，在它自己的状态分布上的损失不超过 εN + O(1/T)。εN 是策略类 Π 里最好的策略在聚合分布上的损失。
  4. 定理 3.2：再结合定理 2.2，得到 J(π̂) ≤ J(π*) + uTεN + O(1)。u 是“偏离专家一步后剩余代价最多增加多少”；如果专家能在几步内把局面拉回来，u = O(1)，误差就随 T 线性增长。
  5. 有限样本（定理 3.3）：每轮 m = O(1) 条轨迹、N = O(T² log(1/δ)) 轮，以概率 1−δ 得到同样形式的界。
保证说的是“序列里存在一个好策略”（论文脚注 3 补充：从序列里均匀随机挑一个执行也满足），并没有保证最后一轮最好。这就是算法第 10 行要在验证集上挑选的原因。另外，如果策略类表达不了聚合数据里的专家行为，εN 本身就大，界也就失去意义。

09 · PITFALLS实践中的坑

  • 专家必须能标注任意状态。规划器、脚本或仿真里的特权策略最容易满足（Mario 实验和实现 B 都是这种）。真人很难给“不是自己在开”的画面打准确的标签，所以后来出现了 HG-DAgger 这类由人决定何时接管的变体。π0.6 的 RECAP 也把人工纠错数据并入全部数据重新训练，思路相近。
  • 标签要和状态对齐。实现 B 第 0 轮（L33–44）先根据当前观测算动作，执行后才把下一帧图像和这个动作配对存下，差了一步；第一步还固定给 0。后面几轮是先记观测再按同一观测补标签，是对齐的。imitation 用 flatten_trajectories 把 obs[:-1] 和 acts 配对，没有这个问题。
  • 采集时学生是随机策略。imitation 采集时对学生动作采样，评估时常用确定性动作，两者访问的状态分布不完全一样。需要的话可以把 get_robot_acts 换成 predict(obs, deterministic=True)。
  • 注释和代码不一致。SimpleDAggerTrainer.__init__ 的注释说注入学生动作时“所有环境同时得到 robot action”，但 step_async 实际是逐环境掷硬币。以代码为准。
  • 数据只增不减。早期差策略产生的状态会一直留在 D 里，每轮训练时间也随 |D| 增长。论文的 Mario 实验说明，适当的 β 可以减少无用的早期数据。
