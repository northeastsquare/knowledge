RoboTrack：给机器人视频里的“点”出考卷、印练习册

外号 · 「出考卷，印练习册」考卷是人标的真机视频，练习册是仿真算出来的点轨迹

点跟踪（point tracking）：在第一帧点一个位置，模型要说出这个点在后面每一帧的坐标，以及这一帧能不能看见它。现有模型在机器人视频上分数偏高，是因为老考卷太简单。RoboTrack 做了两件事：一份更难的真机考卷 RoboTrack-Bench，和一本仿真生成的练习册 RoboTrack-15M。模型结构不改，只把练习册掺进训练数据，就能在真机视频上涨分。

01点跟踪：给一个点，跟到底

小例子 · 4 帧

第 0 帧，你在杯把上点了一下，坐标 (100, 200)。模型要交回一张表：

帧0123
坐标 (x, y)100, 200104, 198108, 196112, 195
看得见？110（被夹爪挡住）1

第 2 帧看不见，坐标也要给：那是“如果没被挡，它应该在哪”。第 3 帧它重新露出来，模型要认出是同一个点。

打个比方：在杯子上贴一张看不见的小贴纸。点跟踪就是每一帧都回答两件事：贴纸在哪，贴纸露不露脸。

代码里一段视频有 T 帧、N 个点，答案就是两个数组。RoboTrack-Bench 的每个片段文件夹里放 video.mp4 和 point_tracks.npz：

trajs_2d [T, N, 2]每帧每个点的像素坐标 x、y visibility [T, N]1 = 看得见，0 = 被挡住或出画 query_frames [N]每个点第一次看得见的帧，就从这里开始问

bench.py:1load_clip:72 读片段时，只在不到 2 帧可见的点会被丢掉，因为查询帧之后没东西可评（bench.py:87）。

Q1 答每个点每帧给两样：像素坐标 (x, y) 和“看得见”的概率。看不见时坐标照样要给（估计它被挡住时在哪），可见性写 0。评测时可见概率 = visibility × confidence，≥ 0.6 算“看得见”（evaluate.py:13）。

机器人为什么要它：点轨迹是一种很省的“物体怎么动”的表示。可以拿来从示教视频里学、给策略当输入，或者像本文的移液实验一样，直接用来对齐目标位置（见 第 07 节）。

怎么标

  1. 挑点：机器人视频里大部分像素是静止背景。标注员优先挑会动或会被挡住的点。
  2. 描轨迹：按 TAP-Vid 的做法，用运动估计辅助标注员一帧帧描。
  3. 打类别：每条轨迹标成三类之一：机器人或人的身体、被操作的物体、静止物体。
  4. 复核：另一组标注员逐帧检查每条轨迹，合格才收进来。
  5. 多视角：其中 33 对视频由两个相机同时拍。两个视角里标的是同一批物理点，帧也对齐。

来源：官方博客 · RoboTrack-Bench 一节。内容为转述。

老考卷为什么不够

论文拿四个跟踪器在五个基准上比。结论是老基准给的分偏高，而且排名会变：

现象数字
同一模型，RoboTAP → RoboTrack-Bench每个模型都掉 3.0–6.6 AJ。最强的 CoWTracker：70.5 → 63.9
仿真基准奖励“仿真训练”BootsTAPNext 比 TAPNext 多训了 1500 万条真实视频：RoboTrack-Bench 55.1 → 60.2（+5.1），RGB-Stacking 却 75.0 → 65.5（−9.5）
领先幅度缩水CoWTracker 领先 CoTracker3：RoboTAP 上 4.7，这里只有 2.1。AllTracker 领先 CoTracker3：2.7 → 0.8
DAVIS 冠军不灵了BootsTAPNext 在 DAVIS 最强，这里落后 CoWTracker 3.7，还输给只用 Kubric 训的 AllTracker（60.2 vs 61.4）
Q2 答两个原因。考卷变难了：杂乱背景、小物体、夹爪挡住手里的东西、第一和第三人称都有。训练数据不对路：主流模型靠 Kubric 训，Kubric 是“物体被扔进场景”，很少有机械臂抓着东西移动的画面。所以 RoboTAP 上 70.5 的 CoWTracker，到这里只有 63.9。

顺手修掉的评测 bug

README 指出：AllTracker 原版的稀疏评测里，如果一个片段的点不是按查询帧顺序存的，查询会和错误的点配对，分数会虚高或虚低。DAVIS 和本基准都受影响。本仓库按点的下标取查询：query_frames = clip.visible.argmax(0)，再用 np.arange(N) 逐点取坐标，顺序就不会乱。论文里的数字都用修正后的评测。

03怎么打分：AJ、δ、OA

小例子 · 1 个点，查询帧之后 5 帧

真值：前 4 帧看得见，第 5 帧被挡。模型每帧都说“看得见”。4 个可见帧的位置误差（已缩放到 256×256 画面）是 0.5、3、10、20 像素。

阈值 δ（像素）124816

FP：说可见但不对（太远或其实被挡）3+13+12+12+11+1
Jaccard = TP / (4 + FP)0.1250.1250.2860.2860.500
位置准确率 = 够近数 / 40.250.250.500.500.75

AJ = 五个 Jaccard 的平均 = 0.264。<δavg = 五个位置准确率的平均 = 0.45。OA：5 帧里可见性说对 4 帧 = 0.8。

如果模型在第 5 帧老实说“看不见”，每个 δ 的 FP 都少 1，AJ 升到 0.310（1/7、1/7、2/6、2/6、3/5 的平均）。

打个比方：考试按“答对且敢答”给分。答错了扣分，题不存在你还硬答（点被挡住却说看得见）也扣分。不会就说“看不见”，比瞎猜强。

每个片段算一组分，再对 307 个片段求平均，不是对所有点混在一起平均（evaluate.py:63）。所以短片段和长片段权重一样。

Q3 答对每个阈值 δ 算 Jaccard = TP / (真值可见帧数 + FP)，五个阈值再平均。点被挡住时你还说“看得见”，这一帧就算进 FP，分母变大，分数下降。所以 AJ 同时考位置和可见性，比只看位置的 <δavg 更严。

核心想法：把点“钉”在刚体上

小例子 · 一个点的一生

假设焦距 f = 300，画面 624×352，中心 (312, 176)。

  1. 第 20 帧，分割图说像素 (400, 180) 落在杯子上，深度图说它离相机 0.8 m。
  2. 反投影到相机坐标：x = (400−312)/300×0.8 = 0.235，y = (180−176)/300×0.8 = 0.011，z = 0.8。
  3. 再换到世界坐标，然后换到杯子自己的坐标系里存下。之后杯子怎么动，这个点在杯子上的位置都不变。
  4. 第 40 帧，杯子被抓着往相机右边平移了 5 cm。用杯子新位姿把点搬回世界，再投影：u = 300×0.285/0.8 + 312 ≈ 419，v ≈ 180。
  5. 查深度：渲染深度图在 (419, 180) 是 0.80 m，点自己也是 0.80 m。差 0 < 0.03 m，看得见。
  6. 如果夹爪挡在前面，渲染深度是 0.55 m。点在它后面 0.25 m ≥ 0.03 m，看不见。

打个比方：给杯子纹一个小点。仿真器每一帧都知道杯子在哪、朝哪。纹身跟着杯子走，所以随时能算出它在画面里的位置。再拿深度图看一眼它前面有没有东西挡着。全程不用人标。

代码里的流程

RoboTrack 没改 MolmoSpaces 一行代码。datagen/molmospaces_ext.py 从外面挂上去：注册一个任务配置，换一个 rollout 运行器，再换掉保存函数。

  1. 任务配置 RoboTrack15MPickConfig。继承 MolmoSpaces 的 PickBaseConfig：Franka 抓取、ProcTHOR-10k 训练集房子、DROID 风格的两相机、只留成功轨迹。点跟踪参数也在这里：5000 点 / 相机、每 20 帧采一次候选、不给底座两节连杆打点、遮挡容差 3 cm。
    config:37点参数:50
  2. 包住 reset 和 step_chunk。RoboTrackRunner 让任务每走一步就调一次 _Recorder.record()：存下所有刚体的位姿，以及每个相机的深度图和相机矩阵。

05什么样的仿真数据才有用

RoboTrack-15M 改了好几版。第一版在考卷上一分没涨。作者看了一个简单的统计：跟踪点在视频里移动了多远，画成直方图，和 RoboTrack-Bench 的直方图比距离。

版本点采在哪直方图看到什么结果
v1画面任何地方，含墙、地板、家具第三人称相机固定，大部分点根本不动没涨分
v2只在机器人和被操作的物体上手腕视角接近真机视频涨分
v3（发布版）再把底座和安装台上的点挪到会动的机械臂上第三人称视角也接近真机视频消融 63.0 AJ，比只用 Kubric 的对照高 1.5

顺带发现：Kubric 在手腕视角上也有同样的偏差。这大概解释了为什么只用 Kubric 应付不了机器人操作里多变的视角。

v2 对应代码里的 trackable_body_ids（机器人 + 自由物体），v3 对应 --exclude-robot-links base fr3_link0 和第 04 节第 4 步的换点逻辑。

Q5 答第一版到处采点，固定相机拍到的大多是不动的墙和地板，点几乎不移动，和真机视频的运动分布差太远。第一处修改：只在机器人和可动物体上采点。第二处：底座和安装台也不动，把落在那里的点换到机械臂会动的连杆上。两处都改完，第三人称视角的运动分布也对上了。

真机应用：移液

任务：机械臂拿起电子移液枪，从一个小瓶吸液，打到另一个小瓶，再放回枪架。难点是枪尖要以毫米级对准瓶口，每次小瓶摆放都不同。做法照 RoboTAP：录一次遥操作示教并分段。测试时把相机画面和示教画面对齐，估计小瓶移动了多少，然后开环执行，中途不再看。所以估计必须一次就准。

局限

长时间遮挡、点重新露出时认回来、杂乱背景上的小物体，这三类仍是难点。练习册只有“抓起日常物体”，还没有移液这种精细动作。README 也提醒：用点轨迹驱动真机时（比如视觉伺服），先校验轨迹，限制它能下发的运动幅度，并保留人监护和急停。

10读完做几道题

先自己想，再点开看答案。

  1. 一个点在查询帧之后 4 帧都看得见，模型位置全对，但第 5 帧点被挡住时模型仍说“看得见”。对每个 δ，Jaccard 是多少？

    看答案
    TP = 4，|V| = 4，FP = 1（被挡还说可见）。每个 δ 都是 4 / (4 + 1) = 0.8，所以 AJ = 0.8。位置全对也拿不到满分。见 第 03 节，metrics.py:36。

  2. 仿真里一个点离相机 1.20 m，渲染深度图在它的像素上是 1.18 m。判可见还是遮挡？如果渲染深度是 1.10 m 呢？

    看答案
    1.20 − 1.18 = 0.02 < 0.03，可见（这点差是深度离散误差）。1.20 − 1.10 = 0.10 ≥ 0.03，遮挡：前面有东西。point_tracking.py:99

  3. 为什么采样时要把点存成“刚体本地坐标”，而不是世界坐标？

    看答案
    点长在物体上，物体一动，世界坐标就变了。本地坐标不变，每帧乘上刚体当下的位姿就能得到新位置。存世界坐标就只能得到一个不动的点。point_tracking.py:74point_tracking.py:88

  4. 你只有 4 张卡，想复现 RoboTracker 的 50% 配比，要改什么？大约多久？

    看答案
    加 distributed.virtual_world_size=8。每张卡累加两个虚拟卡的梯度，数据组分配和更新都和 8 卡一样，约 3.5 小时。robotracker.yaml:52

  5. BootsTAPNext 多训了 1500 万条真实视频，RoboTrack-Bench 涨 5.1，RGB-Stacking 却跌 9.5。这说明什么？

    看答案
    RGB-Stacking 是仿真叠积木，它奖励“像仿真”的训练数据，不代表真机能力。考卷本身会影响排名，所以需要真机视频的考卷。见 第 02 节。

  6. RoboTrack-15M 只有机械臂，为什么 RoboTracker-Warp 在人手视频（EgoVerse、Ego-Exo4D）上也涨分？RoboTracker 呢？

    看答案
    练习册教的是“操作场景下的运动和遮挡”：东西被拿起、被挡住、视角在动，这些人手视频里也有。RoboTracker-Warp 在人手上涨了约 1.5，RoboTracker 在 EgoVerse 人手上反而略降（62.87 → 62.37），它的收益主要在机器人视频上。小模型吸收新数据的能力可能更有限。见 第 07 节。

  7. 置信度损失的目标为什么是“误差 ≤ 12 像素”，而不是直接用“看得见”？
