DETR：把目标检测当成"集合预测"来做

外号 · 「匈牙利点名官」100 个 query 一次出框，匈牙利匹配挨个点名

传统检测器先铺几万个 anchor，再用 NMS 去掉重复框。DETR 去掉了这两样：CNN 抽特征，Transformer 编码，再用 100 个可学习的 object query 一次并行解码出 100 个"槽"，每个槽要么是一个物体，要么是"没有物体"。训练时用匈牙利算法把槽和真值一对一配好，再算损失。ACT 的策略网络几乎就是这套结构，只是把"100 个框"换成了"100 步动作"。

01问题：检测器里的手工部件

一张图里有几个物体，数量不定，顺序也无所谓。所以检测的输出本质上是一个集合。以前的检测器不直接预测集合，而是绕了一圈：

Faster R-CNN 一类DETR
候选从哪来特征图每个位置铺几种尺寸、长宽比的 anchor，几万个100 个可学习的 object query
训练时谁负责哪个真值手写规则：IoU 大于阈值的 anchor 算正样本，一个真值配多个 anchor匈牙利算法，一个真值只配一个 query
重复框怎么办NMS 后处理，按 IoU 阈值删训练时就罚重复，推理不做 NMS
物体之间的关系每个候选各自分类回归query 之间做自注意力，互相"商量"谁报哪个
小物体 / 大物体APS 26.6，APL 53.4（FPN+）APS 20.5，APL 61.1

DETR 的大物体好很多，因为编码器的自注意力能看全图。小物体差，因为它只用了 1/32 分辨率的一层特征，没有 FPN。后来的 Deformable DETR 主要就是修这两点（小物体和收敛慢）。

Q1 答不要 anchor：候选换成了 100 个可学习的 query，位置由网络自己学。不要 NMS：训练时用一对一匹配，一个物体只有一个 query 能拿到"框"的监督，其余 query 被要求输出"无物体"；再加上 query 之间的自注意力，网络自己学会了不重复报。论文 Fig.4 显示，最后一层解码器的输出再做 NMS，AP 几乎不变。

2.1 位置编码

Transformer 对输入顺序不敏感，必须告诉它每个 token 在图里的位置。DETR 把 x、y 两个方向分开编码，各 128 维，拼成 256 维。坐标先归一化到 [0, 2π]：

$$\mathrm{PE}(p,2i)=\sin\!\Big(\frac{p}{10000^{2i/128}}\Big),\quad \mathrm{PE}(p,2i+1)=\cos\!\Big(\frac{p}{10000^{2i/128}}\Big),\qquad \mathrm{pos}_{(y,x)}=\big[\mathrm{PE}(y)\,;\,\mathrm{PE}(x)\big]\in\mathbb R^{256}$$

dim_t:41拼 y、x:47normalize=True:83。也可以换成可学习的位置编码（--position_embedding learned），论文表 3 里两者差别很小。

位置编码加在每一层注意力的输入上，而且只加给 Q 和 K：

$$\mathrm{Attn}\big(Q{=}X{+}P,\;K{=}X{+}P,\;V{=}X\big)=\mathrm{softmax}\!\Big(\frac{(X{+}P)W_Q\,\big((X{+}P)W_K\big)^{\!\top}}{\sqrt{d_k}}\Big)\,X W_V$$

编码器 q=k=src+pos:154解码器交叉注意力:224

Q5 答加在每一层的 Q 和 K 上（不只是第一层输入）。Q·K 决定"看哪里"，所以需要位置；V 是"取回来的内容"，保持纯特征，不掺位置。这样每层的残差流里一直是内容，位置每层重新注入。交叉注意力里，query 侧加 object query，key 侧加图像的 2D 正弦编码。

2.2 object query 和全 0 的 tgt

query_embed = nn.Embedding(100, 256) 就是 100 个可学习向量 detr.py:39。它不当作解码器的输入，而是当作解码器的"位置编码"，每层都加到 Q、K 上。真正的输入 tgt 是全 0 transformer.py:55。

所以第一层时，100 个槽的内容都是 0，只靠各自的 query 区分彼此。经过交叉注意力，每个槽从图像里取回内容，内容逐层积累。论文的可视化显示，训练后每个 query 会偏好图里某些区域和某些框的大小，像一组学出来的"专长"。

Q2 答object query 是 100 个可学习的 256 维向量，每个代表一个输出槽的"身份"。它们被当成位置编码，每层加到 Q、K 上；解码器的内容输入 tgt 从 0 开始，内容全靠交叉注意力从图像里取。如果 100 个槽输入相同又没有 query，它们会输出一模一样的结果。ACT 照搬了这一点：decoder_in 也是全 0，decoder_pos_embed 就是 100 个 query。ACT decoder_in:497ACT decoder_pos_embed:369

03二分匹配：先配对，再算损失

网络输出 100 个预测 $\hat y=\{\hat y_i\}_{i=1}^{N}$。真值只有几个，用 ∅ 补到 100 个，记作 $y$。100 个槽没有固定顺序，所以要先找一个排列 $\sigma$，让总匹配代价最小（论文式 1）：

$$\hat\sigma=\mathop{\arg\min}_{\sigma\in\mathfrak S_N}\;\sum_{i=1}^{N}\mathcal L_{\mathrm{match}}\big(y_i,\hat y_{\sigma(i)}\big)$$

每对的代价看两样：类别对不对，框像不像。真值是 ∅ 的那些不参与匹配（代价恒为 0）：

$$\mathcal L_{\mathrm{match}}\big(y_i,\hat y_{\sigma(i)}\big)=-\mathbb 1_{\{c_i\neq\varnothing\}}\,\hat p_{\sigma(i)}(c_i)\;+\;\mathbb 1_{\{c_i\neq\varnothing\}}\,\mathcal L_{\mathrm{box}}\big(b_i,\hat b_{\sigma(i)}\big)$$

代码里把三项按权重相加，得到一个 100 × (真值个数) 的代价矩阵，交给 scipy 的 linear_sum_assignment（匈牙利算法）求解。每张图单独解。

$$C_{ij}=\lambda_{\mathrm{cls}}\cdot\big(-\hat p_i(c_j)\big)+\lambda_{L1}\,\big\|\hat b_i-b_j\big\|_1+\lambda_{\mathrm{iou}}\cdot\big(-\mathrm{GIoU}(\hat b_i,b_j)\big),\qquad \lambda_{\mathrm{cls}}=1,\;\lambda_{L1}=5,\;\lambda_{\mathrm{iou}}=2$$

cost_class:68cost_bbox:71cost_giou:74C:77linear_sum_assignment:81权重 1/5/2:67

匹配整个过程在 torch.no_grad() 下，只给出"谁配谁"，本身不传梯度。

Q3 答匈牙利匹配在 100 个预测和 M 个真值之间找一对一的配法，让"分类代价 + 框代价"的总和最小。匹配时用概率 $-\hat p(c)$ 而不用 $-\log\hat p(c)$：论文说这样分类项和框损失的量级可比，实验效果更好。代码注释也写了：这里近似的是 $1-\hat p(c)$，常数 1 不影响匹配结果，所以省掉了 matcher.py:65。

04损失：匈牙利损失 + 辅助损失

配好 $\hat\sigma$ 之后，对每一对算损失（论文式 2）。这一步在全部 100 个槽上都算分类，但只在配上真值的槽上算框：

$$\mathcal L_{\mathrm{Hungarian}}(y,\hat y)=\sum_{i=1}^{N}\Big[-\log\hat p_{\hat\sigma(i)}(c_i)\;+\;\mathbb 1_{\{c_i\neq\varnothing\}}\,\mathcal L_{\mathrm{box}}\big(b_i,\hat b_{\hat\sigma(i)}\big)\Big]$$

框损失是 L1 和 GIoU 的组合。L1 对大框、小框的误差尺度不一样；GIoU 与尺度无关，两者互补：

$$\mathcal L_{\mathrm{box}}(b,\hat b)=\lambda_{\mathrm{iou}}\big(1-\mathrm{GIoU}(b,\hat b)\big)+\lambda_{L1}\,\|b-\hat b\|_1,\qquad \mathrm{GIoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}-\frac{|C\setminus(A\cup B)|}{|C|}$$

其中 $C$ 是同时包住 A、B 的最小框。两个框不相交时 IoU 恒为 0、没有梯度；GIoU 的第二项仍会把两个框往一起拉。generalized_box_iou:40

  • 归一化。L1 和 GIoU 都除以整个 batch（多卡时取所有卡平均）的真值框个数 num_boxes，不是除以槽数 num_boxes:228。
  • 辅助损失。解码器 6 层的输出都接同一组预测头，每层都重新做一次匹配、算一遍同样的损失，总共 6 份相加 aux:239aux 权重:340。论文说这能帮模型学会每类物体输出正确的个数。
$$\mathcal L_{\mathrm{total}}=\sum_{\ell=1}^{6}\Big[\,1\cdot\mathcal L_{\mathrm{ce}}^{(\ell)}+5\cdot\mathcal L_{L1}^{(\ell)}+2\cdot\mathcal L_{\mathrm{GIoU}}^{(\ell)}\Big]$$

Q4 答没配上的 query，分类目标设成 ∅（"无物体"），只算交叉熵，不算框损失 target_classes:116。一张 COCO 图平均只有 7 个物体左右，100 个槽里九成以上是 ∅。不降权的话，网络最省事的做法是全报 ∅。所以 ∅ 类的交叉熵权重设成 0.1（eos_coef），类似 Faster R-CNN 里对正负样本做的平衡。

编码器有多重要

论文表 2：编码器 0 层时 36.7 AP，3 层 40.1，6 层 40.6，12 层 41.6。没有编码器，大物体 APL 掉 6 个点。论文的注意力可视化显示，编码器已经把各个物体"分开"了，解码器只需盯住物体的边缘（头、脚）来定框。论文 §4.2

收敛慢

DETR 要几百个 epoch，Faster R-CNN 只要 36 个左右。主要原因：一对一匹配让每个真值每步只有一个正样本，且匹配结果在训练早期不稳定；交叉注意力开始时对 850 个位置几乎均匀，要很久才学会聚焦。Deformable DETR、DN-DETR、DINO 等后续工作主要解决这一点。

  2. 把 100 个 object query 全部换成同一个向量，会发生什么？

    看答案
    tgt 全是 0，query 又一样，100 个槽的输入完全相同，每层算出的结果也完全相同，最后 100 个槽输出同一个框。一对一匹配下只有一个能配上，其余全被罚，网络学不下去。query 不同是槽能"分工"的前提。见 Q2 答。

  3. 辅助损失里，第 3 层解码器的匹配结果 σ̂ 是直接用最后一层的吗？

    看答案
    不是。每层都拿自己的预测重新调用一次 matcher。detr.py:241

  4. 为什么框损失除以真值框个数 num_boxes，而不是除以 100？

    看答案
    框损失只在配上的槽上算，个数就是真值框数。除以 100 会让物体多的图权重更大、物体少的图梯度太小。多卡时还要先 all_reduce 再平均，让每张卡的归一化一致。detr.py:228

  5. --lr_backbone 0 时，backbone 会怎样？

    看答案
    train_backbone = lr_backbone > 0 为 False，所有 backbone 参数 requires_grad=False，整个 ResNet 冻结。默认 1e-5 时，只有 layer2–4 的卷积参与训练。backbone.py:114backbone.py:63

  6. ACT 也有 100 个 query、也是全 0 输入。它为什么可以直接算 L1，不需要匹配？

    看答案
    动作序列有顺序，第 i 个槽固定对应第 t+i 步，目标和槽一一对应，不需要找排列。DETR 的框没有顺序，必须先匹配才能知道哪个槽该对哪个真值。见 Q6 答。

  7. 交叉注意力里，K 加了位置编码，V 没加。如果 V 也加上 pos，最直接的变化是什么？

    看答案
    取回来的内容里会混进位置向量，解码器残差流里内容和位置就搅在一起了。DETR 的设计是位置每层只用来算"看哪里"，内容保持干净。见 Q5 答。
