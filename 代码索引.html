先看这一组对照：动作怎么出

步骤OpenVLA（离散 token）π0 / openpi（flow matching）
动作怎么表示ActionTokenizer：每维 256 个 binembed_suffix：带噪的连续动作块 + 时间步
训练目标下一个 token 的交叉熵（和语言模型一样）compute_loss：速度场的均方误差
推理predict_action：逐个生成 7 个 tokensample_actions：10 步去噪，输出 50 步动作块
后来的改进OFT 的 L1 回归头：并行输出整个动作块FASTTokenizer：反过来引入离散 token

详细对比见 OpenVLA vs π 系列。

VLA 怎么生成动作

VLA · 动作当 token（OpenVLA）

概念解释 →
  • 官方openvla · ActionTokenizer ↗
    每维动作裁剪后切成 256 个 bin，覆盖词表最后 256 个 token
  • 官方openvla · predict_action ↗
    自回归生成 7 个动作 token，再解码、反归一化成连续动作

FAST · 动作分词

概念解释 → · 逐文件精读 →
  • 官方openpi · FASTTokenizer ↗
    DCT+BPE 分词器（HF: physical-intelligence/fast），映射到 PaliGemma 词表末尾
  • 官方openpi · BinningTokenizer（对照） ↗
    RT-2/OpenVLA 式逐维分箱，便于和 FAST 对比

Flow Matching · 流匹配

概念解释 →
  • 官方openpi · Pi0.compute_loss ↗
    构造 x_t = t·噪声 + (1−t)·动作，回归速度场 u_t = 噪声 − 动作
  • 官方openpi · Pi0.sample_actions ↗
    从纯噪声出发，用 10 步欧拉积分 x ← x + dt·v 得到动作块

Action expert · 动作专家

概念解释 →
  • 官方openpi · Pi0Config ↗
    骨干 gemma_2b，动作专家 gemma_300m
  • 官方openpi · gemma.get_config ↗
    gemma_300m 的宽度、深度、头数
  • 官方openpi · Pi0.embed_suffix（π0.5 adaRMS） ↗
    状态、带噪动作和时间步编码成动作专家的输入；π0.5 用 adaRMS 注入时间

Action chunk · 动作块

概念解释 →
  • 官方openpi · action_horizon = 50 ↗
    π0 一次输出 50 步
  • 官方openvla-oft · L1RegressionActionHead ↗
    OFT 一次并行回归整块动作（NUM_ACTIONS_CHUNK 步）
  • 官方openvla-oft · 并行解码 ↗
    用占位 token 一次前向得到整块动作，不再逐 token 生成

KV Cache

概念解释 →
  • 官方openpi · 前缀 KV cache ↗
    图像+文字前缀只算一次，10 步去噪都复用这份 cache

感知—执行时延 / 实时分块

  • 复现RLinf · RTC 引导采样 ↗

Cross-embodiment · 跨本体
