ACT：看一眼，规划接下来 2 秒的动作

ACT 是一种行为克隆算法。它每看一次画面，就一次性输出接下来 100 步（50Hz 下约 2 秒）的关节目标位置，而不是一步一步地猜。网络是一个 CVAE：训练时用一个额外的编码器把"人这次的操作风格"压成隐变量 z，推理时扔掉编码器，令 z = 0。

01 · HISTORY前世今生

ACT 本身不复杂，它是几条老路线的交汇点。要解决的问题也很具体：用 2 万美元以内的廉价双臂，做毫米级的精细操作。

1989 → 2011
行为克隆与误差累积
ALVINN（1989）把开车当成"看图 → 输出方向盘"的监督学习，这就是行为克隆（BC）。它的老毛病是误差累积：每步小错让机器人走到没见过的状态，错误越滚越大。DAgger（2011）靠专家在线纠错来缓解，但遥操作时很难让人随时标注。
2015
CVAE：条件变分自编码器
Sohn 等人提出 CVAE，在给定条件 x 时，用隐变量 z 表示"同一条件下的不同答案"。ACT 用它来吸收人类示范里的随机性。
2017 → 2020
Transformer 与 DETR
Transformer（2017）擅长处理序列。DETR（2020）用"ResNet 特征图 + Transformer 编码器 + 一组可学习 query 的解码器"直接输出 N 个检测框。ACT 的策略网络几乎就是 DETR，只是把"N 个框"换成"k 个未来动作"，原始代码也是在 DETR 代码上改的。
2021 → 2022
BeT、RT-1、VINN
这些方法用 Transformer 或最近邻做模仿学习，但都是每次输出一步动作，BeT 和 RT-1 还把动作离散化成格子。在 ACT 论文的精细任务上，它们的最终成功率大多接近 0。
2023.04 · RSS 2023
ALOHA + ACT 诞生
Tony Z. Zhao、Vikash Kumar、Sergey Levine、Chelsea Finn（Stanford / Berkeley / Meta）发表《Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware》。论文有两半：ALOHA 是一套低成本双臂遥操作硬件，ACT 是配套的学习算法。核心想法借自心理学的"动作分块"：人做事是一段一段规划的，不是一个肌肉指令一个肌肉指令地想。同年 Diffusion Policy 也提出预测动作序列，两者是同期工作。
2024.01
Mobile ALOHA
Fu、Zhao、Finn 把 ALOHA 装到移动底盘上，用 ACT 等策略配合静态 ALOHA 数据联合训练，完成炒虾、推椅子等任务。注意：炒菜等演示属于 Mobile ALOHA，不是 ACT 原论文。
2024.05
LeRobot 开源
Hugging Face 发布 LeRobot，ACT 是首批收录的策略之一，并附带 ALOHA 仿真预训练权重。之后配合 SO-100 / SO-101 低成本机械臂，ACT 成了 LeRobot 教程里默认推荐的入门策略。
2024 → 至今
动作分块成为标配
π0 一次输出 50 步动作块，再用实时动作分块（RTC）处理块与块的衔接；ALOHA Unleashed（2024，系鞋带、挂衣服）改用扩散策略。生成动作的方式变了，"一次输出一段动作"这个思路一直沿用到今天的 VLA。

1

示范采集：ALOHA 遥操作训练前

ALOHA 有两对机械臂。人用手推动小一号的主臂（WidowX，约 3300 美元），大一号的从臂（ViperX 6 自由度，约 5600 美元）按关节角一一跟随。整套硬件不到 2 万美元，以 50Hz 记录数据。

观测 o_t = 4 路 RGB 相机（正前、顶部、左右手腕），每路 480×640 + 从臂关节位置 qpos，14 维 = 2 臂 × (6 关节 + 1 夹爪) 动作 a_t = 主臂关节位置，14 维（绝对位置，下一时刻的目标）

为什么动作取主臂而不是从臂？从臂由电机内置的 PID 去追主臂的角度。人"用了多大力"体现在两者的位置差里。如果记录从臂的位置，这个力的信息就丢了。论文还发现，用相对位移（delta）代替绝对目标位置，效果会变差。

每条示范持续 8–14 秒，即 400–700 步。每个任务录 50 条，穿魔术贴任务录了 100 条，合计约 10–20 分钟数据。

切片采样：一帧观测配 100 步未来动作训练

每个训练样本取一个时刻 t，只拿当前这一帧观测（n_obs_steps=1，不看历史），再拿从 t 开始的 100 步真值动作作为监督目标。

batch["observation.images.*"] (B, 3, 480, 640) × 4 路 batch["observation.state"] (B, 14) batch["action"] (B, 100, 14) ← a[t : t+100] batch["action_is_pad"] (B, 100) ← 越过回合末尾的位置为 True

例子：一条示范共 400 步，抽到 t = 350，那么只有 50 步真实动作，后 50 步是补齐的，action_is_pad 标为 True。这些位置在 ③ 中会被注意力屏蔽，在 ⑨ 中不计入损失。

LeRobot 的实现方式：配置里声明 action_delta_indices = range(100)，数据集工厂按帧率换算成时间偏移 [0, 1/fps, …, 99/fps]，LeRobotDataset 据此自动取出未来动作并生成补齐掩码。

3

CVAE 编码器：把"这次怎么做的"压成 z只在训练

这是一个 BERT 风格的 4 层 Transformer 编码器。它的输入序列是：

[CLS] 1 个可学习 token qpos → Linear 1 个 token（14 → 512） action → Linear 100 个 token（每步 14 → 512） ────────────── 共 k + 2 = 102 个 token，加固定的 1D 正弦位置编码 padding mask：CLS 与 qpos 不屏蔽，动作部分沿用 action_is_pad

取 [CLS] 位置的输出，经过 Linear(512 → 64)，前 32 维是均值 μ，后 32 维是 2·log σ（沿用原实现的写法）。然后用重参数化采样：

$$z = \mu + \sigma \odot \epsilon,\quad \epsilon \sim \mathcal N(0, I),\quad z \in \mathbb R^{32}$$

注意：编码器不看图像。论文说这样做是为了训练更快。所以 z 只能描述"这段动作和当前关节角相比有什么特点"，比如偏快还是偏慢、先动左手还是先动右手。场景信息完全由策略网络自己从图像里读。

z 是用来干什么的？人类示范有随机性：同一个画面，这次停顿了 0.5 秒，下次没有停；这次交接位置偏左，下次偏右。如果没有 z，策略只能把这些情况平均起来。z 相当于告诉策略"这一条走的是哪个版本"，让它可以专心学"在这个版本下应该怎么动"，而不会被迫学成平均值。

4

ResNet18 主干：每路相机 → 300 个视觉 token训练 + 推理

每路图像用 ImageNet 预训练的 ResNet18 处理，取 layer4 的输出特征图，BatchNorm 层冻结（FrozenBatchNorm2d）。ResNet 总下采样 32 倍，所以：

480×640×3 → ResNet18 layer4 → 15×20×512 → 1×1 Conv(512→512) → 展平成 300 个 token，每个 512 维 + 2D 正弦位置编码（行、列各占 256 维） 4 路相机 → 1200 个视觉 token

2D 位置编码让每个 token 记住自己在图像的哪一格。展平之后，Transformer 仍然知道"左上角"和"右下角"的区别。

LeRobot 里所有相机共用同一个 ResNet，主干和其余部分的学习率都是 1e-5（通过 optimizer_lr_backbone 单独设置）。

拼 token：z + 关节 + 图像 = 1202 个训练 + 推理

token 0 z → Linear(32 → 512) 训练时来自 ③，推理时 z = 0 token 1 qpos → Linear(14 → 512) token 2…1201 1200 个视觉 token 来自 ④ ──────────────────────────────────────── encoder 输入 (1202, B, 512) 位置编码：前 2 个用可学习的 1D Embedding，后 1200 个用 2D 正弦编码

z 和图像在这里是平等的 token。Transformer 可以通过注意力自己决定 z 的影响有多大：训练时 z 携带了真值信息，策略会参考它；推理时 z = 0，策略只能依赖图像和关节状态。

在 LeRobot 里，如果数据集只有环境状态（比如仿真里物体的坐标）而没有图像，会多一个 env_state token，用来代替视觉 token。

6

Transformer 编码器：4 层自注意力训练 + 推理

结构是标准的 post-norm 编码器层：自注意力加前馈网络。主要参数为 dim_model=512、n_heads=8、dim_feedforward=3200、dropout=0.1。位置编码只加在 Q 和 K 上，V 不加（DETR 的做法）。

这一步做的是信息融合。4 路相机的画面、两只手臂的关节角、z 在注意力中互相交换信息，输出 1202 个"已经看过全局"的特征，作为解码器的记忆（memory）。

7

Transformer 解码器：100 个 query 各自"认领"一个未来时刻训练 + 推理

这是 ACT 能一次输出 100 步的关键。解码器的输入是一个全零张量 (100, B, 512)，真正起作用的是 decoder_pos_embed = nn.Embedding(100, 512)。这是 100 个可学习向量，第 i 个向量专门负责"未来第 i 步"。每一层的计算分三步：

① 自注意力：100 个 query 互相看 → 保证相邻时刻的动作前后连贯 ② 交叉注意力：Q = query + 位置编码 K = memory + 位置编码，V = memory（来自 ⑥ 的 1202 个 token） → 每个时刻自己去画面里找需要的信息 ③ 前馈网络 输出 (100, B, 512)

这和 DETR 中"100 个 object query 各自认领一个检测框"是同一套机制。动作是并行一次性解码出来的，不是像语言模型那样一个一个地生成，所以推理只需要一次前向传播。

层数的一个历史问题：论文附录写的是 7 层解码器。但原始代码有一个 bug，实际只用到第 1 层（见 tonyzhaozh/act#25）。LeRobot 为了复现原始结果，把 n_decoder_layers 默认值设为 1。

损失与反向传播只有训练

$$\mathcal L = \underbrace{\frac{1}{N}\sum_{t,i}\big|\hat a_i - a_i\big|}_{\text{只在非补齐位}} \;+\;\beta\cdot \underbrace{D_{\mathrm{KL}}\big(q_\phi(z\,|\,a_{t:t+k},\tilde o_t)\,\big\|\,\mathcal N(0,I)\big)}_{\text{把 } z \text{ 拉向标准正态}},\quad \beta=10$$

两项各管一件事：

项作用漏掉会怎样
L1 重构让预测的 100 步动作贴合示范策略根本不模仿
KL 正则把 z 的分布拉向 N(0, I)，限制它携带的信息量编码器会把整段动作"抄"进 z，推理时 z=0，策略就什么都不会了

β = 10 在这里算比较大。它换来的是：z 只保留"风格"这类低维信息，绝大部分信息必须由策略从图像里自己读。这也是推理时敢把 z 置零的底气。

一处原文的不一致：论文 Algorithm 1 的伪代码写的是 L_reconst = MSE，但正文明确说"我们用 L1 而非常见的 L2，L1 对动作序列的建模更精确"，消融实验也证明换不回来。LeRobot 的实现按正文用 L1。另外论文把 KL 权重记作 β，代码里叫 kl_weight，默认 10.0。

Adam，学习率 1e-5，batch size 8，dropout 0.1。LeRobot 里 ResNet 主干被单独分到一个参数组（optimizer_lr_backbone，默认也是 1e-5），整体约 80M 参数，单卡 2080 Ti 约 5 小时。

04 · INFERENCE推理细节：⑩ → ⑪ 再回到 ④

推理时 ③ 整块被删掉，模型只剩"看图 → 出 100 步"。不一样的地方在于这 100 步怎么用。LeRobot 提供了两种方式，默认是第一种。

10

方式一：队列，一次预测用 100 步默认

select_action() 每被调用一次，只返回一个动作。内部维护一个长度 100 的队列：

队列空 → 调一次网络拿到 (B, 100, 14)，取前 n_action_steps 步压入队列 队列非空 → 直接吐出一个，不碰网络 100 步用完 → 再看一眼画面，重新预测

好处是推理极省，50Hz 下每 2 秒才跑一次网络（每次约 10ms）。代价是这 2 秒内机器人是闭着眼睛走的：中途被碰一下、物体滑了，它不会察觉，只能等下一个块。

推论：n_action_steps 是"盲跑多久"的旋钮。chunk_size 决定网络能规划多远，n_action_steps 决定实际执行多远。可以预测 100 步只执行 10 步，用反应速度换推理开销。

方式二：时间集成，每个时刻都看、都平均temporal_ensemble_coeff

开启后，每个时间步都重新预测一整个块。于是在时刻 t，手里有来自不同次预测的、对同一个未来时刻的多个版本，把它们加权平均：

$$a_t=\frac{\sum_i w_i\,A_t[i]}{\sum_i w_i},\qquad w_i=\exp(-m\cdot i)$$

$A_t[i]$ 是第 i 次预测对时刻 t 给出的动作，$i$ 越小越旧，所以旧预测权重更大。m 控制新观测进入的速度，默认 0.01，m 越小越相信新预测。

关键细节，容易看错：平均的是同一个未来时刻的多次预测，不是把相邻时刻的动作做平滑。普通平滑会引入偏差（把"该走到哪"往回拉），这里不会。论文特别强调这点。
注意默认是关的。LeRobot 里 temporal_ensemble_coeff 默认 None，也就是走 ⑩ 的队列。开启时必须令 n_action_steps=1，否则直接报 NotImplementedError。

动手看：m 怎么影响"新信息进来的速度"

假设第 0 次预测说"这一步该到 0"，之后每次新预测都说"该到 1"（比如机器人被推了一下）。拖动 m 看平均值的追赶速度。

05 · WHY IT WORKS每一步为什么这么设计

动作分块的 k 不是越大越好

论文在 4 个设置（2 个仿真任务 × 人工 / 脚本数据）上扫 chunk size，关掉时间集成，只看分块本身：

k平均成功率说明
11%等于没有分块，单步预测，基本学不会
10044%（峰值附近）论文的选择
200 / 400略降接近开环，缺少反应能力，长序列也更难建模

同一组实验里，给 BC-ConvMLP 和 VINN 也加上 k 步输出，它们同样大幅提升。可见分块本身是通用的收益，ACT 的增益来自"分块 + Transformer + CVAE"的组合。

三个部件各自的贡献

去掉什么后果证据
动作分块成功率跌到 1%k 扫描实验
Temporal Ensemble平均掉约 3.3 个百分点（BC-ConvMLP 掉约 4）论文 VI-A
CVAE 目标脚本数据几乎无影响；人工数据 35.3% → 2%论文 VI-B ——这是全文最有说服力的一张图
怎么理解"CVAE 在人工数据上才重要"：脚本策略是确定性的，同一观测永远对应同一动作，隐变量没东西可编码。人类示范则处处随机：停顿、交接点、抓取角度都不一样。没有 z，一个确定性网络被迫输出这些情况的中位数，而中位数往往是个谁都不对的形状。

它为什么快

100 步动作一次前向并行解码，不是自回归生成。对比扩散策略要迭代几十步去噪，ACT 只需要一次，2080 Ti 上约 10ms。这也是当年 ACT 相对 Diffusion Policy 的主要优势之一。

反直觉的几点，集中说清

为什么推理时 z = 0 还能用？

训练时 KL 项（β = 10）一直在压 z 的信息量，逼它接近 N(0, I)。结果有两条：一是策略被迫从图像里读主要信息，不能只靠 z；二是先验均值 0 落在训练分布之内。所以递一张"空白纸条"不会掉出分布。不过要注意：z = 0 是先验均值，输出接近"平均风格"，并不是在多个模式里随机挑一个。这个策略在推理时是确定性的。

为什么不看历史观测？

LeRobot 里 n_obs_steps 被强制为 1。ACT 的设计是"用 100 步动作块替代历史"：它不需要看过去，因为过去的信息体现在当前状态里，而未来的一致性由解码器的 100 个 query 自注意力保证。反过来说，被遮挡或运动模糊的瞬时画面无法靠历史补救，这是它的一个脆弱点。

为什么用绝对关节位置而不是位移？

论文试过用 delta 关节位置，性能下降。绝对目标位置让每一帧的预测是自洽的，也让时间集成里的加权平均有意义（平均"目标位置"是合理的，平均"增量"则要另外解释）。

为什么分块加上时间集成，而不用 RTC？

ACT 的时间集成只是在推理阶段把多次预测做加权平均，没有解决"新块的第一帧与旧块最后一帧不连续"的本质问题。后来的实时动作分块（RTC）在 π0 等更大的模型上用"引导生成"来保证块间连续，这是同一条路上的下一步。

ACT 的定位很清楚：用最少的推理开销，把单个任务做到稳定流畅。它不擅长跨任务泛化，也没有语言接口。

已知局限

  • 单任务：每个任务单独训一套权重。
  • 依赖视角：相机位置、光照、背景一变，性能就掉。
  • 分布外很脆：仿真的插入任务上，目标位置偏移稍大就失败。
  • 推理确定性：z=0 让它在多解场景下倾向"平均解"，不像扩散能采样出不同模式。
  • 误差仍会累积：分块把有效视野缩短了 k 倍，但没有消除累积，只是减速。
