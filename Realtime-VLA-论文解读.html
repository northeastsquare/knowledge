Realtime-VLA FLASH：扩散 VLA 的投机推理框架

用投机推理加速扩散 VLA，实现实时闭环控制

论文Realtime-VLA FLASH: Speculative Inference Framework for Diffusion-based VLAs
机构中科院计算所 · Dexmal
arXiv2605.13778v1
主题VLA · 推理加速

它解决的问题

扩散式视觉-语言-动作模型（dVLA，代表是 π0）能捕捉多模态的动作分布，在复杂操作任务上表现很强，但要在真实机器人上实时部署，全量推理的高延迟是硬约束。

  • 机器人控制频率远高于模型推理频率，现有系统只能靠开环动作分块（open-loop action chunking）来桥接这个速度差：一次预测未来一整段动作，先执行几步，等执行到一半才触发下一次重规划（replanning）。
  • 问题在于：虽然重规划频率被降低了，每一轮重规划仍然要跑同样昂贵的全量推理管线（图像编码 → VLM prefill → 多步动作去噪）。端到端推理延迟依旧是最主要的瓶颈，直接限制了 dVLA 用在需要快速反应的、延迟敏感的任务上。

作者想借用的工具是投机推理（Speculative Inference）——它在 LLM 和自回归 VLA 上已经被证明有效：让一个轻量草稿模型先提出候选，主模型并行验证，从而省掉昂贵的主模型生成。但这套东西在 dVLA 上没法直接搬：

投机推理的三要素在 dVLA 上全部失效

要素自回归模型（LLM / AR-VLA）dVLA（π0 类）
草稿提出离散 token 级概率天然支持动作是连续空间里多步迭代去噪生成的，什么叫"有意义的草稿"不清楚
并行验证token 概率逐位核对去噪本身是串行的，天然抗拒并行
接受准则有显式似然可比较连续动作没有显式似然，拿不出自然的接受判据

三者里最要命的是验证（verification）：找不到一种便宜的方法来检验一段草拟的连续动作块，投机推理就会退化成"把完整串行去噪再跑一遍"，等于没有加速。

一句话概括：dVLA 推理太慢，而投机推理三要素在连续去噪的设定下没有现成答案，本文要解决的核心就是"如何在连续动作域里做便宜又可靠的验证"。

方法主线

作者先用roofline 剖析找瓶颈，再据此设计一条"闪电路径（Flash Path）"替代大部分全量推理，一共五步。

  1. 延迟剖析定位闲置算力：在 RTX 4090D 上把 π0 全量推理拆成三段——图像编码 11.3 ms、VLM prefill 26.7 ms、动作去噪 20.0 ms（合计 58.0 ms）。roofline 分析显示图像编码与 prefill 是算力受限（应消除冗余计算 → 复用 KV Cache），而动作去噪是访存受限（每步反复读 cache 又无法跨步并行 → 算力闲置，适合改做并行验证）。
  2. 双路径运行时：保留原始全量路径（Full Path）作兜底，新增一条轻量闪电路径（Flash Path）。绝大多数重规划轮走 flash path，只有验证失败或进入精细调节阶段才回落到 full path 校正轨迹。
  3. 轻量草稿模型出候选：flash path 仍编码当前图像，但跳过 VLM prefill，把视觉特征喂给一个只有约 110M 参数的草稿模型（单个 Gemma block + 线性动作头，对比 VLM 约 2.7B），一次性并行预测整段候选动作块。
  4. 多步并行验证：利用 flow matching 的线性插值路径——把草稿终点与高斯噪声插值出中间去噪状态，在选定的几个去噪时刻并行调用主模型的 Action Expert 重构终点，逐动作比较距离，返回最长一致前缀作为可执行动作。
  5. 相位感知回退：用夹爪开合（gripper switch）作为"即将进入精细调节阶段"的启发式信号，主动回退全量路径；再加周期性全量刷新（PF）纠正长期漂移。两者叠加才是最优的成功率-延迟权衡。

输入、输出与数据流

模型输入 / 输出

  • 输入：多模态观测 o_t = [I_t¹, …, I_tⁿ, ℓ_t, q_t]——多视角图像、语言指令、机器人状态（joint state）。
  • 输出：未来动作块 A_t = [a_t, a_{t+1}, …, a_{t+H-1}]，H=50 步；每步动作含语义不同的通道——末端位姿 p_t、旋转 r_t、二值夹爪控制 g_t。
  • 执行方式：只执行动作块前缀，每执行 12 步后基于新观测重规划一次。

训练或运行方式

草稿模型训练（离线、一次性的额外开销）

  • 目标：对冻结的全量路径策略输出做监督回归，损失为加权 Smooth L1 / Huber（δ=1.0）。
  • 前缀加权：采样前缀最多 16 步，前缀权重 0.9、尾部权重 0.1——早期可执行动作权重更高，最终执行多长前缀仍由验证与回退决定。
  • 超参：AdamW，学习率 2×10⁻³，weight decay 0.01，batch 64，100 epochs，FP32；每套 LIBERO suite 训一个草稿模型，约 4×RTX 4090D、6 小时。

在线运行

  • 动作块 H=50，每执行 12 步重规划；验证阈值 δ=0.15，验证时刻数 K=2。
  • 草稿模型在推理时不做完整去噪，而是并行预测整块（H 个学习到的 action query slot 同时解码）。
  • 所有在线实验在单张 RTX 4090D 上跑；真机用同步推理循环，不做异步推理或延迟隐藏。

真机适配

传送带分拣（toy dog + hairbrush 两类，每类 200 条演示）：先对预训练 π0 用 LoRA 微调 20k 步；草稿模型的观测来自真实演示，但回归目标是微调后主模型生成的教师动作块，而非直接克隆原始演示动作。约 8×H20，微调 12 小时 + 草稿训练 2 小时。

我真正学到的内容

  • 投机推理在连续动作域的真正门槛是验证，而 flow matching 恰好免费送了一个验证器。因为 flow matching 训练时就在高斯噪声与目标动作之间的线性路径上学习速度场，给定草稿终点就能插值出中间状态、在几个时刻并行问 Action Expert"你会不会从这里走到这个终点"，从而绕开完整串行去噪。这是全文最关键的一步借力。
  • 延迟剖析决定设计，而非先想方案再找理由：roofline 把三段分别标成算力受限 / 访存受限，于是结论直接指向"prefill 该复用 KV Cache、去噪该并行验证"——优化点是从硬件特征反推出来的。
  • 投机加速不是全域都安全：平滑运动时观测变化慢、小误差可容忍；但夹爪开合这类精细调节阶段误差会放大成失败。所以"什么时候该信任草稿"和"草稿能不能被接受"是两回事，需要单独的相位感知机制。
  • 把二元接受改成"返回最长一致前缀"更实用：比 yes/no 更细粒度，能执行多少就执行多少，还让回退的交接更平滑。
  • 几乎零成本的阶段信号：夹爪通道在 LIBERO 里是 ±1 的离散开合，标准化后仍然在 0 附近分开，所以"过零检测"就能识别抓取/释放事件——不需要额外模型或标注。

可复用设计

  • 草稿模型与主模型架构对齐：直接复用 VLM 的一个 Gemma block + 线性动作头，保持同样的动作块表示——既便宜（110M vs 2.7B），又让验证阶段能直接复用主模型 Action Expert，甚至部分复用 Triton kernel。
  • H 个可学习 action query slot：把"定长动作块写在哪"显式化，用 blockwise 注意力掩码让 slot 同时看到视觉-语言前缀和状态 token，一个前向 pass 并行产出整块动作。
  • 前缀加权的回归目标：早期可执行动作权重高，但"最终执行多长"仍留给验证与回退判定——训练目标和推理目标各司其职。
  • "周期刷新 + 相位回退"的组合拳：PF 负责长期漂移的粗校正，FB 负责精度关键阶段的针对性校正，单独用都不够，叠加才是最优权衡。
  • 保守前缀规则 L = min_k L(k)：多个验证时刻取最保守的可执行长度，宁可少执行也不冒险。
  • 真机草稿回归教师输出而非原始演示：草稿模型学的对象是微调后主模型的动作块，而不是人类演示——保证草稿与主策略同分布。

疑问与风险

  • 验证只是"局部一致性启发式"，不是正确性保证（附录 B 明确承认）：接受一个草稿前缀，不代表它与全量路径产生相同轨迹。端点误差受四因素约束——接受阈值、Action Expert 的局部重建误差、复用 KV Cache 的条件失配、以及"草稿诱导插值路径 vs 训练用目标路径"的路径失配。
  • 阈值与验证时刻是手工启发式：δ=0.15、K=2 是拍出来的，作者自己也把"轨迹自适应的验证阈值"列为未来方向。
  • 相位信号依赖夹爪通道：用 gripper switch 当阶段信号很优雅，但对没有明显开合语义的末端执行器（如吸盘、灵巧手）未必成立。
  • 额外训练成本：每套任务/suite 要单独训一个草稿模型（约 6 小时），相比纯 kernel 优化（Triton）或蒸馏到少步生成的方法，多了一份离线开销和部署复杂度。
  • 真机证据面窄：只有传送带分拣一类任务、两类物体、每条件 10 次试验，结论的泛化性还有待更多真实任务验证。
  • 附录表格呈现有瑕疵：Table 2 里 Object / Goal / 10 三行的对齐看起来错位（Acc / FR 数字与 suite 行对不齐），不影响正文结论，但读附录数据时要小心。

后续动作

  • 补背景：读 π0 原论文（arXiv:2410.24164）吃透 flow matching VLA 的 Action Expert 与 KV Cache 机制；读 Realtime-VLA 系列（Triton 版 2510.26742、v2 2603.26360）理解 kernel 级优化到底做了什么。
  • 读代码 / 复现：复现 Table 6 的组件级延迟分解，亲自验证"去噪访存受限、prefill 算力受限"的 roofline 结论在自己硬件上是否成立；对比 flash path 并行验证的真实墙钟收益。
  • 动手实验：把投机推理与 real-time chunking（RTC）结合——现有 RTC 假设固定推理延迟，而 FLASH 引入了可变接受前缀长度，需要能处理变延迟策略更新的轨迹优化。
  • 追方向：关注边缘部署（VLA-Perf 2602.18397 指出边缘设备更偏访存受限、功耗/散热更紧），FLASH 减少重复全量推理的思路在边缘可能收益更大。
