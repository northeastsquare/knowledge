RLinf 里的 RL 方法详细对比

RLinf（"inf" = Infrastructure / Infinite）不是一种算法，而是把十几种 RL 算法塞进同一套接口的具身 RL 基础设施。这一页按「数据从哪来、要不要 critic、改模型哪部分」把内置的 15 种 RL 算法 + 5 种 SFT/模仿配方摊开对比。

① on-policy 策略梯度

5 个

主力家族。共同点：只用刚采的数据更新一次，靠裁剪或 KL 约束住步长。分水岭在优势怎么来——PPO 系要训 critic（GAE），GRPO 系用组内相对回报代替 critic，省一半显存但要求同一状态能重复采样。

PPO / Async PPO
在 ManiSkill 上比 GRPO 更稳、更好。代价是要养 critic；RLinf 的处理是让 critic 和 VLA 的语言主干共享参数，只挂一个轻量 value head。Async PPO 数学不变，纯粹解决系统吞吐。
GRPO / DAPO / Reinforce++
无 critic 路线。GRPO 是 LIBERO 多任务主力；DAPO 的四件套主要面向长 CoT，其动态采样是具身场景唯一被大量继承的部分；Reinforce++ 最轻，把 KL 直接减进奖励。

② off-policy 最大熵

3 个

SAC 一脉。样本效率远高于 ①（能反复复用 replay buffer），代价是价值高估要靠一堆工程手段压住。RLinf 的三个变体正好是三种压法：CrossQ 改架构、RLPD 改数据配比 + 集成、SAC 本身靠 target 网络。

SAC
软 Bellman + 自动调温度 α，双 Q + target 网络。
CrossQ
反其道行之：删掉 target 网络（消除价值传播的人为延迟），用 Batch Renorm 补稳定性，critic 加宽到 2048。结果是 UTD=1 就能打到 REDQ/DroQ 的样本效率，算力便宜得多。
RLPD
真机上最实用的一个：批次一半在线一半演示数据，critic 加 LayerNorm 防外推爆炸，10 个 Q 的集成里随机取子集。不需要离线预训练阶段。

③ 流 / 噪声空间

2 个（+πRL）

专门解决一个麻痹问题：流匹配 / 扩散策略的 log π 算不出来，而策略梯度和最大熵 RL 都要它。两条解法——要么想办法把似然变可算（SAC-Flow、πRL），要么换个地方做 RL，绕开似然（DSRL）。

SAC-Flow
把 K 步 ODE 采样视作 RNN 展开，用循环式 Transformer 重参数化速度网络解决稳定性；每步加高斯噪声 + 漂移修正，保持终点分布不变，于是路径密度可拆成单步高斯乘积 → 得到可导 log π。可叠 RLPD 上真机。
DSRL
最"懒"也最省的解法：完全不碰似然。冻结 π₀，把「选初始噪声」当成新的动作空间，训一个 ~500K 的 SAC agent 在这个空间里出手。可训参数比整模型少三个数量级，泛化几乎不损。
πRL（RLinf 自家 π₀/π₀.₅ 报告）
同一问题的第三种解法：Flow-Noise 学一个噪声网络把采样变成可算似然的高斯链；Flow-SDE 把 ODE 转成保持边缘分布的 SDE + 两层 MDP，然后照常上 PPO。

④ 表示 / 蒸馏

2 个

都不改 VLA 本体，但目的不同：RLT 是换个更好的状态表示再做 RL；OPD 根本不做 RL，而是用 teacher 的 logprob 当优势做在线蒸馏。

RLT（RL Token）
冻结 VLA 上加编码-解码器，用自回归重建损失压出一个紧凑 RL token（信息瓶颈）；轻量 actor-critic 以 RL token + 本体感觉 + VLA 参考动作块为条件，靠正则锚定不跑偏。
OPD（On-Policy Distillation）
学生 rollout，teacher 不生成动作，只在事后给学生自己的 action token 打 dense token 级 logprob，优势 = teacher logprob − 学生 logprob（后者停梯度）。打完即卸载，省显存省延迟。

⑤ 离线优势条件

3 个

真机场景的现实主义路线：完全不做新 rollout，只把已有数据重新打分再训。IQL 走经典优势加权 BC；RECAP / STEAM 走一条更有意思的路——把优势变成CFG 的条件信号，高优势样本当条件输入、低优势当无条件输入，推理时用 guidance 把策略往高优势方向推。

IQL
期望回归学 V（不对 OOD 动作取 max，这是它稳的关键）+ Bellman 学 Q + 优势加权 BC。D4RL 上的经典基线。
RECAP (CFG)
四段流水线：折扣回报 → 价值模型 SFT → 逐帧优势 → CFG 训练。对应 π₀.₆ 的训练配方，见 π₀.₆ 精读。
STEAM
把 RECAP 的价值信号换掉：不回归折扣回报，而是从专家演示的时序顺序自监督学「进度」——帧对正序监督前进、逆序暴露倒退，偏移按轨迹长度归一化（越高效得分越高）。再用 worst-of-N 集成取最小值当优势，专门压制对 OOD rollout 的高估。完全不需要奖励和人工标签。

VLA 专属：动作块带来的粒度问题

VLA 一次输出一个动作块，这让「优势 / logprob 算在哪一级」成了真问题。RLinf 把它做成配置项，支持三级粒度：

chunk-level
整块当一个宏动作，共享一个奖励和优势；critic 只出一个标量。
action-level
块内每个原子动作各自算奖励与优势；critic 出一个 K 维向量。
token-level
仅 logprob 支持，细到每个 token。

论文的结论很干脆：action-level 一致优于 chunk-level，成功率更高、value loss 更低，在 ManiSkill PutOnPlateInScene25Main 和 LIBERO-Goal 上都成立。

PPO 的两条实操经验

  • 用 action-level 价值估计，不要 chunk-level。
  • 用 Partial Reset，不要固定 episode 长度。因为优化目标是「至少成功一次」（success_once），部分重置的成功率明显更高，OpenVLA 和 OpenVLA-OFT 上都一致。

GRPO 的两条实操经验

  • 开 Valid Action Mask：任务提前完成后的时间步要 mask 掉，不要算进损失。
  • 开成功率过滤（借 DAPO 的动态采样思想）：一组轨迹全成或全败时优势恒为 0，直接丢掉这组。OpenVLA + ManiSkill 上不加过滤会在 step 400 附近崩溃，加了就稳；但在 OpenVLA-OFT 上收益不明显——不是万灵药。

系统层：为什么同一个算法能快 2 倍

RLinf 的底层范式叫 M2Flow（macro-to-micro flow transformation）：你用粗粒度的直觉方式写工作流，系统自己把它翻译成细粒度的执行计划，靠弹性流水线（空间调度）和自动上下文切换（时间调度）去搜一个巨大的调度空间。

对具身 RL，三种 GPU 分配模式差别很大，而且最优模式取决于仿真器是 CPU 密集还是 GPU 密集：

collocated
全部组件共享全部 GPU。LIBERO（CPU 并行、rollout 是瓶颈）上最优，比基线快 1.25×–2.13×。
disaggregated
各组件分占不同 GPU。
hybrid
RLinf 新提的混合模式 + 细粒度流水。ManiSkill（GPU 并行）上 8 卡快 1.88×，16/32 卡仍有 1.61×–1.69×。

推理 RL 侧：GRPO 训 Qwen2.5 的 1.5B / 7B / 32B，比 veRL 快 1.10×–1.58×；长上下文（28,672）下 disaggregated 比 collocated 快 1.17×–1.21×。后端可选 FSDP+HF/SGLang/vLLM（快速原型）或 Megatron+SGLang/vLLM（大规模）。

效果侧：单一模型在 130 个 LIBERO 任务上 98.11%，另一个单模型在 25 个 ManiSkill 任务上 97.66%，RoboTwin 6 个任务专用模型平均 84.63%。整体比基座模型提升约 20%–85%。

怎么选

  • 有仿真器、要大改、要稳：PPO（action-level + partial reset）。ManiSkill 类 GPU 并行环境配 hybrid 模式。
  • 多任务、不想养 critic：GRPO + valid action mask + 成功率过滤。LIBERO 类 CPU 环境配 collocated。
  • 真机 + 有演示数据：RLPD（对称采样是关键），或 SAC-Flow + RLPD。
  • 真机 + 不能大规模采样：RECAP 或 STEAM，纯离线走 CFG。没有奖励标注就选 STEAM。
  • 要最大程度保住 VLA 泛化：DSRL（~500K 参数）或 RLT（紧凑表示 + 轻量头）。
  • 有更强的同架构模型可当老师：OPD，比 RL 简单得多。
  • 数据固定、就是离线基准：IQL。
  • 吞吐是瓶颈而非算法：先换 Async PPO / 调 GPU 分配模式，别改算法。
