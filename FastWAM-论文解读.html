世界动作模型，执行时还要先“做梦”吗？

外号 ·「练时做梦，用时不做」

多数世界动作模型（WAM）先生成一段未来视频，再根据它出动作。Fast-WAM 把这里面的两件事拆开检验：训练时照样让模型预测未来视频；执行时只把当前画面过一遍视频网络，就直接去噪出动作块。论文的回答是：收益主要来自训练时的视频监督，执行时的想象贡献小得多。

假设

§1WAM 的好处，可能来自两个地方

普通的视觉运动策略直接建模 p(a1:H​∣o,l)：看当前观测 o 和指令 l，输出 H 步动作。多数 世界模型路线的 WAM 在中间插入未来画面 v：

p(a1:H​∣o,l)=∫p(v1:T​∣o,l)p(a1:H​∣o,l,v1:T​)dv1:T​

先想象未来画面，再在想象出的未来上出动作。实现上有两种：视频和动作在同一个模型里一起去噪（Fig. 1A，对应 Joint），或先生成视频、再交给逆动力学模块出动作（Fig. 1B，对应 IDM）。

Fast-WAM 执行时的接口退回普通策略：

pθ​(a1:H​∣o,l)=pθ​(a1:H​∣z(o,l))

z(o,l) 是视频主干对当前上下文的一次前向编码，里面没有采样或去噪未来画面这一步。

论文的出发点是：WAM 的收益可能来自 ① 训练时“预测未来视频”这个目标，它逼主干学会物理动态；也可能来自 ② 执行时显式生成的未来，它给动作提供预见。现有 WAM 两样都做，功劳分不清。论文在同一套骨干、同样的数据和训练步数下搭了四个变体（§3.3）。

变体训练时视频损失执行时生成未来动作读取什么
Fast-WAM有无当前帧的视频特征
Fast-WAM-Joint有视频与动作一起去噪 10 步整段（带噪的）视频
Fast-WAM-IDM有先把视频去噪 10 步，再去噪动作生成好的整段视频
w/o video co-train无无当前帧的视频特征
Q1 答以 Fast-WAM 为中心做两次单变量比较。它和 Joint、IDM 都有视频损失，只差执行时想不想象，差值归给“想象”；它和 w/o video co-train 执行时都不想象，只差训练时有没有视频损失，差值归给“视频监督”。开头那张 2×2 表的右下角是空的：论文没有测“去掉视频损失、却仍然想象”的组合。另外，论文比较的是一次生成一个动作块的设定，没有测把多次想象串成的长时程 rollout（§3.1）。

接线

§3两个专家，一次注意力，谁能看谁

Fast-WAM 是两个 Transformer 拼成的 MoT（Mixture of Transformers）。视频专家是预训练的 Wan2.2 视频 DiT：30 层、宽 3072。动作专家是新加的 ActionDiT：30 层、宽 1024，约 1B 参数。hidden_dim:17 hidden_dim:38

每一层里，两个专家各自用自己的权重算 Q/K/V，拼起来做一次注意力，结果再切回各自的输出投影、文本交叉注意力和 FFN。flash_attention:632 这里没有 MoE 那种给 token 选专家的路由器：视频 token 永远走视频权重，动作 token 永远走动作权重。

能拼在一起，前提是注意力的头数和头宽对齐：两边都是 24 头 × 128。动作专家宽 1024，它的 Q/K/V 投影把 1024 维映射到 3072 维，视频专家是 3072 → 3072。self.q:178 加载时会检查头数和头宽是否一致。num_heads:144

论文没写的一步：动作专家也从 Wan2.2 初始化

配置里的 ActionDiT_linear_interp_Wan22_alphascale_1024hdim.pt 来自 scripts/preprocess_action_dit_backbone.py：它把视频 DiT 的每个权重矩阵用线性插值缩到动作专家的尺寸（3072 → 1024，FFN 14336 → 4096），输入维被缩小的矩阵再乘 √(3072/1024) = √3，让输出量级大致不变。动作编码器和输出头不复制，随机初始化。_interpolate_last_dim:53 alpha:207

三组 token 的读取关系

把 §2 的 326 个 token 分成三组：C（当前帧 98）、F（未来 196）、A（动作 32）。论文 Fig. 2 的注意力 mask 如下（示意），行是“读的一方”，列是“被读的一方”：

读 ↓ 被读 →CFA C 当前帧✓—— F 未来✓✓— A 动作✓—✓

四条规则：

  • A 只读 C 和 A，不读 F；
  • C 只读自己，也不读 F；
  • F 读 C 和 F，用来学“从当前画面往后演”；
  • C、F 都不读 A，视频分支完全不受动作影响。

语言和本体状态不在这张表里，它们走另一条路：每个专家各自对 context 做交叉注意力。

注意力一层只走一步；叠 30 层，任何两三步的路径都会被走通。程序按你的 mask 搜路径，判断三件事。对角线（组内自注意力）固定打开。

    Q2 答注意力是逐层叠起来的。如果只挡 A → F，却让 C 读 F，那么第 1 层 C 吸收了未来的信息，第 2 层 A 再从 C 那里读到，未来就绕道进了动作。实验 1 里点“漏一处”，程序会找出 F → C → A 这条两跳路径。所以 C → F 也必须挡住（video_mask:520）。这条规则还有第二个作用：C 的特征只取决于当前观测，执行时才能删掉 F（见 Q5）。

    训练

    §4两份噪声，两个回归目标

    视频和动作都用流匹配（论文记作 t，代码叫 sigma，这里统一写 σ）：

    yσ​=(1−σ)y+σϵ,LFM​(y)=Ey,ϵ,σ​​fθ​(yσ​,σ,o,l)−(ϵ−y)​22​

    y 是动作块或未来视频的潜变量；σ = 0 是干净数据，σ = 1 是纯噪声；网络要预测从数据指向噪声的速度 ε − y。代码里的目标就是 noise - sample。training_target:59

    一维小例子：某个动作分量真值 y = 0.4，抽到噪声 ε = −1.2、σ = 0.25，于是 yσ = 0.75 × 0.4 + 0.25 × (−1.2) = 0，监督目标 ε − y = −1.6。网络只看到输入 0 和 σ = 0.25，要猜出 −1.6。

    代码写成 λvℒvid + λaℒact，两个系数从配置的 loss 里读，没写就是 1。lambda_video:157 loss_total:603

    Q3 答有两条路。第一，C 和 F 用的是同一套视频专家权重，视频损失更新的权重也就是计算 C 特征的权重。第二，F 在每一层都读 C 的 K/V，视频损失的梯度会沿 F → C 这条注意力流回 C 的表示；动作损失的梯度则沿 A → C 流回。C 的特征同时被“预测未来画面”和“预测动作”两个目标塑造，执行时动作读到的正是它。这和 VLA 的 co-training 是同一类做法：多加一个辅助目标来改善共享表示，只是这里的辅助目标换成了视频预测。

    噪声时间：shift 与钟形权重

    代码不直接采 logit-normal。它先采 u ~ U(0, 1)，再做变换：

    σ=φs​(u)=1+(s−1)usu​

    s 就是 shift。s = 1 时 σ = u；s > 1 时 σ 被推向 1，高噪声样本变多。_phi:18

    每个样本的损失再乘一个钟形权重，两端为 0、σ = 0.5 处最大，并归一化到“在采样分布下均值为 1”：training_weight:39

    w(σ)∝e−2(σ−0.5)2−e−0.5

    “采样密度 × 权重”才是每个噪声水平实际分到的训练量，下图叫它“有效分布”。推理时 u 在 1 到 0 之间等分 10 段，同样经过 φs。u_steps:76

    结论的边界

    • 想象并非没用。真机上 IDM 比 Fast-WAM 高 15 个点，LIBERO 上两个想象变体也都略高。论文的措辞是视频预测的主要价值“may lie”在训练阶段。
    • 设定是单个动作块。论文比较的是一次生成一个动作块的设定；把多次想象串成的长时程 rollout 没有测。
    • 真机只有一个任务，且没有报告样本量。
    • 视频先验仍来自大规模预训练。“无具身预训练”不等于从零训练。

    §10读完做几道题

    1. 训练时如果首帧 token 的时间步不置 0，而是和未来帧一样用 σᵥ，执行时会出什么问题？

      看答案
      执行时首帧的时间步是 0，训练时却带着随机 σᵥ 的时间嵌入，C 的特征在训练和执行时就不再是同一个函数的输出。Q5 里“删掉 F 不影响动作”的论证依赖 C 的输入完全一致，这一条就断了。代码靠 token_timesteps[:, 0, :] = 0 保证一致。token_timesteps:562 回看 Q5

    2. 只挡 A → F、不挡 C → F，未来信息最少经过几层就能到达动作？

      看答案
      两层：第 1 层 C 读 F，第 2 层 A 读 C。网络有 30 层，这条路一定会被走通。回实验 1 点“漏一处”

    3. 如果让视频行可以读动作（C → A 打开），执行时还能缓存首帧 K/V 吗？

      看答案
      不能。C 的特征会随带噪动作变化，而动作每个去噪步都在变，视频专家就得每步重算。视频预测也会依赖动作噪声。回实验 1 点“C 也读 A”

    4. LIBERO 配置里，送进视频专家的未来视频有几个潜在帧、多少 token？

      看答案
      2 个潜在帧，196 个 token；加上首帧共 294 个。9 帧只是采样层的帧数，VAE 时间压 4 倍且首帧单独编码。回 §2

    5. 把 model.loss.lambda_video 设成 0，得到的是哪个变体？它和“执行时不想象”是一回事吗？

      看答案
      得到的是 w/o video co-train 的近似：架构和推理不变，只少了视频损失。“执行时不想象”是 Fast-WAM 本来就有的推理方式，λ = 0 改的是训练目标。这正是论文要分开的两个变量。回看 Q1 lambda_video:157

    6. Joint 的视频专家工作量是 Fast-WAM 的多少倍？为什么实测延迟只差约 3 倍？

      看答案
      每次调用 294 × 10 = 2940 对 98 × 1，即 30 倍，与分辨率无关。实测 580 / 190 ≈ 3.05 倍，说明 Fast-WAM 的 190 ms 里有不少开销与未来视频无关，比如动作专家的 10 步、VAE 和文本编码。回实验 3

    7. 动作 shift 从 5 改成 1 以后，10 步推理的 σ 序列怎么变？

      看答案
      shift 5：1、0.978、0.952、0.921、0.882、0.833、0.769、0.682、0.556、0.357、0，前面步子很小，最后一步跨 0.357。shift 1：每步均匀降 0.1。回实验 2

    8. 真机实验能说明“执行时想象没用”吗？

      看答案
      不能。真机上 IDM（90%）高于 Fast-WAM（75%），有预训练的 π0.5 是 100%。论文能支持的是：去掉视频监督的影响（75% → 10%）远大于去掉想象的影响。回 §6
