SmolVLA：小而快的开源 VLA

外号 · 「半脑小钢炮」只用半个 VLM，0.45B，消费级显卡就能跑

一个 0.45B 参数的 VLA：只取 SmolVLM2 的前一半层做感知，后面接一个窄而浅的流匹配动作专家。它用社区采集的数据预训练，单卡能训，消费级 GPU 就能跑，还配了一套异步推理。

论文SmolVLA: A Vision-Language-Action Model for Affordable and Efficient Robotics
机构Hugging Face（LeRobot 团队）等
arXiv2506.01844
规模0.45B（另有 0.24B / 2.25B 对照）
代码lerobot/policies/smolvla
主题轻量化 · 流匹配 · 异步推理

它解决的问题

主流 VLA（OpenVLA 7B、π0 3.3B）都有十亿级参数。训练贵，部署也难，在 SO-100 这类几百美元的机械臂旁边几乎跑不起来。另一头，社区里有大量用低成本机械臂采的小数据集，却没人拿来预训练。

SmolVLA 同时回答两件事：

  • 模型能不能小？砍掉 VLM 一半层、压缩视觉 token、把动作专家做窄，换来更低的训练与推理成本。
  • 数据能不能散？只用 481 个社区数据集（22.9K 条轨迹，10.6M 帧）预训练，比同类工作小一个数量级。

另外它把“算动作”和“执行动作”拆开，提出异步推理，让机器人在等下一块动作时不用停下。

整体架构

一句话：VLM 读一遍场景并把每层的 K/V 存起来，动作专家反复读这份缓存，把噪声一步步去成一整块动作。

图 1 · SmolVLA 的推理路径。左半边只跑 1 次，右半边的专家与欧拉循环跑 10 次。形状和默认值取自 configuration_smolvla.py 与 modeling_smolvla.py。点击任一方块，跳到它的子架构图（模块目录）。想把所有图放在一起看，见全景图。

和 π0 的关键区别：π0 里动作专家与 PaliGemma 逐层做联合注意力，两边层数相同；SmolVLA 只取 VLM 的前一半层，专家还把联合注意力换成“一层自注意力、一层交叉注意力”交替。两处改动都是为了省算力。

1 · 图像预处理

每个相机单独处理，对应 SmolVLAPolicy.prepare_images。补边补在左侧和上侧（resize_with_pad，smolvla 的约定，代码文档说明 openpi 用的是居中补边）。补的值是 0，乘 2 减 1 之后变成 −1。

掩码来自 {相机名}_padding_mask，没有就全真。empty_cameras 默认是 0，也就是缺哪个相机就少哪个，不补假图。一个相机都没有会直接报错。

↑ 回总图 · 下一个：视觉编码 →

2 · 视觉编码：SigLIP + 像素重排

视觉部分整体冻结（freeze_vision_encoder=True）。每个相机各过一次。后两步是 SmolVLM 自带的 connector：把相邻的 4×4 个 patch 拼成一个 token，再线性投影到文本宽度 960。

乘 √960 是把图像 token 放大约 31 倍。语言词嵌入在代码里也乘同一个数（modeling_smolvla.py 的 embed_image 和 embed_language_tokens），所以图像和语言的数值大小相近。这是 Gemma 一类模型的惯例。论文里我没找到对图像这一步的解释，“为了和语言同量级”是我对照代码的读法。

SmolVLM 默认还会把大图切成多块再加一张全局图。SmolVLA 不切块，只用全局图，所以 3 个相机总共 192 个视觉 token。

3 · 语言编码

预处理流水线先给任务文本补换行，再用 SmolVLM2 的分词器切成 token，最后查词嵌入表。词嵌入属于冻结的 VLM。

↑ 回总图 · ← 上一个：视觉编码 · 下一个：状态编码 →

4 · 状态编码：state_proj

机器人关节状态先按数据集统计量做 MEAN_STD 归一化（在预处理流水线里），进模型后补零到 32 维，再用一层线性映射成 1 个 token。这一层是可训练的。状态是传感器读到的“现在”，动作是模型预测的“接下来”。两者是同一种数（同单位、同归一化），含义不同。

↑ 回总图 · ← 上一个：语言编码 · 下一个：prefix 拼接 →

5 · prefix 拼接与注意力掩码

embed_prefix 把三种 token 按固定顺序拼在一起：各相机的图像 token，语言 token，最后是 1 个状态 token。同时生成两种标记，一种说明哪些位置有效（pad_masks），一种说明谁能看谁（att_masks）。

图像和语言的 att 都是 0，累计值相同，所以彼此双向可见。状态的 att 是 1，累计值更大：它能看到图像和语言，图像和语言看不到它。动作 token（att 全为 1）在后面接上，见图 3。prefix_length 默认 −1，不额外补长。

↑ 回总图 · ← 上一个：状态编码 · 下一个：VLM 文本层 →

6 · VLM 文本层（SmolVLM2，前 16 层之一）

这是一个标准的 Llama 式解码层，宽度 960。预填充时只有 prefix 在这里流动，每层算出的 K、V 被存进缓存。冻结，不参与训练。

注意力是分组式的：15 个 Q 头共用 5 组 K/V，每组 3 个头，头维度 64。预填充时 K、V 在加完 RoPE 之后被写进缓存，见下一节。训练时 prefix 和动作 token 在同一次前向里一起走，不经缓存。

↑ 回总图 · ← 上一个：prefix 拼接 · 下一个：KV cache →

7 · KV cache：写一次，读十次

缓存用的是 transformers 的 DynamicCache，16 层各有一格，存 K 和 V。预填充时写满，之后 10 步去噪都只读。

按我的估算（P = 241、bf16），每层 K 加 V 约 0.3 MB，16 层合计约 5 MB 每个样本。这是算式结果，没有实测。

SA 层会把动作 token 的 K、V 追加到缓存末尾，所以每个去噪步结束后，代码用 past_key_values.crop(prefix_len) 裁回去，否则下一步缓存里就混进了上一步的动作。

↑ 回总图 · ← 上一个：VLM 文本层 · 下一个：噪声与时间 →

8 · 噪声动作与时间 τ

训练和推理拿到 x_τ 的方式不同。训练时把真实动作和噪声按 τ 混合；推理时从纯噪声出发，τ 从 1 逐步降到 0。模型从不直接拿到“真实的未来动作”当输入：训练时输入的是加噪后的版本，真值只用来算目标 u；推理时真值根本不存在。

Beta(1.5, 1) 的密度随 τ 增大而上升，所以训练更常见到噪声多的样本。怎样理解这种时间步采样，见噪声时间步采样。

↑ 回总图 · ← 上一个：KV cache · 下一个：动作入口 →

9 · 动作入口：action_in_proj 与时间 MLP

噪声动作先映射到专家宽度 720。时间 τ 用正余弦编码成 720 维向量，复制 50 份，与动作嵌入沿特征维拼起来，再过两层 MLP 融合。这与 π0 的做法一致；π0.5 才改用 adaRMSNorm 注入时间。

时间编码的周期按几何级数分布在 4e-3 到 4.0 之间（min_period、max_period），τ 的范围是 (0, 1]，所以快慢两种频率都有。

↑ 回总图 · ← 上一个：噪声与时间 · 下一个：动作专家 →

10 · 动作专家：16 层，交替两种注意力

专家是一个窄的 Llama 式模型：宽度 720，MLP 中间宽度 2048，同样 15 个 Q 头、5 组 K/V、头维度 64。它没有词嵌入和输出词表，输入输出都是连续向量。每一层要读 VLM 缓存里同序号那一层。

偶数层（0、2、…、14）是自注意力，奇数层（1、3、…、15）是交叉注意力，由 self_attn_every_n_layers=2 决定。点上图的层，进入对应的内部结构。

↑ 回总图 · ← 上一个：动作入口 · 下一个：专家自注意力层 →

11 · 专家的自注意力层（SA，偶数层）

动作 token 的 Q 去看两部分 K/V：缓存里的 prefix，以及它们自己刚算出的 K/V。位置编号接在 prefix 之后（prefix 有效长度 + 0…49），所以动作像是“续写”在场景后面。

掩码由两块拼成：每个动作 token 对 prefix 全部可见，对动作之间是下三角（因果）。这一层是专家里唯一让动作 token 互相交流的地方，论文认为它让动作块更平滑。

↑ 回总图 · ↑ 回动作专家 · 下一个：专家交叉注意力层 →

12 · 专家的交叉注意力层（CA，奇数层）

Q 来自动作 token，K 和 V 来自 VLM 缓存（每个 token 320 维）。专家用自己的 k_proj、v_proj 把它们再投影一次，仍是 320 维。这两个投影只在 CA 层里存在，是新建并训练的。

一个值得留意的细节，是我读代码得到的观察：动作 token 的 q 位置从 0 开始（代码里把位置减去最小值），而缓存里的 K 保留着 prefix 里的原始位置。两者的相对位置因此不对应真实的先后关系。我没有在论文里找到对此的说明，是否有影响没有验证。

↑ 回总图 · ↑ 回动作专家 · ← 上一个：专家自注意力层 · 下一个：输出头与欧拉积分 →

13 · 输出头与欧拉积分

推理的外层循环。每一步用当前的 x 和 τ 算出速度 v，再向 τ 减小的方向走一小步：x ← x + dt·v，dt = −0.1。10 步走完，τ 从 1 到 0，x 就从噪声变成动作块。实现在 euler_integrate，约定噪声在 τ = 1。

SmolVLA 的 VLM 前缀只在循环之外跑 1 次，循环里只有动作入口、专家和输出投影。想让相邻两块动作衔接平滑，可在这个循环里挂 RTC 的引导（rtc_processor）。

↑ 回总图 · ← 上一个：专家交叉注意力层 · 下一个：后处理与动作队列 →

14 · 后处理与动作队列

这是 select_action 的经典路径：整块动作先进队列，每个控制周期取队首一个，取出之后才反归一化（后处理器作用在单个动作上）。

四个省算力的设计

① 只用 VLM 的前一半层

论文的依据是：下游任务的最佳特征不一定在最后一层。动作专家只读到第 N 层，取 N = L/2。代码里就是把 text_model.layers 截到前 num_vlm_layers=16 层。专家层数默认与之相同（num_expert_layers=-1），所以 VLM 和专家的计算量一起减半。

论文的消融（LIBERO 平均成功率）：N=8 为 75.0，N=16 为 78.5，N=24 为 79.5，N=32 为 80.3。对同一个 500M 的 VLM，保留前 16 层（78.5）比直接换成更小的 256M VLM（75.8）略好。

② 每张图只留 64 个 token

SmolVLM 默认会把图切成多块再加一张全局图。SmolVLA 不切块，只用全局图，再用像素重排把 1024 个 patch 压成 64 个。三个相机总共也只有 192 个视觉 token。

③ 窄而浅的动作专家，交替两种注意力

专家宽度是 VLM 的 0.75 倍（960 → 720）。每一层专家按序号交替：

图 2 · 专家 16 层的排布。self_attn_every_n_layers=2 决定了 SA / CA 的交替。

层类型QueryKey / Value可见范围
SA（偶数层）动作 tokenprefix 的 K/V，接上动作 token 自己的 K/V看完整 prefix；动作之间因果
CA（奇数层）动作 token只用 VLM 缓存的 K/V，再过专家自己的 k_proj / v_proj 重投影（320→320）只看 prefix，不看其他动作 token

论文的结论是：只用 SA 不如只用 CA，两者交替最好。它认为 SA 让动作块更平滑，真机上尤其明显。

④ 动作 token 之间用因果掩码

每个动作 token 只能看它前面的动作，不能看后面的。掩码由 make_att_2d_masks 按“累计 1 的个数”生成：图像和语言标 0，状态标 1，50 个动作 token 全标 1。

图 3 · 注意力掩码。图像和语言看不到状态与动作，所以 VLM 的特征不会被动作“污染”，缓存才能复用。论文的消融：因果 74.5，双向 67.5（LIBERO 平均）。

训练方式

训练的是一个标准的条件流匹配目标：给定观测，预测把噪声带回真实动作块的速度。

τ  ~ Beta(1.5, 1) × 0.999 + 0.001      # 偏向噪声多的一端
ε  ~ N(0, I)                            # 形状 (B, 50, 32)
x_τ = τ·ε + (1 − τ)·a                   # 代码约定：噪声在 τ = 1
u   = ε − a                             # 回归目标
loss = MSE( v_θ(x_τ, τ, 观测), u )      # 只算真实动作维度，剔除越过回合末尾的步

时间采样用的是 π 系列的做法，参见噪声时间步采样。论文里印的插值式是 A^τ = τA + (1−τ)ε，目标却写成 ε − A，两者方向对不上。这是我的读法：以代码的 NOISE_AT_ONE 约定为准，它前后自洽。

预训练与微调的数字

  • 预训练：200k 步，全局批大小 256，481 个社区数据集。学习率 1e-4，预热 100 步，余弦衰减到 2.5e-6，AdamW（β=0.9, 0.95）。
  • 社区数据的清洗：用 Qwen2.5-VL-3B 重写含糊的任务描述；把相机统一重命名为 camera1/2/3（顶部、腕部、侧面）。
  • 微调：官方文档建议先采约 50 条演示，在单张 A100 上训 20k 步约 4 小时。
  • 代码里的默认值：学习率 1e-4，预热 1000 步，衰减 30000 步，梯度裁剪 10，权重衰减 1e-10。与论文预训练设置不同，是微调预设。

推理：一次缓存，十次去噪

  1. 预填充：图像、语言、状态拼成 prefix，过 VLM 前 16 层，每层的 K/V 存进 DynamicCache。KV Cache 只在这一步算一次。
  2. 采噪声：x 取自标准正态，形状 (B, 50, 32)。
  3. 去噪 10 次：每次只让动作专家跑一遍，读缓存里的 prefix K/V，预测速度 v，用欧拉积分更新 x。SA 层会往缓存里追加动作 K/V，每步结束后用 crop(prefix_len) 裁回去。
  4. 后处理：裁掉补零维，反归一化，推入动作队列。队列放满 n_action_steps=50 步，用完才再推理。

代价分布很清楚：厚重的 VLM 前缀只跑 1 次，每步去噪只跑又窄又浅的专家。这也是它在小显卡上能跑的原因。想做平滑衔接可以打开 RTC。代码里 select_action 不支持 RTC，要走 predict_action_chunk。

异步推理

同步执行时，机器人要把整块动作做完，才取下一帧观测去推理。推理期间机器人空等，这段时间里世界也在变。感知—执行时延就是这样来的。

论文的做法是把预测和执行拆开：

图 4 · 同步与异步。异步时推理不占用控制循环。

  • 机器人端（RobotClient）把观测发给策略服务器（PolicyServer）。服务器可以是带 GPU 的远端机器。
  • 当本地队列长度与块长度之比低于阈值 g 时，提前触发下一次预测，不阻塞控制循环。
  • 新旧队列重叠的部分按函数 f 聚合。观测变化很小时可以跳过推理（相似度过滤）。

LeRobot 现在的实现不专属 SmolVLA：src/lerobot/remote_inference/ 放服务器与客户端，src/lerobot/inference/ 放引擎，后端有 sync、rtc、remote 三种，传输层是 Zenoh。我只通读了它的设计文档，没有逐行读实现。

我真正学到的内容

  • 规模不是唯一杠杆。0.45B 的模型在 LIBERO 上追平 3.3B 的 π0。省出来的算力来自砍层、压 token、做窄专家。
  • 缓存让“多步去噪”变得便宜。VLM 只跑 1 次，专家跑 10 次。流匹配或扩散类动作头想省推理时间，先看能不能把条件编码缓存起来。
  • SA 和 CA 的分工。CA 负责“读场景”，SA 负责“让动作块自己连贯”。把二者交替，比选其一都好。
  • 数据质量处理很朴素。重写任务描述、统一相机顺序。论文明确说统一相机顺序对这种数据量的预训练有益；任务描述重写没有给出单独的消融。
  • 异步推理是系统层的收益。它和模型结构无关，别的分块策略（如 时序集成）也能用。

可复用设计

  • VLM 取中间层特征。换别的 VLM 时，先用“截到前 N 层”的小实验定 N，别默认用最后一层。
  • 每个动作维度都补零到固定宽度（32）。一个检查点可以对接不同本体，推理时再裁回真实维度。多构型的思路见 跨本体。
  • 缺失相机用“全 −1 图像 + 掩码 0”占位。一个检查点可接受不同数量的相机。
  • 专家的 K/V 投影重新训练。CA 层把 VLM 的 K/V 当输入再投影，这样专家宽度可以和 VLM 不同。

疑问与风险

  • 从零训练的陷阱。配置里 load_vlm_weights 默认是 False。官方的 LIBERO、Meta-World 等文档在从头训时都显式加了 --policy.load_vlm_weights=true，代码在 False 且用 PEFT 时也会告警。用 --policy.type=smolvla 从头开训却漏掉这一项，VLM 就是随机初始化，又被冻结。这是我读代码得到的判断，没有实际跑过。
  • 真机样本小。SO-100 只有三个任务，π0 在抓放上是 100，SmolVLA 是 75。每项任务的试验次数请去原文附录核实，我没有核实。
  • 社区数据偏窄。主要是 SO-100 / SO-101 这类低成本机械臂。能否迁移到高精度、力控的场景，论文没有证据。
  • 代码注释与配置不一致。prepare_images 的文档字符串写“缩放到 224×224”，实际按配置缩放到 512×512。以配置为准。
  • 异步推理的安全边界。LeRobot 文档明确说它不是硬实时控制器，相机、执行器调用仍可能拖慢控制周期。
