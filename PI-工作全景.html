Physical Intelligence（π）的工作全景

Physical Intelligence 发布的每项工作，都按一句话 → 怎么做 → 解决了什么 / 留下了什么 → 下一步来写。每一项都是在接上一项留下的问题，顺着往下读就能串成一条线。总体时间线见 VLA 发展史，同类对照见 Google / DeepMind 线。

先记住这条主干

π0 底座→π0.5 开放世界→π*0.6 从经验学→π0.7 可操控

其余工作都是给这条主干补短板，可以分成三组：

  • 动作怎么出得又好又快：FAST（训练快）→ 知识隔离（不伤 VLM）→ RTC / 训练时 RTC（执行不卡）。
  • 怎么听懂人：Hi Robot（分层理解复杂指令）→ π0.5 把分层合进一个模型 → π0.7 用元数据控制"怎么做"。
  • 数据和改进从哪来：openpi 开源 → RECAP（自己的经验）→ 人类视频迁移 → RL Token（几分钟的在线精修）。

2024

打底座：VLM + 动作专家

公司成立后的第一个模型，先回答一个问题：能不能有一个通用底座，同时具备 VLM 的常识和灵巧的连续控制？

π0模型

2024.10 · arXiv 2410.24164 · 本库精读

一句话：给 VLM 接一个会"画"连续动作的小网络，一次输出一整段动作。

  • 骨干是 PaliGemma 3B（VLM），另接一个约 300M 参数的动作专家；两者在同一个 Transformer 里通过注意力交互。
  • 动作专家用 flow matching 从噪声出发，经少量去噪步骤生成连续动作，一次输出 50 步的动作块，控制频率可到 50Hz。
  • 预训练数据包括约 1 万小时、7 种机器人构型的自采数据，加上 OXE；之后再用高质量数据做后训练。

解决了 RT-2/OpenVLA 那种"动作当文字"的路线又慢又粗的问题，能叠衣服、收桌子；留下的问题：动作专家是新加的、没有预训练，训练慢，还可能破坏 VLM 原本的知识。

→ FAST 想：能不能把连续动作也压成好用的 token？

2025 上半年

听得懂、训得快、走进陌生的家

围绕 π0 的三个短板展开：训练效率（动作 token）、复杂指令（分层）、开放世界泛化（异构数据混训）。

FAST / π0-FAST动作

2025.01 · arXiv 2501.09747 · 本库精读 →

一句话：像压缩 JPEG 一样压缩动作，让自回归 VLA 也能学高频灵巧动作。

  • 对一段动作的每一维做 DCT（离散余弦变换），把轨迹变成频率系数，量化后只保留主要成分。
  • 再用 BPE 把系数合并成少量 token，比"每步每维一个 bin"短得多、冗余少得多。
  • 训练出 π0-FAST：自回归输出 FAST token，再解码回连续动作。

训练速度约为扩散/flow 版的 5 倍，并且在高频任务上首次让 token 路线追上 π0；代价是推理时要逐 token 生成，比 flow 慢。

→ 后续的 π0.5 和知识隔离都把 FAST token 用作"训练骨干的信号"。

openpi 开源生态

2025.02 · GitHub

一句话：把 π0、π0-FAST 的权重和微调代码公开，后来又加入 π0.5。

  • 提供 base checkpoint，以及在 DROID、ALOHA、LIBERO 等数据上微调好的版本。
  • 提供 JAX 训练和推理代码，后来也支持 PyTorch；可以用 LoRA 微调到自己的机器人上。

让学术界第一次能直接拿到 flow-matching VLA 的权重，πRL、RLinf 等后续开源工作都建立在它上面。

→ 对比 OpenVLA 的路线可见 OpenVLA vs π 系列。

Hi Robot交互

2025.02 · arXiv 2502.19417

一句话："慢脑"先把复杂指令和用户插话想成下一步简单指令，"快脑"π0 去执行。

  • 高层 VLM 看图像和用户的话（如"做个素三明治""那个不是垃圾"），输出下一步的原子指令，必要时也回复用户。
  • 低层 π0 只执行"拿起面包"这类简单指令。
  • 高层的训练数据来自合成：给已有机器人片段配上人可能说的复杂指令和插话。

让机器人能处理开放式指令和执行中途的纠正，在单臂、双臂、移动双臂三种平台上验证；但需要两个模型。

→ π0.5 把"想下一步"和"做动作"合进同一个模型。

π0.5模型

2025.04 · arXiv 2504.16054 · 本库精读

一句话：多种数据混在一起训，一个模型先说出子任务、再做动作，在没见过的家里收拾房间。

  • 混训数据：多种机器人数据、网页图文数据、高层子任务标注、口头指令。
  • 推理时同一个模型先输出子任务文字（如"拿起盘子"），再由动作专家输出连续动作，相当于把 Hi Robot 的分层放进一个模型。
  • 预训练阶段用 FAST 离散 token，后训练阶段加入 flow 动作专家。

第一次在训练时完全没见过的真实家庭里完成收厨房、整理卧室等长任务；留下的问题：只靠示范数据，做得不够快、不够稳，也不会从自己的失败中学。

→ 知识隔离解释"为什么要先用离散 token 训"；π*0.6 让它从经验中学。

知识隔离（Knowledge Insulation）动作

2025.05 · arXiv 2505.23705

一句话：别让新加的动作专家把 VLM 的知识"冲掉"。

  • 发现：直接把随机初始化的动作专家接到 VLM 上训练，梯度会回传进骨干，拖慢训练、损伤语义知识。
  • 做法：阻断动作专家流向骨干的梯度；骨干改用 FAST 离散动作 token 和网页数据来训练。
  • 推理时仍然用动作专家输出连续动作，保持速度。

同时拿到"训练快（token）、跑得快（flow）、泛化好（保住 VLM 知识）"，成为 π0.5 之后的标准训练配方。

→ 解决了训练问题，接下来是部署时的延迟问题。

2025 下半年

跑得顺、从经验中变强

模型能做事以后，问题变成：推理延迟导致动作卡顿；只靠模仿，成功率和速度到不了实用水平。

实时动作分块（RTC）动作

2025.06 · arXiv 2506.07339

一句话：边执行当前动作块边算下一块，并让两块无缝衔接。

  • 异步执行：机器人执行当前动作块时，模型已经在算下一块。
  • 推理期间必然会执行的那几步动作被"冻结"，其余部分用 inpainting（补全）方式生成，保证与已执行动作连贯。
  • 只在推理时修改，不需要重新训练，适用于任何扩散/flow VLA。

消除块与块之间的停顿和抖动，即使延迟很大也能完成划火柴这类精细任务；代价是推理时的补全带来额外计算。

→ 训练时 RTC 把这部分开销去掉。

π*0.6 / RECAPRL

2025.11 · arXiv 2511.14759 · 本库精读

一句话：把"这个动作比平时好还是差"作为条件喂给模型，用监督学习完成 RL。

  • 训练一个价值函数，评估每段经验离成功还有多远，据此算出优势（advantage）。
  • 把"优势好/坏"作为一个二元条件放进输入，正常地做监督学习；推理时始终条件化为"好"，即可得到改进后的策略。
  • 数据来自三种：示范、自主执行（包括失败）、人工干预纠正；循环迭代。

不依赖难以用于大模型的策略梯度，就让 VLA 从自己的经验中学习；在做咖啡、叠衣服、组装纸箱上吞吐量提升约一倍以上，并能连续运行数小时。

→ 继续往两个方向走：更可操控的通用模型（π0.7）、更快的局部精修（RL Token）。

训练时 RTC动作

2025.12 · arXiv 2512.05964

一句话：训练时就模拟推理延迟，让模型学会接着已执行的动作往下写。

  • 训练时随机模拟一段延迟，把动作块的前缀设为"已经确定"的真实动作，只学习生成剩余部分。
  • 推理时直接把已执行的前缀作为条件，不再需要 inpainting。
  • 不改模型结构和机器人运行时，只需要几行代码。

在 π0.6 上做纸箱、做咖啡，效果和推理时 RTC 持平，但计算更省；在延迟较大时表现更好。

人到机器人的迁移数据

2025.12 · arXiv 2512.22414

一句话：机器人预训练足够多样以后，"看人做"的视频就能直接教会机器人。

  • 用简单的混训配方，把人类第一视角视频和机器人数据一起训练，不做专门的人-机映射工程。
  • 对比不同预训练规模：数据少时人类视频几乎没用，场景、任务、本体足够多以后迁移才"涌现"。
  • 分析发现，多样化预训练让人和机器人数据的表示变得与本体无关。

在只出现在人类数据里的泛化场景上，性能接近翻倍，为"用便宜的人类视频扩充数据"提供依据。

2026

可操控的通才 + 快速精修

两个互补的方向：让大模型"听话地按指定方式做"，再用小网络把最后几毫米做准。

π0.7模型

2026.04 · arXiv 2604.15483 · 本库精读

一句话：不只告诉模型"做什么"，还告诉它"怎么做、做到多好"。

  • 5B 参数。训练时的上下文除了任务和子任务指令，还包括子目标图像、episode 元数据（速度、质量、是否出错）、控制模式。
  • 因此可以用质量好坏不一的数据训练，推理时再把元数据设为"高质量、快"。
  • 带来组合泛化：不做任务特定微调，就能执行训练中各技能的新组合。

把"数据质量参差不齐"从问题变成可控的条件，开箱表现接近甚至超过此前各任务的专用微调模型。

RL TokenRL

2026.04 · arXiv 2604.23073 · 本库精读

一句话：冻结大 VLA，让它吐出一个小表示和参考动作，只训练小网络做在线 RL。

  • VLA 冻结不动，输出一个压缩的状态表示（RL token）和一个参考动作块。
  • 只训练一个轻量的 actor-critic，在参考动作附近做局部修正，而不是从零探索。
  • 在真机上用几分钟到几小时的在线 RL，把毫米级插拔、拧螺丝等精细操作做得更快、更准。

同时拿到 VLA 的泛化和小模型 RL 的样本效率；局限是只能在 VLA 已经会做的动作附近精修。
