π0.5：一个模型先说再做，在没见过的家里收拾房间

结构几乎还是 π0，变的是训练配方：五类数据混训，先把动作当文字和网页数据一起训成"懂机器人的 VLM"，再接 动作专家做连续动作；推理时同一个模型先说出子任务，再以它为提示词出动作。本页同时给出对照 openpi 源码的架构图和代码结构。

一句话：π0.5 的网络结构基本就是 π0，真正变的是训练配方：先把动作当文字、和网页数据一起把 VLM 训成"懂机器人的 VLM"，再接一个动作专家做连续动作；推理时同一个模型先说出下一步该做什么，再把它当提示词出动作。论文反复证明的一件事是：97.6% 的预训练数据不是目标机器人的家务数据，泛化靠的是这些"别的数据"。

问题：VLA 为什么"换个家就不行"

π0 之前的 VLA 大多在和训练数据相同的环境里评测。真正进一个陌生的家，三件事同时变化：环境（布局、光线、柜门把手的样式）、物体（没见过的碗、衣服、玩具）、任务长度（"收拾厨房"要先拉抽屉、再拿盘子、再放进水槽，持续几分钟）。单靠目标机器人的数据来覆盖这些变化不现实：论文只有约 400 小时、约 100 个家的移动操作数据。

  1. 环境和物体的多样性要从别的来源借：更轻、更容易搬进不同家庭的固定机械臂（ME）；实验室里各种机器人做各种任务的数据（CE）；以及网页图文（WD）里关于"物体是什么"的常识。
  2. 长任务要有结构：先决定"下一步做什么"，再决定"手怎么动"。以前通常是两个模型（一个 LLM 规划 + 一个底层策略，见 Hi Robot），π0.5 想用一个模型同时做这两层。
  3. 训练效率：数据种类越多，训练越贵。FAST 已经证明把动作当 token 训比 flow 快得多，但推理慢；需要一个"训练时离散、推理时连续"的办法。

所以 π0.5 要同时解决三件事：怎么混数据、怎么分层、怎么又训得快又推得快。下面三节分别对应。

分层推理：一个模型，先说再做

模型表示的是联合分布 π(at:t+H, ℓ̂ | ot, ℓ)：o 是所有相机图像加本体状态，ℓ 是总指令（"把盘子放进水槽"），ℓ̂ 是模型自己输出的文字（子任务，或者 VQA 的答案），a 是动作块。论文把它拆成两步（Sec IV-A）：

π(a, ℓ̂ | o, ℓ) = π(a | o, ℓ̂) · π(ℓ̂ | o, ℓ)　——　动作分布只依赖子任务 ℓ̂，不直接依赖总指令 ℓ。

① 高层：π(ℓ̂ | o, ℓ)看 4 路相机 + 总指令，自回归解码出一句子任务文字，比如 "pick up the cup"。这一步和 VLM 回答问题是同一个输出口，所以网页 VQA 数据直接帮到它。
② 低层：π(a | o, ℓ̂)把子任务文字当提示词，看腕部 + 前置相机和状态，由动作专家 10 步 flow matching 出 50 步动作。它从来不看总指令。
③ 训练来源MM / ME / CE 里多阶段的任务都人工标了子任务；训练时同一条数据既学"预测子任务文字"，也学"给定子任务出动作"。还标了目标框，让模型先说出相关物体在哪、再说子任务。

这和 LLM 的思维链是同一个思路：先把"收拾卧室"翻译成"整理毯子""捡起枕头"，动作策略只需要会做这些短而具体的事。反直觉的实验结果（Sec V-E，Fig 13）：全模型比"人当高层指挥"（human HL）还好；而不做高层推理、只是把子任务数据放进训练（implicit HL）是第二名，已经拿到大半收益；完全不放子任务数据（no HL）明显变差；用 GPT-4 零样本当高层最差。

两阶段训练：先把动作当文字训，再接动作专家

联合损失（Eq. 1）只有两项：

E[ H(x1:M, fℓ(o, ℓ)) + α · ‖ ω − at:t+H − fa(aτ,ω, o, ℓ) ‖² ]

第一项是所有文字 token 的交叉熵——子任务、VQA 答案、目标框坐标，以及 FAST 编码的动作 token，它们都是 PaliGemma 词表里的 token。第二项是动作专家的 flow matching 损失，α 控制它的权重。整个配方就是在两个阶段给 α 取不同的值：

预训练（Pre-training）后训练（Post-training）
α0：没有动作专家，模型就是一个标准的自回归 VLM10.0：加入随机初始化的动作专家，两项一起优化
步数280k 梯度步80k 梯度步
动作怎么表示全部用 FAST 离散 token，当下一个 token 预测FAST token 继续训（保住文字能力），同时用 flow matching 训连续动作
数据MM + ME + CE（含 OXE）+ HL + WD，所有任务一视同仁MM + ME 里成功且不太长的片段 + WD + 多环境的 HL + 口头指令 VI；去掉实验室 CE，聚焦家务
目的便宜、稳定地把各种知识装进 VLM专门化到移动操作，并装上能实时推理的动作头
  • 为什么预训练不用 flow：FAST 论文证明离散 token 训练在算力上高效得多（本文 Fig 12：π0 训到 300k 步仍不如 π0.5）；而且动作和文字共用一个输出口，VLM 的语言能力不会被一个随机初始化的动作头的梯度冲掉——这个问题后来在知识隔离里被单独研究。
  • 为什么推理不用 FAST：自回归解码几十个 token 要走 2B 主干几十次，约 750ms 一块；flow 动作专家 10 步约 100ms。
  • 两种动作表示互不相见：注意力掩码让 flow 的动作 token 不看 FAST token，反之亦然（Appendix E，Fig 18），避免一种表示"抄"另一种的答案。
  • 口头指令 VI 是什么：专家在机器人旁边，用语言实时"遥操作"已训练好的低层策略——每次说一句子任务、看机器人做完再说下一句。这样采到的是"好的高层决策"示范。它只占高层数据的约 11%，但去掉后性能显著下降（Fig 13）。
  • 动作空间统一：所有动作按各自数据集的 1% / 99% 分位数归一化到 [−1, 1]，统一到最大维度（代码里是 32 维），维度不够的补 0；关节控制和末端控制用提示词里的 <control mode> 区分。

机器人与推理回路

  • 两种移动操作平台：都有两条 6 自由度手臂 + 平行夹爪、腕部相机，一个前置和一个后置相机，全向轮底盘（线速度 2 维 + 角速度 1 维），升降躯干（1 或 2 维）。状态和动作空间共 18 或 19 维。
  • 相机分工：高层推理用全部 4 路相机；低层出动作只用两只腕部 + 前置相机。
  • 控制：模型以 50Hz 直接给出手臂、夹爪、躯干的目标位姿和底盘目标速度（带动作分块），由简单的 PD 控制器跟踪。没有轨迹规划，没有碰撞检测，导航和操作全部端到端。
  • 一轮推理：拍 4 路图 → 解码子任务文字 ℓ̂ → 以 ℓ̂ 为提示词、拍腕部 + 前置图 → 10 步去噪得到动作块 → 执行。

3weight_loaders.py · CheckpointWeightLoader ↗ · train.py · init_train_state ↗加载预训练参数并和当前模型形状合并；按 freeze_filter 决定哪些参数可训（LoRA 时只训 LoRA）
4train.py · train_step ↗调 model.compute_loss（flow matching 损失）→ 梯度裁剪 → AdamW → EMA；记录 loss 和梯度范数
5pi0.py · compute_loss ↗采 τ ~ Beta(1.5, 1)，构造 x_t，一次前向前缀 + 后缀，只对后 50 个输出算 MSE

论文里的预训练（FAST token + 子任务 + VQA，α=0）和后训练（α=10）在 openpi 里都没有对应代码；pi05_base 就是官方后训练完成后的权重，用户只能从它开始微调。更多概念到源码行的对应见 代码索引。

关键结果

1. 真的能进没见过的家（Sec V-A，Fig 7）

在训练集之外的 3 个真实厨房、3 个真实卧室里，用两种机器人做"物品放进抽屉""衣服放进洗衣篮""餐具放进水槽"，每个任务 2–5 分钟、多个阶段，只给一句总指令。各家各任务的平均完成度都比较高，且和 mock 环境里的分数接近——说明 mock 评测能代表真实表现。

2. 泛化随"见过多少个家"增长（Sec V-B，Fig 8–9）

把移动操作数据按地点切成 3 / 12 / 22 / 53 / 82 / 104 个家，固定训练步数（40k）后训练。完成度和语言跟随率都随地点数稳步上升；到 104 个家时，和一个直接在测试家庭数据上训练的模型表现相当。反过来，不走预训练配方、只用 104 个家或测试家庭数据直接训，都差很多——别的数据源是必要的。分布外物体的语言跟随提升得比分布内慢，但也在涨。

3. 每类数据各管什么（Sec V-C，Fig 10–11）

去掉完成度（mock 家）语言跟随
ME（多环境固定臂）显著下降显著下降
CE（实验室跨本体）显著下降显著下降
ME + CE下降更多下降更多
WD（网页图文）差异不显著分布外物体明显变差；高层推理也显著变差（Fig 13）

跨本体数据的收益来自两方面：ME 带来别的环境，CE 带来别的任务。网页数据管的是"认识没见过的东西"和"决定下一步做什么"。

4. 对比 π0 和 π0-FAST+Flow（Sec V-D，Fig 12）

同样的机器人数据、相近的步数：π0.5 显著好于 π0；也显著好于"用 Eq. 1 的混合配方、但只用动作数据训"的 π0-FAST+Flow。π0 多训到 300k 步仍追不上，印证 FAST 论文的结论：离散 token 训练在算力上更高效。π0.5 比 π0-FAST+Flow 多出来的只有 HL 和 WD 数据，这部分差距就是"会说话"带来的。

5. 高层推理的几种做法（Sec V-E，Fig 13）

排名：全模型 > 人类当高层（oracle）≈ 隐式 HL（不做高层推理，但训练里有子任务数据）> 去掉 VI > 去掉 WD > 去掉 HL > GPT-4 零样本当高层。两个重要信息：训练里放进子任务数据本身就拿到大半收益；11% 的口头指令数据对高层决策至关重要。

深层理解：这篇真正改变了什么

  • 把"泛化"从模型问题变成数据配方问题。网络结构几乎没动，所有收益来自数据怎么混、分几个阶段训。后来的 π 系列工作基本都沿着"配方"而不是"结构"在改。
  • 动作 token 和文字 token 同一个出口，是分层能力的来源。子任务预测、VQA、目标框、FAST 动作在预训练里是同一类任务，所以网页知识能直接流到"下一步做什么"的决策里；而低层动作被刻意隔开（只看 ℓ̂，不看 ℓ），不用背负语义理解。
  • "训练时离散、推理时连续"成为默认做法。FAST 负责训得快、保住语言能力，flow 动作专家负责推得快、动作细。后训练阶段才引入随机初始化的动作专家，使其梯度不会在预训练阶段破坏 VLM——知识隔离一文随后把这个现象说清楚并给出单阶段方案。
  • 语言成为一种新的示范形式。口头指令 VI 不是遥操作，而是人用语言"开"机器人；它采的是决策层的数据，便宜且高效，占比 11% 却不可或缺。
  • 评测范式的改变。全部实验都在训练集之外的环境进行，并用"完成度"而不是二值成功率衡量长任务。

代价与边界

  • 仍然会出错（Sec VI）：陌生样式的抽屉把手、物理上难开的柜门；手臂遮挡要擦的污渍这类部分可观测问题；高层推理有时"走神"，比如放东西时反复开关抽屉。
  • 提示词很简单。能理解多复杂的指令取决于标注数据的复杂度；更细的偏好和约束要靠更丰富的标注（人工或合成）。
  • 上下文很短，没有记忆。跨房间导航、记住东西放在哪，这类任务需要更长的上下文或显式记忆。
  • 两阶段训练贵且绕。预训练 280k 步 + 后训练 80k 步；动作专家在后训练才开始学。知识隔离一文给出了单阶段替代方案。
  • 开源只有一半。openpi 放出了 flow 低层策略的权重和代码（pi05_base / pi05_droid / pi05_libero），高层子任务推理、FAST 头和训练数据都没有公开。

被谁接手

  • 训练配方 → 知识隔离（2025.05）：把"为什么要先离散再连续"讲清楚，并改成单阶段：动作专家的梯度不回传到 VLM，FAST token 和 flow 同时训。
  • 从示范到经验 → π*0.6 / RECAP（2025.11）：在 π0.5 的基础上加价值函数和优势条件，让模型从自己的成败里学。
  • 更多输入形式 → π0.7（2026.04）：子任务文字之外，还能输入速度/质量元信息和视觉子目标来"指挥"同一个模型。
  • 实时性 → 实时动作分块（RTC）：解决动作块之间衔接的延迟问题，π0.5 的 50 步动作块是它的直接对象。
  • 复现与扩展 → OpenVLA vs π 系列里可以看到，离散 token 与连续生成两条路线在 π0.5 之后开始互相借鉴。

自测

π0.5 和 π0 的网络结构差在哪？

几乎一样（SigLIP + Gemma 2B + 300M 动作专家）。代码里只有两处不同：本体状态离散成数字写进提示词；时间步 τ 单独过 MLP 后用 adaRMSNorm 注入动作专家每一层。

低层动作分布依赖总指令 ℓ 吗？

不依赖。π(a | o, ℓ̂) 只看观测和模型自己预测的子任务 ℓ̂；总指令只影响高层 π(ℓ̂ | o, ℓ)。

预训练和后训练的 α 分别是多少，意味着什么？

预训练 α=0：没有动作专家，动作全部用 FAST token 当文字训。后训练 α=10：加入随机初始化的动作专家，flow matching 损失和交叉熵一起优化。

推理时为什么不用 FAST token？

自回归解码几十个 token 要过 2B 主干几十次，约 750ms 一块；flow 动作专家 10 步约 100ms。所以训练用 FAST 拿效率，推理用 flow 拿速度。

去掉网页数据 WD 影响什么？

mock 家的整体完成度差异不显著，但分布外物体的语言跟随明显变差，高层子任务推理也显著变差——网页知识主要用在"认识新东西"和"决定下一步"。

"隐式 HL"是什么，结果说明了什么？

训练里保留子任务数据，但推理时不做高层推理、直接把总指令喂给低层。它是第二名，说明把子任务数据放进训练本身就拿到了大半收益。

openpi 里的 π0.5 实现了论文的哪一部分？

只有 flow matching 低层策略（给定提示词出动作），由 Pi0 类加 pi05=True 实现；没有子任务文字解码、FAST 离散头和两阶段预训练代码。
