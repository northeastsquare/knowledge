FAST / π0-FAST：把动作像 JPEG 一样压缩成 token

离散动作 token 在高频控制下学不动，问题不在“离散”本身，而在每个 token 携带的信息太少。FAST 用 DCT + BPE 把一段动作压成约 30 个高信息量 token，让自回归 VLA 第一次能学会 50Hz 的叠衣服。

一句话：FAST 是一个动作 tokenizer（不是模型）；π0-FAST 是“π0 的 VLM 主干 + FAST token + 自回归解码”训出来的模型。它不是 flow matching，也不是 OpenVLA 那种逐维分箱。

问题：为什么分箱 token 在高频下“学不动”

分箱的做法是：对动作块 a1:H（H 步 × D 维）的每一步、每一维独立离散成 256 个 bin 之一，得到 H×D 个 token：[T1,1…T1,D, …, TH,1…TH,D]。

  1. 玩具实验：让小 Transformer 根据 4 个点预测一条三次样条。曲线本身不变，只改采样率（每条 25 → 800 个点）。分箱 token 在低采样率下预测很准；采样率越高误差越大，最后模型干脆一直复制第一个动作。
  2. 原因在训练目标：自回归模型学的是“给定前面所有 token，下一个是什么”，学习信号正比于 Ti 相对 T1:i-1 的边际信息量。信号越平滑、步长越短，相邻两步的差就越小，下一个 token 几乎等于上一个，边际信息趋近于 0。“抄上一个”这个捷径就能拿到很低的 loss。
  3. 现实印证：OpenVLA 在低频的 BridgeV2、RT-1 数据上效果不错，但很难拟合 15Hz 的 DROID；在 20Hz 收桌、50Hz 叠 T 恤任务上，分箱 token 训练的策略完全没有进展。

所以要的不是“换成连续表示”，而是先把冗余挤掉，让每个 token 都有信息。这就是一个压缩问题。

FAST 算法五步（Frequency-space Action Sequence Tokenization）

① 归一化每个动作维度的训练集第 1 / 99 分位数映射到 [−1, 1]。用分位数是为了抗离群值，也方便不同机器人共用一个 tokenizer。
② 逐维 DCT对 H×D 动作块的每一维沿时间轴做离散余弦变换。低频系数描述整体走势，高频系数描述突变。平滑的轨迹只需要少数几个系数。
③ 缩放取整round(γ·C)，γ 默认为 10。这是唯一有损的一步：小系数会变成 0，矩阵变得稀疏。γ 控制压缩率和精度之间的权衡。
④ 低频优先展平按“先所有维度的第 0 频，再所有维度的第 1 频……”展平（column-first）。这样自回归时先确定整体形状，再补细节，rollout 更稳。
⑤ BPE 合并在整数序列上训练词表为 1024 的 BPE，无损地压掉成串的 0，并合并跨维度常一起出现的系数组合。输出是固定大小的词表，可以直接塞进 VLM 词表。

解码是完全逆过程：BPE 解码 → reshape 成 H×D → 除以 γ → 逆 DCT → 反归一化，得到连续动作块。整个 tokenizer 只有两个超参（γ 与词表大小），论文发现都不敏感。唯一需要学习的是 BPE 词表，几分钟就能训完。

为什么这样设计换成别的会怎样
用 DCT：解析变换，像 JPEG 一样简单快，不需要训练网络VQ / FSQ 等学习式压缩也能提升训练，但要单独训练网络、仔细调参；论文的 FSQ 基线在灵巧任务上不如 FAST
保留 BPE去掉 BPE 后仍好于分箱，但大量 0 token 会稀释学习信号，还要多解码几百个 token，效果变差、推理变慢
低频优先展平按维度展平（先把一维的所有频率写完）会让早期 token 只定义了一条手臂的一维，rollout 不稳

FAST+：通用动作 tokenizer

  • 训练数据：约 100 万条 1 秒动作块，覆盖单臂、双臂、移动操作，关节空间和末端空间，以及多种控制频率。
  • 泛化：在训练时没见过的机器人数据集上（灵巧手、人形、甚至 Waymo 驾驶），token 数都至少减半，有些数据集减少得更多。训练策略时，效果与专门为该数据集训练的 FAST tokenizer 持平。
  • 用法：HuggingFace 上三行代码 AutoProcessor.from_pretrained("physical-intelligence/fast", trust_remote_code=True)；也可以用 .fit(action_dataset) 在自己的数据上重新训练 BPE。建议输入先做分位数归一化，每次切 1 秒动作块。

π0-FAST：模型怎么搭、怎么训、怎么推

  1. 结构：π0 的 PaliGemma（Gemma 2B + SigLIP）主干，去掉动作专家。动作也变成词表里的 token，与文字共用同一个输出头。
  2. 输入序列：[图像 token] Task: 指令, State: 256-bin 离散状态;\n 作为前缀，Action: [FAST token…] | 作为后缀。前缀内部双向注意力，后缀因果注意力。
  3. 词表映射：FAST 的 1024 个 token 映射到 PaliGemma 词表末尾，并跳过最后 128 个特殊 token：pg_id = vocab_size − 1 − 128 − fast_id。
  4. 训练：标准的下一个 token 交叉熵，只在后缀（动作部分）上计 loss。没有噪声、没有积分步数，和训练语言模型完全一样。
  5. 推理：前缀先过一遍填 KV cache，然后逐 token 贪心解码（默认温度 0），遇到 EOS 停止 → 截取 “Action:” 与 “|” 之间的部分 → FAST 解码 → 连续动作块。
  6. 规模：在 π0 的同一套跨本体数据（9.03 亿时间步自有数据，外加 9.1% 的 BridgeV2 / DROID / OXE）上训练，对标扩散/flow 版 π0。
相机图像 + 指令 + 状态→PaliGemma 2B
前缀双向注意力→逐 token 生成
约 30–60 个 FAST token→BPE 解码 → ÷γ → 逆 DCT→连续动作块
交给机器人执行

两种方法的重建误差相当。注意 FAST 列：无论频率多高，每条手臂大约都是 30 个 token。token 数跟着动作本身的复杂度走，而不是跟着采样频率走。

  • 策略效果：在收桌（20Hz）、叠 T 恤（50Hz）上，分箱完全学不会，FAST 能学会；FAST 与 FSQ 相当或更好，灵巧任务上优势更明显。
  • DROID 零样本：第一个只用自然语言提示、不做微调，就能在伯克利、斯坦福、华盛顿大学三个校园的新环境里完成简单桌面任务的 DROID 策略。
  • 与骨干无关：把 OpenVLA 的分箱换成 FAST+ 后，它在叠 T 恤任务上从学不会变成能学会。
  • 对比扩散/flow 版 π0（单任务）：小数据集（Libero、叠 T 恤，少于 50 小时）两者相当；大数据集（收桌）FAST 达到同样效果所需训练步数约为 1/3；DROID 上 FAST 更听语言指令，flow 版常忽略指令。
  • 通才模型：π0-FAST 在 π0 的全部数据上训练，5 个任务（含最难的叠衣服）与 π0 持平，训练 GPU 小时少 5 倍。

深层理解：这篇真正改变了什么

  • “离散还是连续”被问错了：分箱失败不是因为离散，而是因为 token 的信息密度太低。只要每个 token 都有足够的边际信息，离散自回归就能学好高频灵巧动作。论文原话的意思是：任何足够有效的压缩方法都能加快 VLA 训练。
  • tokenizer 是模型的一部分：LLM 里 BPE 的选择影响很大，机器人也一样。动作表示决定了训练信号长什么样，比“换更大的骨干”更便宜、更有效。
  • 先轮廓、后细节：低频优先展平让自回归的生成顺序变成“先定整体趋势，再补细节”，与扩散模型从粗到细的去噪相似，只是换成了在频域里按 token 生成。
  • 训练快的来源：交叉熵 + 共享输出头，梯度直接落在 VLM 熟悉的“下一个 token”任务上，不需要随机初始化的动作专家从零学起，也不用学一个速度场。
  • 语言跟随更强：动作和文字共用同一个输出空间，VLM 的语言能力保留得更好。这个观察直接引出了后来的知识隔离（KI）。

代价与边界

  • 推理慢：在 RTX 4090 上，flow 版 π0 生成 1 秒动作块约 100ms，π0-FAST 约 750ms。原因有两个：要逐个解码 30–60 个 token（flow 版只要 10 步积分），而且每一步都要跑完整的 2B 主干（flow 版只跑 300M 动作专家）。论文的静态任务没受影响，但动态任务和实时控制会受影响。
  • 有损且长度可变：γ 决定精度上限。输出 token 数不固定，一旦解码出非法序列，openpi 会返回全 0 动作，部署时需要专门处理。
  • 验证范围：论文只在静态机械臂上做了策略实验；移动、人形和驾驶数据只测了压缩率。
  • 可能的加速：作者提到可以借鉴 LLM 的推测解码、量化、定制算子，但论文没做。

被谁接手

  • π0.5：取两条路线之长。训练时用 FAST token 训 VLM 主干（训练快、语言好），推理时由 flow 动作专家出动作（推理快），两种动作表示之间用注意力 mask 隔开。
  • 知识隔离（KI）：FAST token 训练骨干，同时阻断动作专家回传到骨干的梯度，避免破坏 VLM 知识。见 Physical Intelligence 工作全景。
  • π0.6 / π0.7：沿用 π0.5 的“FAST 训骨干 + 动作专家出动作”底座。见 π*0.6、π0.7。
  • 另一条路：OpenVLA-OFT 放弃逐 token 生成，改为并行解码加连续回归来提速。对比见 OpenVLA vs π 系列。
  • 放回全局：VLA 发展史中的“动作表示”主线，2025.01 节点。

自测

π0-FAST 是 flow matching 吗？和 π0 的根本区别是什么？

不是。π0-FAST 没有动作专家，由 VLM 主干像生成文字一样逐个生成 FAST token，用交叉熵训练；π0 由动作专家用 flow matching 从噪声积分出连续动作，用速度场回归训练。两者最后都输出连续动作块。

同一条平滑曲线采样更密，为什么分箱 token 更难学？

相邻 token 越来越像，每个 token 相对前文的边际信息趋于 0，模型靠“抄上一个”就能把 loss 压得很低，学习信号被稀释。

FAST 中哪一步有损？哪一步需要训练？

缩放取整有损（由 γ 控制）；只有 BPE 词表需要在数据上训练，DCT 是固定的解析变换。

为什么要按“低频优先”展平？

自回归先生成所有维度的低频系数，相当于先确定整段动作的整体形状，再补高频细节，rollout 更稳定。

FAST 让训练快 5 倍，为什么 π0.5 推理时又换回 flow？

FAST 推理要用 2B 主干逐 token 解码（约 750ms/块），flow 动作专家 10 步积分约 100ms。π0.5 用 FAST 训练拿收敛速度和语言能力，用 flow 推理拿速度。
